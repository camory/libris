## Goal
The form's authors become what it sends: *Ajouter un auteur* adds an
empty box, focused, on the role texte or scénario, and the add sends every
box as the reader left it. Every field of the app shows which one has the
focus with the `accent` outline.

## Risks and decisions
**The boxes travel in the draft.** `EditionDraft` gains `authors:
Author[]`, the boxes as the form holds them, and `editionOf` reads them,
so the rule "each name once per role, in the boxes' order" is the
domain's, and T148's trimming and T151's refusals land beside the other
fields' in `editionOf` and `refusalsOf`. Rejected: the `authors`
parameter kept as `SourceAuthor[]` (the form would flatten the boxes
itself); a second domain function the form calls (two doors for one
draft).

**`AuthorBox` exposes `focusName()`.** The form decides which box takes
the focus (a new one here, a refused one in T151 and T152); the box owns
the input. D10 lets a type gain a method decided in the brief, and
`defineExpose` is how a Vue component gains one; it adds no data flow, so
props in and events out still hold. Rejected: the form querying the
child's input through the DOM (it reaches into the box's markup); a prop
that asks for the focus (a second request with the same value changes
nothing, and T151 needs both lines).

**The new box starts on `WRITER`.** Every kind's first role is `WRITER`,
worded texte or scénario by the catalogue; a change of kind rewords it
as it rewords every box.

**A box is not keyed by its name.** Once the form holds the typed names,
a key on the name remounts the box at each keystroke and drops the focus
(step 6); two empty boxes would also share one key. The key is the
implementer's, so long as it stays with its box.

**The focus outline is checked by hand.** jsdom computes no style and a
spec never asserts a class: step 9 has no case, as T144's layout had none,
and goes to Tophe in the PR body with the refused fields' `danger`.
