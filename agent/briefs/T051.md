## Goal
The backend implements contract `v0.8.1` with no cover yet fetched: the
lookup answers the house's id and no candidate, the add stops storing a
cover address, the catalogue answers no cover, and the cover operation
serves the pictures of the covers directory. It is the frame T052–T059 fill;
until T059 the backend is not deployed (Tophe, 2026-09-30).

## Rules in play
- D02 — the cover is the bibliography's: `bibliography.domain.cover` holds
  its values and port, `bibliography.application.cover` the use case, the
  file adapter an infrastructure package; the controller stays in
  `library.infrastructure.web`, the only web package
- D04 — the pin moves to `v0.8.1` and is the first red; no other contract edit
- D07 — the two cited scenario tests are un-skipped and changed in nothing
  else; `FastEntryScenarios` *S1 Typed ISBN, found* gains `id` and `covers`,
  declared in the PR body; no other scenario test is edited
- D09 — one environment variable, `LIBRIS_COVERS_DIR`, and the second named
  volume `covers` in `deploy/compose.yaml`; the amendment is proposed in the
  PR body
- D10 — `FindCover` is a use case with `operator fun invoke` only; the port
  `CoverStore` keeps a verb of its own, `read`; SQL untouched
- D11 — ids are strings; `id` and `coverUrl` serialised `null`, never
  omitted; the not-found is `404` `/problems/not-found` with a problem body,
  no `detail`
- D12 — `CoverName` and `Cover` are values with two doors: a constructor
  that `require`s, an `of(...)` that answers `null`; the adapter maps
  through `of` and catches no constructor's exception

## Test plan
One step is one case is one commit; `./gradlew detekt` before each commit;
a step is committed before its guard's mutation is checked. `./gradlew test
--tests '*ApiContractTest'` lists the contract cases one by one.

1. **red — the pin.** `ApiContractTest` loads `…/v0.8.1/openapi.yaml`. The
   commit body lists the red cases; expected: the lookup's (no `id`, no
   `covers`), the add's keyed `201` (the stub's `NewBook` no longer matches),
   the cover operation's two. Any other red: stop and report `blocked` with
   the case.
2. **red then green — the lookup's id and covers.** `IsbnControllerTest`
   *an edition the house holds is answered with its fields*: the held
   edition gets a fixed `EditionId`, the whole map gains `"id"` (that id as
   a string) and `"covers"` (empty list). `IsbnResponse` gains `id` (`Held`:
   its id; `Found`: `null`) and `covers`. `FastEntryScenarios` *S1* gains
   `"id": null` and `"covers": []`, STRICT kept; nothing else in it moves.
   The lookup's contract cases go green.
3. **green — S10.** Remove `@Disabled("covers")` from *S10 A held edition
   offers its own cover, not yet stored*; a red is the run's code at fault.
4. **red then green — the add stores no cover address.**
   `AddBookToBookshelfTest`: the edition inserted for an ISBN the house
   lacks has `coverUrl = null`. `NewBook` and `NewBookRequest` lose
   `coverUrl`; `AddBookToBookshelf` builds the `Edition` with `coverUrl =
   null`. `NewBookTest`, `NewBookRequestTest` and the `NEW_ONE_PIECE_1` of
   `ApiContractTest` drop the argument; the keyed `201` goes green.
   `BookshelfScenarios` and `CatalogueScenarios`, which still post a
   `coverUrl`, stay green untouched.
5. **red then green — the catalogue answers no cover.**
   `CatalogueControllerTest` (new web slice, same form as
   `IsbnControllerTest`): `BrowseCatalogue` answers one held edition whose
   `coverUrl` is set; the book's `coverUrl` is `null`. `BookResponse` gets
   `coverUrl = null`.
6. **red then green — a cover's name.** `CoverNameTest`: `CoverName.of` of
   64 lower-case hexadecimal digits answers the name.
7. **guard — what is not a name.** `CoverName.of` answers `null` to 63
   digits, 65, one upper-case `A`, and `../` followed by 61 digits.
   Mutation: drop the length from the pattern.
8. **red then green — a JPEG.** `CoverTest`: `Cover.of` of the bytes of
   `recordedBytes("covers/tall.jpg")` answers `CoverFormat.JPEG` and those
   bytes. JPEG: the bytes start `FF D8 FF`.
9. **red then green — a WebP.** Same with `covers/small.webp`:
   `CoverFormat.WEBP`. WebP: `RIFF` at offset 0 and `WEBP` at offset 8.
10. **red then green — not a picture.** `Cover.of` answers `null` to the
    bytes of a text and to the four bytes `RIFF`.
11. **red then green — the stored file.** `FileCoverStoreTest`, over a JUnit

    extension) are read by `read(CoverName(name))` as a JPEG cover with
    those bytes. Creates the port `CoverStore` and `FileCoverStore`.
12. **red then green — no such file.** `read` of a name with no file
    answers `null`.
13. **red then green — the directory setting.** `LibrisApplicationTest` is
    given `LIBRIS_COVERS_DIR` through its `@SpringBootTest` properties and
    sees `CoversProperties(dir = <that path>)`; `application.yaml` binds
    `libris.covers.dir: ${LIBRIS_COVERS_DIR}`, no default. `FileCoverStore`
    is built from it.
14. **red then green — a stored JPEG is served.** `CoverControllerTest`
    (web slice): `findCover` answers a JPEG cover; the answer is `200`,

15. **red then green — a stored WebP is served** as `image/webp`.
16. **red then green — a malformed name.** `GET /api/v1/covers/ABC` is

17. **green — S5's not-found.** Remove `@Disabled("covers")` from *S5 Libris

19. **Tidy on green**, the gate run plainly, then the documents: the task

**GOTCHAS.md gains:** Jackson 3 leaves `FAIL_ON_UNKNOWN_PROPERTIES` off, so a

## Risks and decisions
**The stored cover address stays.** `Edition.coverUrl` and `cover_url`
remain: the lookup of a held edition answers its stored address "as today",
and T057 reads the editions from before the deploy. New editions are stored
with `null`. *Rejected:* dropping the column now, a loss of data no task
line asks for.

**No `coverSource` yet.** The add accepts the field because Jackson 3 drops
undeclared fields (checked: `DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES`
defaults to off in jackson-databind 3.1.5); no test of this task reads it.
*Rejected:* declaring it unread, a property no test exercises.

**A cover is the file `{name}`.** T053 stores "under a name made from its
bytes" and this task "serves by name a picture of the covers directory": the
file is named by the name, no extension, and its format is read from its
bytes, the only two formats the spec stores. Bytes of neither format are no
cover, hence `404`. *Rejected:* an extension per format, a second name for
one picture.

**The file adapter sits in `bibliography.infrastructure.persistence`.**
Covers are stored data of the bibliography; D02 describes that package as
the `JdbcClient` adapters, so the PR body proposes adding "and the covers'
files". *Rejected:* a new `infrastructure.cover` package, a layout D02 does
not name.

**`CoverName` is checked by the domain alone.** Its rule is the contract's
pattern, so `CoverName.of` is the edge's check, unlike the ISBN whose
contract writing is narrower than `Isbn.of`. It also keeps any path out of
`dir.resolve`. A malformed name is `404`: the contract describes no `400`
on this operation.

**`LIBRIS_COVERS_DIR` has no default.** A backend without it fails at start
rather than store pictures in its container. `LibrisApplicationTest` is
given one; `.env.example` gains one for `bootRun`, so the
*Local development* comment of `docs/ARCHITECTURE.md` ("the three database
variables") is proposed for change in the PR body. *Rejected:* a relative
default.

**The `404` whatever `Accept` says.** Contracteer's keyed `404_NO_COVER`
may send `Accept: image/*`; Spring answers a `ProblemDetail` as
`application/problem+json` anyway. If that case answers `406`, stop and
report `blocked` with the request it sent.

**`FindCover` is the bibliography's**, called by the library's web package
as `IsbnController` reads the bibliography's lookup types.
