## Goal
Each author's box gets its trash, which takes the box out of the form at
once and hands the focus to *Ajouter un auteur*, so the add sends only the
authors left. While the add runs, the names, the trashes and *Ajouter un
auteur* accept nothing, as the form's other fields already do.

## Risks and decisions
**The box asks, the form removes.** `AuthorBox` draws its trash, a line
part of the box in the *Screen*, and emits `remove` with no payload; the
form, which holds the list, takes that box out by its key and focuses its
own *Ajouter un auteur*, reached through a template ref. Rejected: the
form drawing the trash beside the box (the trash sits inside the box's
first line); the box emitting its name (two boxes may share one).

**"Empty" is the empty string.** The trash reads *Retirer l'auteur* while
the name is `""`, as the *Screen* says; a name of spaces alone reads
*Retirer* and those spaces. S9 names "empty or spaces alone" apart, so
the spec's "empty" is taken as written. Rejected: a blank test (a rule
the spec does not state).

**`disabled` is optional on `AuthorBox`.** As on `CoverChoice`, absent
reads enabled, so `AuthorBox.spec.ts`' helpers keep their shape. It
covers the name and the trash only; T147 extends it to the roles' line
with the list.

**No component case for the body sent.** The removal takes the box out of
the list the draft already reads (T145); a case on the emitted edition
would be green on step 5's code with no mutation short of a second list.
S3 proves the body, and its guard's mutation proves it tells the boxes
apart.

**The cross gets a case of its own.** The view already rebuilds the form
on each pencil, so step 8 is a guard; edition-form S13 covers a typed
title, and the backlog line names the authors brought back, so the view's
spec states it for the boxes.
