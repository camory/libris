## Risks and decisions
**Fit.** One run: one pin, one route on an existing controller, a use
case answering a constant, its result, a request type, four test files
touched, T130's shape. Rejected: a split, since the bump reds the save's
cases and only the controller greens them.

**`SaveEdition` in `library.application.catalogue`.** Its `200` is a
`Book`, the edition with the reader's copies, which the tree answers as
`HeldEdition` from this package (`FindCatalogueEdition`), and a
bibliography use case cannot name it (D02, rule 4). The call reads
`saveEdition(reader.id, EditionId(id))`. How T154 writes the edition
(through `EditionRepository` or a bibliography use case called inside, as
`AddBookToBookshelf` calls `HoldEdition`) is T154's brief's.
Rejected: `EditEdition` (the spec's act is the save, *Enregistrer*).
Rejected: a use case in `bibliography.application.edition` (cannot answer the copies).

**`SaveEditionResult` with `Saved(held)` now.** The controller answers
`200` on it and the keyed `200` stub needs it, though `SaveEdition`
answers `NoSuchEdition` until T154; the variant's name `NoSuchEdition`
matches the read's. Rejected: a nullable answer (the tree answers
outcomes by sealed results, D11).

**`invoke(readerId, editionId)`, the edited fields added by T154.** The
contract stubs vary on the id alone, and the reader is what the answer's
copies are read for; the fields have no application type before T154
decides what the save writes. Rejected: an application type of the fields
now (its validation and its shape would be T154's code written without
its test).

**`EditionDetailsRequest`, bound but not read.** The body must be read
into a typed request for `auto: body type mismatch` to fail in
`ProblemAdvice` with the `400` the case expects; without a body
parameter the controller answers `404`. The type declares the contract's
`EditionDetails` whole, so T154 adds `validate` without reshaping it, and
reuses `NewAuthorRequest` and `NewSeriesRequest`, the request forms of
the contract's `Author` and `SeriesEntry`, imported from `web.bookshelf`
as `CatalogueController` already imports `web.isbn`'s responses. Its
name follows the schema's, as `NewBookRequest` follows `NewBook`.
Rejected: a class with one field (a shape T154 rewrites).
Rejected: copies of the author and series requests in `web.catalogue`.

**Two `@Suppress("UnusedParameter")`.** detekt reports the use case's two
parameters and the controller's request, unread until T154; T130
suppressed `RemoveCopy.invoke` the same way until T131. T154 removes
both.

**Exact stubs for both keys.** Both responses of the save are keyed, so
the verifier sends no generated `200` with a random id; each stub
matches the id its key fixes, no matcher needed. An unstubbed id answers
`null` and shows as `403`.
