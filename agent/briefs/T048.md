# T048 — Libris unavailable on the first page

**Backlog line:** Frontend: Libris unavailable on the first page — when the
first page does not come, in place of the list *Erreur lors du chargement,
veuillez réessayer plus tard.* with the alert icon, and nothing listed.
Realises the first-page case of S4 on the frontend and un-skips its test
(full text in `agent/TASKS.md`).

**Serves:** spec `catalogue` S4 (the first page) and the *Screen* state
*Unavailable* (first page only); PRD §4.1; D05, D07, D10, D11; U01, U02,
U03, U05, U07, U08.

**First of its kind:** none. The message of U05 is already drawn by
`IsbnView` (`isbn.error`, `isbn.addError`) and a composable already turns a
failed port into a state (`useAddBookToBookshelf`'s `notAdded`).

## Goal
When this task is done, `/catalogue` says to try again later, with the alert
icon, when the first page does not come, and lists nothing; the rejection
that escaped `void browse()` since T046 is caught. The test *S4 Libris
unavailable* passes on the frontend; the next-page case stays T049's.

1. **Red: S4 on the first page.** Remove the `.skip` of *S4 Libris

6. Run the greps of the criteria and then the gate; read its output for

## Risks and decisions
**The state is `unavailable`, with nothing in it.** The spec names the
screen state *Unavailable*; the view needs no more than the status, and
T049 decides what the next-page failure keeps (the rows) when it reads it.
- Rejected: `notAdded`-style naming (`notListed`), a word the spec does not use.
- Rejected: carrying the error in the state, which no case reads and D11
  keeps off the screen.

**Every rejection of the port is the same failure.** `FetchCatalogueApi`
throws on any status but 200 and `fetch` rejects with a `TypeError` when
nothing answers; for the reader both are "try again later" (D11: the wording
is the frontend's; the only `400` is an `after` the app never sends on the
first page). `browse` catches whatever the port rejects with, as
`useAddBookToBookshelf` does; step 3 keeps it so.
- Rejected: telling a `400` apart, which the first page cannot receive.

**The key is `catalogue.error`**, beside `catalogue.empty`, as `isbn.error`
holds the lookup's sentence of the same shape.
- Rejected: reusing `isbn.error`, whose words (*la recherche*) are another
  screen's.

**The message is drawn in the view**, the same block as `IsbnView`'s, not a
new component: two copies of four lines do not yet make a component, and
this task changes no other screen.
- Rejected: a shared `AlertMessage` component, a convention no document
  states and a refactor of `IsbnView` outside this task.
