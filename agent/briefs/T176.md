## Goal
The catalogue's address names the search shown, so leaving for an
ouvrage and coming back, or reopening the app on that address, shows the
same words in the box and their answer. Typing never fills the history:
going back leaves the catalogue, whatever was typed.

## Risks and decisions
**The router hands the query, the view writes it.** `router.ts` computes
`query` from `?q=` as it hands `id` through `props: true`, so the view
reads no route object and its spec sets a prop; the view writes the
address from its `@search` handler. Rejected: `useRoute()` in the view
(a second way for a view to read the address); the query in
`useSearchCatalogue` (application never imports the router).

**The address is written when the search is asked.** The `@search`
handler replaces the address as it calls `search`, so a search left
coming, then an ouvrage opened, brings back the words the box held.
Rejected: writing on the answer (`found` holds no query, and every
`toEqual` of the composable's spec would change); the address driving
the search through the prop (the search key on unchanged words would ask
nothing, where T174 counts it as a later search, and every search would
wait for a navigation).

**The view follows the prop while shown.** The tab or *Ouvrages* tapped
over a search, or a back to a query, changes the prop without a remount;
the view takes the new query, `""` included, unless it is the query it
last asked, which its own `replace` brings back. Rejected: reading the
address at setup alone (the address would name no search over the
search's rows); comparing with the box's text, which runs ahead during
the pause (step 13).

**Loading rows on arrival only.** The spec draws them under a box opened
on a query; a search typed, or a query the prop takes later, keeps the
rows shown until its answer (S6). An answer that comes before the
catalogue's first page is listed at once (step 9), which answers the
`agent/PROPOSED.md` item from T169, since on arrival both requests leave
together. Rejected: a state of the composable for it (it cannot tell an
arrival from a search typed, and a third verb for it).

**No `router.spec.ts`.** The prop's computation is proven by *S7 The
search survives a visit*, which reaches the view through the router; the
view's spec sets the prop. Rejected: a spec of the router alone, which
the tree has none of.
