## Goal
An owner whose bookshelf already holds every reader reads so in place of
the plus, and an add Libris does not answer, or refuses, leaves the block
open with S9's sentence in the chosen reader's row. This is the last piece
of the bookshelf's screen before the star (T084).

## Risks and decisions
**The owner rule is a domain function, `isOwnedBy`**, beside
`membersInOrder`, used by the view for the sentence and by
`useFindBookshelf` for asking the readers, so the rule is written once.
- Rejected: the view reading the reader's role inline — a rule in a view,
  twice in the code.
- Rejected: the state's `readers` turning `null` for a viewer — changes a
  shape three specs read for a fact the members already hold.

**`ReaderChoice` takes `failed`, a boolean, optional like
`NewBookshelfRow`'s `failure`**: one failure only, so no union. The view
binds it to `addState.status === 'unavailable'`, so the message leaves
while the next add runs and closing the block forgets it.

**A tap on another reader moves the form without the message**: the
sentence answers the add of the reader it sits under (U05: the answer
stays under the control that asked); under another name it would say an
add failed that was never sent.
- Rejected: the message following the form — it names the wrong reader.

**The sentence for every reader a member is `body`, `muted`, 8 under the
members' card**, as mockup 21 draws it; it is not U05's empty state (no
icon, nothing centred). No test sees its classes.

**The readers' failure needs no production change**: `useFindBookshelf`
already asks the readers inside its `try`; step 3 is its guard.
