# T078 — A reader chooses their default

**Backlog line:**

>       A reader makes a bookshelf they own their default: the answer is

## Goal
`ChooseDefaultBookshelf`, a constant answering `NoSuchBookshelf` since
T072, becomes real: a reader makes a bookshelf they own their default, the
reader stored with it, and `GET /api/v1/me` names it from then on; any other
bookshelf is refused, the default unchanged. This is the last backend task
of the phase: once deployed, the frontend moves to `v0.11.0` (T079).

## Rules in play
- D07 — the three `@Disabled("bookshelves")` of S7 and S8 in
  `BookshelvesScenarios` are removed, the class's last, so the import of
  `Disabled` goes too; nothing else in the class changes. The web layer
  does not change: `ApiContractTest` already stubs `Chosen` and
  `NoSuchBookshelf` and stays as it is, green, its `tests=` count that of
  `main`; no test of a controller.
- D04 — the pin stays at `v0.11.0`; no contract edit.
- D12 — the default being one the reader owns spans `Reader` and
  `Bookshelf`, so the rule is the use case's: it asks the bookshelf
  `isOwnedBy(reader.id)`, maps a refusal to `NoSuchBookshelf`, and writes
  the reader in one `TransactionOperations` block; its test proves the
  boundary with `TransactionsObserving`, before and after.
- D11 — `ReaderRepository.update` is one SQL statement writing the whole
  aggregate, every column but the id, as `insert` does; a refusal is an
  outcome of `ChooseDefaultResult`, never an exception, the viewer, the
  stranger and an id naming no bookshelf alike. No migration:
  `reader.default_bookshelf_id` exists since `V002`.
- D02 — `ChooseDefaultBookshelf` depends on `domain` ports and
  `TransactionOperations` only; a refusal writes nothing and opens no
  transaction.
- D10 — `invoke(reader: Reader, bookshelfId: BookshelfId)` keeps its
  signature and stays the only public member; the ports are held as
  `readers` and `bookshelves`; the `@Suppress("UnusedParameter")` goes;
  SQL keywords upper case; the arrows of a `when` aligned, as in
  `AddMemberToBookshelf`; files read top-down; the layout of `backend.md`
  kept by hand.

## Risks and decisions
**Fit.** One run: one use case made real, one port method with its adapter
and two fakes, three un-skips, three test files; no web, contract or
schema change. Rejected: a split (S7 and S8 share one use case and one
test class).

**The rule is the use case's, refused through `isOwnedBy`.** Neither
`Reader` nor `Bookshelf` can tell alone whether the default is one the
reader owns, so D12 gives it to the use case; the bookshelf answers the
question it holds, `isOwnedBy`, as in `AddMemberToBookshelf`. A viewer, a
stranger and an unknown id are one outcome: the contract answers all three
`404`. Rejected: a `NotAnOwner` variant (a second branch at the edge with
the same answer); `hasMember` (a viewer would get through).

**The reader changes through `copy`.** The reader has no rule on its
default it could refuse, so it gains no method: the use case writes
`reader.copy(defaultBookshelfId = …)`. Rejected: `Reader.withDefaultBookshelf`
(a method with no rule whose only test restates `copy`; Tophe may ask for
it at review, a local, reversible change).

**The principal is the reader written.** `invoke` takes the `Reader` that
`WelcomeReader` read at the start of the same request, so it is current;
the use case does not read it again. Rejected: re-reading by id (a second
read of what the request holds, and a signature change that moves
`ApiContractTest`'s stubs).

**The transaction holds the update; the check comes before it.** As in
`AddMemberToBookshelf` and `CreateBookshelf`, a refusal is decided from the
read and opens no transaction, so `TransactionsObserving` records none, and
the one block of a choice holds the reader's update. No membership is ever
removed in v1, so nothing can make the bookshelf stop being the reader's
between the read and the write; and `reader.default_bookshelf_id`'s
reference, checked at commit, keeps the schema's part of the rule (D12).
Rejected: reading the bookshelf inside the block (a refusal would then open
a transaction, unlike every sibling, and under PostgreSQL's read committed
the read locks nothing).

**`update` writes every column.** D11's `update` writes the aggregate, as
`JdbcBookshelfRepository.update` writes the name with the members; step 2
changes every field but the id so that a statement writing the default
alone goes red. Rejected: an `UPDATE` of `default_bookshelf_id` alone (a
port named for the aggregate that writes part of it).

**detekt.** `ReturnCount` allows two returns: the outcomes stay in one
`when`, as in `AddMemberToBookshelf`.
