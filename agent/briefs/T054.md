# T054 — Open Library as the chosen source

**Backlog line:**
> - [ ] T054 Backend: Open Library as the chosen source.
>       The worker of T066 fetches the picture of an edition whose chosen
>       source is Open Library from its covers by ISBN, and stores it as T066
>       does, as fetched; the cover operation serves it as JPEG with its
>       year-long `Cache-Control`. Only the chosen source is asked.
>       Realises S5 on a stored cover; un-skips the backend test *S5 Libris
>       serves a stored cover*.

**Serves:** spec `covers` S4 ("it asks that source alone for the picture of
the edition's ISBN", for Open Library), S5 (a stored cover served in the
format it was stored in, kept for a year); PRD §3, §4.7; decisions D02, D04,
D07, D08, D09, D10, D12
**First of its kind:** the first use case that chooses among the
implementations of one port by a value its aggregate holds
(`FetchAwaitedCovers` takes the `CoverFetch` whose `coverSource` is the
awaited cover's `chosenSource`); the first source with two addresses, its
lookup's and its pictures' (`libris.sources.open-library-covers-url`).

## Goal
An edition added with the Open Library cover gets that picture from Open
Library's covers by ISBN, stored as fetched, and the cover operation serves
it as JPEG; inventaire.io is never asked for it. This is the first chosen
source after inventaire.io. The BnF's fetch and the cascade (T057) use the
same port.

## Risks and decisions
**`CoverFetch.coverSource`, a property of the port.** The use case takes
every fetch Spring holds and runs the one whose source the awaited cover
chose, as `LookupEditionByIsbn` takes every `EditionLookup` and orders them
by their `source`; T057's cascade orders the same list by
`CoverSource.order`. Not `source`: `OpenLibrarySource` implements
`EditionLookup` too, whose `source` is an `EditionSource`, and one class
cannot override two `source` of different types; `coverSource` is the
contract's word for it (`NewBook.coverSource`). *Rejected:* a map of fetches
by source built in a configuration bean, a second list each new source must
join; one use case parameter per source, which the cascade cannot iterate.

**`OpenLibrarySource` implements `CoverFetch`.** Decided with Tophe on
2026-10-03 (`agent/PROPOSED.md`): an adapter is named after its source and
implements every port that source serves. Its fetch shares the client and
its bound with the lookup. The PR body proposes D02's sentence on
`bibliography.infrastructure.lookup`: the BnF and Open Library clients
"answer an edition, and Open Library's fetches its picture for the worker".
*Rejected:* a class `OpenLibraryCoverFetch` and a second bean.

**A covers address of its own; the candidate keeps the public one.** The
scenario harness sets `LIBRIS_OPEN_LIBRARY_COVERS_URL` to its stub, and
T052 deferred binding it to the first fetch. The candidate cannot read it:
*S5 Merged answer, from Open Library alone* asserts the public
`https://covers.openlibrary.org/b/isbn/…-L.jpg?default=false`, and a
scenario is never edited. So the candidate keeps its constant and the fetch
reads the setting, whose default is that same address. The setting is
`libris.sources.open-library-covers-url`, beside `open-library-url`; its
environment form (`LIBRIS_SOURCES_OPENLIBRARYCOVERSURL`) is not the
variable's, so the binder trap of the gotchas does not fire. *Rejected:*
the fetch on the constant, which the scenarios cannot stub.

**`?default=false` on the fetch,** as on the candidate: without it Open
Library answers a blank picture for an ISBN it has no cover for, which the
worker would store and name on the edition, ending the wait.
