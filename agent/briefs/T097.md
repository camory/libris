## Goal
`/catalogue/series` lists the reader's series by name, each row its cover
or the stand-in, its name and its count in albums or tomes. T098 adds the
failure and T099 the switch on this list.

## Risks and decisions
**The view sorts, the domain orders.** `seriesInOrder(series, locale)` in
`Series.ts`, called by `SeriesView` with `locale.value` over the `listed`
state, as `HomeView` calls `membershipsInOrder`. Rejected: sorting in the
composable (it knows no locale, and none of the tree's composables sorts).
Rejected: sorting in `FetchSeriesApi` (an adapter carrying a screen rule).

**The `null` kind has an entry of its own.** U06 gives each value of the
field choosing the word its full set of words; `kind` takes four values,
so `series.count` holds four entries and the row writes
`` t(`series.count.${series.kind}`, { count }, count) `` with no branch.
Rejected: `NONE` behind `kind ?? "NONE"` (a branch in the row, and a key
no API answers). Rejected: one *tomes* entry behind `kind === "BD"` (the
choice in the component, against U06).

**A row of its own, `SeriesRow`.** The series row shares the cover block
of `CatalogueRow` but none of its text; it copies the block's markup.
Rejected: a shared cover component (it changes `CatalogueRow`, which this
task leaves untouched; a follow-up for `agent/PROPOSED.md` if wanted).

**The words.** `series.cover`, *Couverture de {name}*, beside
`catalogue.cover`, which names an ouvrage by `{title}`; `series.count` as
the name of what `volumeCount` shows. Rejected: reusing `catalogue.cover`
(its placeholder is a title).

**The scenario's `words` is the row spec's guard.** Step 14 reads the
row's text nodes as the scenario does, so a stray overline, the series
line of `CatalogueRow`, fails a unit case, not only S1. It passes on arrival, so
it is a guard.

**No step for the rows' separation.** The scenario reads text nodes, so
the name and the count need no `{{ " " }}` between them for any test of
this task; none is asked.
