## Goal
A member taps a home row and sees the bookshelf's name and its sorted
*Membres*; a non-member, a malformed id or no answer read one sentence.
T083 (adding a member) and T084 (the star) build on this screen.

## Risks and decisions
**The route nests under the tab's.** `/` becomes a component-less parent of
`""` and `bibliotheques/:id`, and *Accueil* is current when its link is
active, not only exact-active, so every screen below the home page marks
it. Rejected: a `meta` naming the tab on each route (a second source for
what the path says). Rejected: the tab bar testing the path's prefix (the
router already knows).

**The id reaches the view as a prop.** `props: true`, so the view's spec
needs no router. Rejected: `useRoute()` in the view (a router in every case).

**A malformed id reads as no such bookshelf.** The spec's contract answers
`400` for an id that is not one and says the screen shows it as *Not
found*; the composable maps `/problems/validation` to `notFound`. Any other
problem reads as no answer, S9's rule for a refusal the screen never
provokes. Rejected: a third sentence for the malformed id (none written).

**The reader is sorted by display name**, the spec's order; *Vous* is only
how the row reads. Rejected: the reader first, or sorted as *Vous*.

**The rows wait for the reader**, read by `currentReader()` as `HomeView`
does, so no row reads *Léa* then turns *Vous*. Rejected: drawing the
members before the reader is known.

**Two skeleton rows and a title bar**, as mockup 12 draws. Rejected: three
rows like the home page.

**The link holds the name and role; the chevron sits beside it.** The row
becomes a `RouterLink` over its text, then the aria-hidden chevron, so
T084's star button sits between them and never inside a link. Rejected: the
whole row one link (a button inside a link later). Rejected: a click
handler on the row (no link role, no `href`).

**The catalogue's words for the screen go under `bookshelf`.** The loading
sentence and the role words are repeated there, as `catalogue.error`
repeats `home.bookshelves.error`: each screen owns its words. Rejected:
the bookshelf screen reading `home.bookshelves.*`.

**The view's own cases, then the scenarios as guards**, as in T079 and
T081. Rejected: the scenarios as the view's red (its behaviour resting on
the whole app alone).
