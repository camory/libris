# T012 — Expired session in the browser and the installed app

**Backlog line:** Expired session in the browser and the installed app. The
service worker's navigation route excludes `/session`
(`workbox.navigateFallbackDenylist`), `frontend/nginx.conf` answers `/session`
with a 302 to `/`, `FetchMeApi` takes an `onUnauthenticated` callback called on
a 401 (its spec produces the 401 from a fake `fetch`, the Contracteer mock
never serves one), and `main.ts` wires it to
`window.location.assign("/session")`. Verified by the specs, the built `sw.js`,
and by hand on the Pixel: reopen the site and the installed app after the
Authelia session expired, land on the login, come back greeted (D06). If the
installed app fails the redirect, the D06 fallback becomes a task.

**Serves:** PRD §4.8 (installable PWA on Android), §4.10 and §5 (every request
passes through the household's Authelia login); decisions D06 (the 401 means an
expired session, Authelia answers it, the contract does not declare it, the
frontend leaves the app through the network-only path `/session`), D05 (`main.ts`
alone wires the ports, the layers), D07 (`npm test` is the gate, `infra/api`
runs against the mock, one spec beside the module), D09 (nginx serves the built
site), D10 (Conventional Commits, code in English).

## Goal
When this task is done a reader whose Authelia session has expired stops seeing
a page without a greeting: `GET /api/v1/me` answers 401, the API client calls
back, the browser navigates to `/session`, the service worker leaves that path
to the network, Traefik hands it to Authelia, the reader logs in and comes back
to a page that greets them. It matters now because it is the last defect the
`v0.1.0` check on the Pixel found (`agent/PROGRESS.md`, 2026-09-10) and the last
task before Phase 0 closes; the escape path it builds is also what the OIDC move
of D06 will reuse, since it lives in `main.ts` and not in the client.

## Risks and decisions
- **The callback is a required constructor argument, decided locally.** D06
  says the client "takes an `onUnauthenticated` callback"; making it optional
  would let a caller forget the escape path and would add an untestable
  `?.()`. The one other caller is the T007 spec's contract case, which passes
  `() => {}` — measured green, ESLint does not object to the empty arrow.
- **The client rejects after calling back, decided locally.** Something must
  end the method: the body of a 401 is Authelia's, not a `CurrentReader`, so
  parsing it would be a lie. A rejection is what the spec asserts. Its cost:
  `HomeView`'s `.then()` leaves an unhandled rejection in the console while
  the browser navigates away — visible only to whoever has devtools open on a
  page that is leaving. The alternative (a promise that never settles) hides a
  bug instead of reporting it.
- **The 401 case lives in the existing spec file.** D07 fixes the convention —
  one `.spec.ts` beside the module — so a second file (`…unauthenticated.spec.ts`)
  would invent a naming scheme this task has no right to invent. The file then
  holds one case against the mock and one over a stubbed `fetch`; the comment
  is the case name, not a note in the code (D07, "no rationale in code").
- **`vi.unstubAllGlobals()` in an `afterEach`, not a config flag.** Vitest's
  `unstubGlobals: true` in `vite.config.ts` would apply to every future spec
  from a file nobody reads while writing a test; the `afterEach` sits beside
  the stub. Measured: with the stub left in place the contract case still
  passes today only because it runs first — do not rely on the order.
- **`Response` and `vi.stubGlobal` in the jsdom environment: measured green**
  on this tree (Node 24, Vitest 5, jsdom 30), no import and no type cast
  needed; `vue-tsc --build` and ESLint accept the stub as written.
- **The denylist is a regexp anchored on the exact path**, `/^\/session$/`, so
  `/sessions`, `/session/x` and a query string keep the SPA fallback. Measured:
  `npm run build` writes it into `dist/sw.js` verbatim.
- **`navigateFallbackDenylist` needs a `navigateFallback`**; vite-plugin-pwa
  defaults it to `index.html` in `generateSW` mode (read in
  `node_modules/vite-plugin-pwa/dist/index.js`), which is exactly the fallback
  the release on the Pixel showed. Do not set `navigateFallback` by hand.
- **nginx answers the 302, not a static file.** `location = /session` is an
  exact match, so it wins over `location /` whatever the order in the file, and
  no `try_files` is involved. The redirect is to `/` and not to `/index.html`:
  what matters is that the *navigation* to `/session` crosses Traefik, where an
  expired session meets Authelia; when the session is valid the reader is sent
  back to the app. A 302 without cache headers is not cached by default, so no
  `Cache-Control` is added.
- **Nothing here can be verified in the sandbox end to end** (D08: no Docker,
  no nginx, no Traefik, no Authelia). The three things the run can prove are
  the specs, the string in the built `sw.js`, and that the diff is what the
  criteria say. The PR body must say that the redirect through Authelia is
  proven on the Pixel, by Tophe, after deployment.
- **The fix reaches a reader only after the new service worker takes over.**
  The installed app keeps the old worker — the one that swallows `/session` —
  until it updates, so the first reopen after the release may still fail. The
  hand check therefore opens the app once before testing the expiry. This is
  the same lag `agent/PROGRESS.md` records for the footer revision on
  2026-09-10; if it makes the check unreliable, the *Proposed* item about
  `virtual:pwa-register` is the follow-up, not a change in this task.
- **`window.location.assign("/session")` rather than `href = …` or a router
  push.** A router push stays inside the SPA and never reaches the network,
  which is the whole bug; `assign` is the explicit form and is what D06's
  wording ("wires it to a navigation") asks `main.ts` to own.
