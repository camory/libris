## Goal
When this task is done a lookup asks the BnF and Open Library at the same time,
on a virtual thread each, and answers one edition merged in the order of the
sources: the BnF's value for every field it gives, Open Library's for the rest;
the four scenario cases Tophe left skipped for this task are green. It matters
now because the phase's *Done* asks Tophe to type 9782380751673, a book the
catalogue does not hold, and read a card filled by Open Library alone — today
that ISBN answers "unknown" — and because asking the two sources one after the
other would spend two timeouts on every miss, which the spec forbids: "a lookup
costs the slower source and not the sum".

## Risks and decisions
- **`merge` loses its `isbn` parameter.** Every adapter fills `isbn` with the
  ISBN it was asked, and no field is derived from the ISBN inside the domain
  any more, so `merge(editions)` takes `editions.first().isbn`. The use case
  calls it with a non-empty list only, which is why no empty-list branch is
  written: the `Found` case is chosen by there being at least one `Known`.
- **`openLibraryCoverOf` does not come back to `domain`.** Before T021 the
  merged cover was always built from the ISBN; since T021 the BnF fills
  `coverUrl` for every record it maps, and the two scenario cases Tophe
  committed expect the catalogue's cover when the BnF answered
  (`S5 Merged answer`) and Open Library's when it did not (`S5 Merged answer,
  from Open Library alone`). So the cover is an ordinary merged field and the
  Open Library URL is that adapter's own value, built in the adapter.
- **How the sources are asked at once.** `Executors.newVirtualThreadPerTaskExecutor()`
  inside `use {}` — an `ExecutorService` is `AutoCloseable` and closing it
  waits for the tasks — and `invokeAll(callables)`, which answers the futures
  in the order of the tasks, so the merge order is the bean order and no
  sorting is needed. `invokeAll` returns only once every task is done, which is
  what the port's time contract allows: the slowest source is bounded by its
  own read timeout. Plain JDK, no dependency, and `application` may already
  import `java..` under the ArchUnit rule — check `ArchitectureTest` before
  assuming a rule change is needed; none is.
- **How the parallel asking is proven.** Two fakes sharing a `CyclicBarrier(2)`:
  each waits at the barrier before answering, so both must have been asked
  before either returns. The wait is **bounded** — `await(timeout, unit)` — so
  a sequential implementation makes the fake throw and the test fail in a
  second or two instead of hanging the gate forever. A test that can hang is
  worse than no test.
- **The recorded pick of the work does not prove the pick by itself.** Measured
  on 2026-09-15: the search answer for 9782253098058 lists two works,
  `/works/OL36287W` then `/works/OL15196753W` which holds the edition — but
  **both carry `author_name: ["Alexandre Dumas"]`**, so an implementation that
  simply takes the first work is green on that case. The recorded case stays
  (it pins the fields, the single author and the shape of a real answer), and
  the discriminating case beside it is `a search naming no work holding the
  edition gives no authors`: `knows(isbn)` for the edition document, then
  `answers("/search.json", …)` with a short hand-written body whose only work
  holds a different `edition_key`, which must answer an empty author list. That
  case is red on "the first work wins" and on "every work's authors". Write the
  body inline in the test, as T013 wrote its malformed-author body; do not pass
  a hand-written body off as a recording.
- **The work's authors, not the edition's.** The edition document also carries
  an `authors` array of keys, and following it is exactly the request-per-author
  shape the spec and the backlog line forbid. Read `author_name` from the search
  answer only, and map every name to `WRITER`: the search answer gives no
  roles.
- **The bean names.** `LookupConfig` declares `bnfSource` and
  `openLibrarySource`, as it did before T021. A bean of `infra.lookup` may not
  be named `bnf`, and `openLibrary` is likewise the scenario harness's WireMock
  bean name (`agent/GOTCHAS.md`); the `Source` suffix keeps both clear of it.
- **`LibrisApplicationTest` regains a title it once had.** `the BnF is the only
  source` becomes `the BnF is asked before Open Library`, the exact title of
  the case T021 replaced, asserting the classes of the injected list in order.
  Restoring a name from the history is not a new convention.
- **Where `LIBRIS_OPEN_LIBRARY_URL` is declared.** In `application.yaml` only,
  `open-library-url: ${LIBRIS_OPEN_LIBRARY_URL:https://openlibrary.org}`, as
  T013 had it and as `LIBRIS_BNF_URL` is declared today. No `.env.example` and
  no compose file names a source URL, so none is edited: the defaults are the
  production values.
- **Open Library's date is a free text.** `publish_date` is `"Dec 30, 2020"`
  for 9782380751673, `"Jul 15, 2013"` for 9782723488525 and `"2003"` for
  9782253098058, so the publication year is the first four-digit run of that
  text, as the retired adapter did. `number_of_pages` is simply absent for
  9782253098058, which is a `null` page count, not a zero.
- **`S5 Merged answer` depends on the merge order, not on a new recording.**
  The BnF answer behind `partiallyKnows("9782723488525")` has no year and no
  page count, and Open Library's edition gives 207 pages and 2013; the title
  `"Romance dawn"` and the author `"Eiichirō Oda"` are the BnF's, where Open
  Library's search answers `尾田栄一郎`. If that case fails on the title or the
  author, the merge is running in the wrong order — not the recordings' fault.
- **Traps to expect** (`agent/GOTCHAS.md`): run `./gradlew detekt` before each
  commit, and remember `detekt` alone covers main sources — test sources are
  checked inside `check`; `ImportOrdering` is lexicographic; `ReturnCount`
  allows two returns; a caught exception must be named `ignored` to keep
  `SwallowedException` and `TooGenericExceptionCaught` quiet; keep the
  `@BeforeAll` HTTP warm-up in `OpenLibrarySourceTest` and a real recorded
  answer behind any `answersTooLate`; `OpenLibraryStubs.knows` matches the
  search on the `isbn` parameter alone, so assert the query string in full from
  `server.allServeEvents`. Any command containing `gradlew … check` counts as a
  gate run: never mention it inside another command, run it plainly and last.
