## Goal
The backend pins `v0.19.0`: `GET /api/v1/books` reads `q` and answers
`near`, false; a query reading as a whole ISBN answers the reader's edition
of that ISBN alone, any other query none, and no query the catalogue as
before. It is the skeleton T165 to T168 fill: the query value, the use case
taking it and the port's search statement, each then given words, tomes and
near matches.

## Risks and decisions
**Fit.** One run: one pin, one parameter and one field on an existing
operation, one value type, one port overload and its statement, six test
files, no migration. Rejected: a split, since the bump reds the
catalogue's cases and the field alone greens them, while S2 needs the query
end to end.

**`CatalogueQuery`, a value of `library.domain.copy`.** It sits beside the
query port that reads it (D12, a query port in its concern's sub-package),
and depends on `bibliography.domain` only for `Isbn`, as `Copy` does for
`EditionId`. `of` answers `null` for a blank text, which the controller
passes on as no query, so the use case takes the value and never the
text; `of` only checks, so the public constructor `require`s the same rule
(`CoverName`). `isbn` is a member of the value: reading a query is the
query's rule, and T165 adds the words beside it. Rejected: the text given
to the use case. Rejected: a sealed query of an ISBN and of words (the
words' shape is T165's to find). Rejected: trimming in `of` (no case needs
it; `Isbn.of` drops the spaces).

**`Isbn.of`, not `isbn13Of`.** The spec reads a query as an ISBN typed by
hand, hyphens and spaces dropped, an ISBN-10 converted, which is
`Isbn.of`'s; `web.isbn`'s `isbn13Of` gates a path the contract patterns to
thirteen digits. Rejected: reading the ISBN at the web edge (the contract
allows any text for `q`, and the spec makes reading it Libris's).

**`BrowseCatalogue` takes the query.** One use case answers the page, a
query narrowing it, as the spec says the search narrows the catalogue; it
calls the port's search when a query is given. Rejected: a `SearchCatalogue`
use case (the controller choosing between two, the rows' assembly twice).

**An overload of `findPage` on the port.** The search is the catalogue's
statement narrowed (D03), so the adapter shares its ranking and keyset;
the catalogue's `findPage` and its twenty slice cases stay as they are.
Rejected: a nullable query on the one method (every slice call churned).
Rejected: `EditionRepository`'s ISBN lookup in the use case (D03 answers
the ISBN from the search's statement, where T165 adds the words).

**`near` on `CataloguePage`.** Whether an answer is near is the use case's
fact, which T168 computes; the response copies it. Rejected: `near =
false` written in `BookPageResponse` (the response deciding a value, T168
moving it).

**Words answer none, for now.** A query reading as no ISBN gives the
statement a null ISBN, which `=` matches with no row, so no branch exists
for it; step 12 guards it until T165 gives the words their clause.
