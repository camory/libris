## Risks and decisions
**The deploy precondition is Tophe's.** As T087, T096 and T103: no run can
see what is deployed; the brief is written on T120 deployed, since Tophe
launches the loop. The PR body says merging is not deploying.

**`EditionForm` takes `isbn13` alone.** All an unknown ISBN gives it; T122
decides how a found edition fills it. The fields hold their text in the
component, which emits nothing until T123 sends them. Rejected: a blank
`SourceEdition` built for it now (a rule with no case yet).

**The fake gains a third parameter**, `names: string[] | Error = []`,
answered as `FakeSeriesNamesApi` does, so the 35 `new FakeSeriesApi(...)`
stay and every scenario's form finds no series by default, as #318's
`open()` did. The names helpers pass `undefined` to keep the find's
default. Rejected: an answers object (every caller rewritten).

**Words.** The form's own block `isbn.form` holds its labels and the
kinds (`isbn.form.kind.BOOK`…), one key per word, as `catalogue` repeats
`isbn.card`'s; the top part and the bookshelf row take the card's
`isbn.card.isbn` and `isbn.card.noCopy`, being the card's parts (U06).
`isbn.form.volume` is *Tome* alone until T125 keys it by kind. Rejected:
the card's row labels for the fields (a row's word, not a field's).

**The kind is three native radios** sharing one `name`, each inside its
part's label, so `getByRole("radio", { name })` and `checked` read them as
#318 expects; choosing another is the browser's until T125 rewords.

**Résumé grows by CSS**, `field-sizing-content` with three lines as its
minimum height: Chrome on Android has it, and jsdom lays nothing out
anyway, so the growth is checked by hand. Rejected: measuring
`scrollHeight` in script (more code, still untestable here).

**The numeric fields are `type="text"` with `inputmode="numeric"`**, as
the ISBN field: a `number` input empties `deux mille` and `1,5`, which
T124 must refuse with their text kept (U04).
