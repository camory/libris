# T046 — The catalogue tab, its page and the empty catalogue

**Backlog line:** Frontend: the catalogue tab, its page and the empty
catalogue, on `v0.7.0`. The line also covers the pin, the port and its client
joining `LibrisPorts`, the third tab, the page's header, the five skeleton
rows, the empty state, the composable and the tests. It realises S3 on the
frontend and un-skips the frontend test of S3. The full text is in
`agent/TASKS.md`.

**Serves:** spec `catalogue` S3, the *Screen* states *Loading* and *Empty*, its
route and tab; PRD §4.1; D04, D05, D07, D10; U03, U05, U07, U08. The
precondition is met: `3c92bef` (#148) laid the skipped tests, port and fake.

**First of its kind:** the first U05 **empty state** on a screen, the first
**list skeleton** (one row component drawn several times), the first **client
sending a query parameter**, and the first **port read on each arrival**.

## Goal
When this task is done, the tab bar has a third column that leads to
`/catalogue`. That page shows its header and five skeleton rows while the
first page comes, and the empty state when the reader's bookshelves hold
nothing: the catalogue's walking skeleton, so T047 only adds the rows.

## Risks and decisions
**The composable is `useBrowseCatalogue(catalogueApi)`, which exposes `state`
and `browse()`.** The name follows the backend's use case and the sentence
*browse the catalogue*, and its verb is the one function. In T046, `browse()`
asks for the first page and replaces the state. T049 gives later calls the
next page.
- Rejected: `useCatalogue`, because it names a noun and no sentence.
- Rejected: loading inside the composable's creation, because the view could
  then not ask anew without re-creating it.

**`CatalogueState` is `{status: "loading"} | {status: "empty"}` and starts at
`loading`.** The screen shows its skeleton from the first render, so there is
no idle state to draw. The union follows `AddState`, and T047 and T048 add
`listed` and `unavailable`. A page with books leaves the state untouched in
T046, and no case covers it. That is T047's.
- Rejected: a `pages` array plus flags: the states exclude one another.

**The client rejects on any status but 200.** The port answers a `BookPage`
or rejects. The 400 can only follow an `after` that is not an id, which the
screen never sends, and S4 reads a failure as a rejection. The mock answers a
400 with a random problem body, so a spec could not assert its `type` anyway
(probed while planning).
- Rejected: `BrowseAnswer` with a `problem` outcome: a type no screen reads.

**The skeleton row is its own component, drawn five times.** A test counts
it with `findAllComponents`, as the cover's icons are counted, without a
class or a tag. T049 draws two of it under the rows. It is `aria-hidden`, so
S1's `listitem` query never reads it.
- Rejected: one `CatalogueListSkeleton` of five rows, because T049 needs two
  rows.
- Rejected: a `role` or `aria-label` put on it for the test, because the
  skeleton means nothing to a screen reader.

**The scenario file changes beyond its `.skip`.** Moving the fake into the
ports object once the port joins `LibrisPorts` is part of the precondition's
PR (#148). D07's five places are red together. That is the file's only other
change.
