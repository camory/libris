## Goal

whole catalogue at once, the box keeping the focus so the reader types
again; the browser's own clear button never shows beside it. It closes S6,
the last way out of a search before T172 to T176 build on the field.

## Risks and decisions
**The cross is the field's, and emits `search` with `""`.** The field
owns the box and its pause, so the cross empties its model, drops the
pending pause and emits `search` at once with the empty text; the view's
`search` reads `null` from `searchQueryOf("")` and holds `ready`. The
value emitted is the literal `""`, not the model read back: a `defineModel`
bound by the parent reads the parent's prop, which changes only on the
parent's re-render (see the search item of the frontend gotchas).
Rejected: a `clear` event the view would map (a second event for what
`search` already says); a `reset` verb on the composable (D10, one verb).

**The cross shows for any character, spaces included.** "Once the box
holds text": the box shows what was typed as typed, so a text of spaces
is text and the cross empties it. Rejected: the cross from the trimmed
text alone (a box visibly holding spaces with no way to empty it).

**The browser's clear button is hidden from the template.** Chrome on
Android draws `::-webkit-search-cancel-button` on a `type="search"` input,
and Tailwind's preflight resets only `::-webkit-search-decoration`. The
box takes a Tailwind arbitrary variant hiding that pseudo-element
(`appearance: none`); jsdom draws neither, so no spec sees it, and the
proof is the rule in the built CSS plus the Pixel. Rejected: a rule in
`style.css` (it holds the theme tokens and the base, not one control's
part); `type="text"` with `role="searchbox"` (loses the keyboard's search
key, T170).

**The focus is given back by the tap.** The cross's click focuses the box,
which on Android opens the keyboard, whether the box had the focus before
or the search key had closed it; step 6 starts from a box without the
focus so it reds. Whether the keyboard opens is checked on the Pixel.
Rejected: keeping the focus by preventing the cross's `mousedown` alone
(the box lacks it after the search key).
