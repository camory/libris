# T010 — The reader on the home page

**Backlog line:** The reader on the home page. `createLibrisApp(ports, revision)`
builds a router, i18n and Pinia of its own over the given ports and provides
them through typed injection keys; `main.ts` alone reads `import.meta.env`,
builds the real `MeApi` over the same-origin base URL and mounts the
application; `App.vue` receives the revision instead of reading it (D05). The
home view injects `MeApi` and greets the reader by display name, the message in
the `fr` catalogue (PRD §4.10, §5). Shared fakes of the ports live in
`src/fixture` (D07), with the ESLint boundaries element that lets a spec import
them. The dev proxy adds a dev admin's `Remote-*` headers, and `npm run
dev:mock` proxies `/api` to the Contracteer mock instead of the backend (D05,
D06). Tests: the home view mounted with the real i18n and a fake port provided
through its key, awaiting `flushPromises`; the application created through
`createLibrisApp` over fake ports renders the home view (D07).

**Serves:** PRD §4.10 (Libris knows the reader Authelia sent and shows them by
the display name it owns) and §5 (mobile-first UI in French, every feature with
automated tests); decisions D04 (the frontend developed against `contracteer
mock`), D05 (`createLibrisApp`, provide/inject with typed keys, `main.ts` alone
reads `import.meta.env`, the layers and their boundaries), D06 (the dev proxy
carries the Authelia headers the backend trusts), D07 (`npm test` is the gate,
the frontend test slicing, `src/fixture` for shared fakes), D10 (Conventional
Commits, French UI text).

## Goal
When this task is done Phase 0's screen exists: the browser opens Libris and
reads *Bonjour \<display name\>*, the name coming from `GET /api/v1/me` through
the client T007 wrote, wired by a `createLibrisApp` that a test can build over
fake ports. It matters now because it is the last piece before T008 and the
`v0.1.0` deployment — it is what Tophe checks from a phone — and because the
wiring it establishes (a port provided by `createLibrisApp` under a typed key,
injected by the view that needs it, faked from `src/fixture` in tests) is the
shape every later screen copies.

  export interface LibrisPorts {
    meApi: MeApi;

## Risks and decisions
- **Where the injection key lives, decided locally:** beside the port it types,
  in `src/application/MeApi.ts`, as `meApiKey`. D05 fixes the mechanism
  ("provide/inject with typed keys") and not the file. Beside the port, the key
  and the interface change together and a view imports one module; a separate
  `keys.ts` would be a second place to look and a module that owns nothing.
  `InjectionKey` comes from `vue`, which `application` may import (the
  boundaries policies allow every non-`domain` element to import external
  modules, and D05 already puts Vue composables in that layer).
- **`inject(meApiKey)!`, not an `if`.** The key is always provided by
  `createLibrisApp` and by every spec that mounts the view, so a guard would be
  a branch no test can redden. The non-null assertion is the Vue idiom and the
  configured ESLint (`typescript-eslint` recommended) accepts it — measured
  green. If a later screen needs a real absence, `inject(key, default)` is the
  answer, not a throw.
- **The greeting's French text, decided locally:** `home.greeting` =
  `"Bonjour {name}"`, rendered under the title. No document fixes the wording;
  it is one line of the `fr` catalogue and Tophe can change it in the PR. The
  view shows the greeting only once the reader has answered (`v-if`), so there
  is no flash of a name-less sentence and no loading text to translate.
- **The dev admin's identity, decided locally:** `Remote-User: dev`,
  `Remote-Name: Dev Admin`, `Remote-Email: dev@amory.fr`,
  `Remote-Groups: libris-admin` — enough for the backend filter of T009 to
  create a reader and grant `ROLE_ADMIN`, and obviously fake so nobody mistakes
  it for a real household account. It applies in `mock` mode too: the mock
  ignores unknown headers (measured, it answered 200 with them).
- **`--mode mock` rather than a second config file or an env var.** Vite already
  has modes, `defineConfig` receives one, and the script stays a one-liner. The
  mock's port is 9090, the port `docs/ARCHITECTURE.md` uses in its local
  development section; the test mock keeps 9099, so a developer can run both.
  Neither port is started by this task: `npm run dev:mock` against a mock that
  is not running fails with a proxy error, which is the same failure mode as
  `npm run dev` without a backend.
- **`window.location.origin` as the same-origin base URL.** D05 says `main.ts`
  passes the same-origin value; the empty string would work too, and reads as a
  missing value. In production the frontend and `/api` share
  `libris.amory.fr` (D09), and in dev the Vite proxy makes `localhost:5173` the
  origin of both.
- **`i18n.ts` and `router.ts` become factories.** D05 says `createLibrisApp`
  builds a router, i18n and Pinia *of its own*; a module-level `createI18n`
  would be shared by every app a test builds, and vue-i18n's global scope makes
  that leak between cases. The existing singletons and their imports go in the
  same commit; `HomeView.spec.ts` calls `createLibrisI18n()` per case.
- **`[meApiKey]` needs no cast in the spec's `provide`** (measured with
  `vue-tsc --build --force`): Vue Test Utils types `global.provide` loosely
  enough. Do not add `as symbol` on faith.
- **The revision travels as a root prop.** `createApp(AppRoot, { revision })`
  is what lets `App.vue` stop reading `import.meta.env` while the footer keeps
  its own prop; the `createLibrisApp` spec asserts the revision it passed is on
  screen, which is the only test that covers that wire.
- **Coverage of `main.ts`.** It stays untested by design (composition root);
  changed-line coverage is informational in CI (D07), so it costs nothing, and
  keeping it to four statements is what makes that acceptable.
