## Goal
A save that names one of its edition's own authors in other capitals,
accents or end spaces respells that author for the house, so every edition
carrying them reads the spelling sent. The author's name index decides the
match inside the statement that finds or inserts the author, as T156 did
for the series, so no Kotlin code folds a name for it.

## Rules in play
- D02 — the rule lives in `JdbcEditionRepository`
  (`bibliography.infrastructure.persistence`), which writes the author
  rows; `EditionRepository`, `EditEdition`, `HoldEdition`, `web` and
  `library` do not change.
- D07 — the one `@Disabled` line of *S5 …, its author* is removed and
  nothing else in `HeldEditionEditScenarios` changes. The rule is decided
  in SQL, so it is proven in the JDBC slice against PostgreSQL. No
  use-case case: `EditEdition` is unchanged, and its *the edition answered
  is the one the house holds after the write* already proves it answers
  what the house reads back. No test of a controller. `ApiContractTest`'s
  `tests=` unchanged from `main`.
- D10 — SQL keywords in upper case; Given / When / Then; a new fixture
  goes below the class, where its first user reaches it; no rationale and
  no `D##` in code.
- D11 — no optimistic locking: the last save's spelling wins. The
  respelling adds no statement per author: it happens in the author's
  existing find-or-insert statement.
- D12 — an author is a value of the edition, with no repository and no id
  in the domain. The unique index on `BTRIM(name)` under
  `ignoring_case_and_accents` is the one implementation of "never
  doubled". The edition's own authors are those its `contribution` rows
  reference before the write, whatever their role then or now. Only the
  row the name lands on can change, and only when it is an own author, so
  a respelling merges nothing. `insert` never respells, since an edition
  not yet stored has no own authors.
- PRD §3 — case, accents and the spaces at the ends do not count; the
  index already matches all three (`JdbcEditionRepositoryTest`'s three
  *an author named again …* cases). An author is linked once per role.

## Risks and decisions
**Fit.** One run: no migration, dependency, port or contract change. The
work is one statement and the order of `update`, with three slice cases
and one un-skip. Rejected: a split (each half would be one cycle).

**The rule in `update`, not in a new port method.** D12 says it of an
edition *written* with a name of its own authors, and `update` is that
write. Its callers are `EditEdition`, which must respell, and
`FetchAwaitedCovers`, which writes back the names it read, so its
respelling changes nothing. T158's add of a held ISBN must respell too.
`insert` cannot respell, since a new edition has no own authors. The
worker racing a save already undoes the whole save (D11, no optimistic
locking); a respelling is undone with it, nothing new. Rejected: a second
method, as T156 added to `SeriesRepository` (there `HoldEdition` must not
respell yet and thirty calls kept `findOrInsert`; here no caller of
`update` must keep the old behaviour). Rejected: the use case passing the
own authors (authors have no id in the domain, D12).

**The match decided by the index, inside the statement.** As T156 did:
the conflict branch of the author's find-or-insert lands on the one row
the name matches, and gives it the name sent only when the edition
references that row. A Kotlin folding (`Contributions.kt`'s) disagrees
with the index on `Ø` and its kin, and could respell into a name another
author holds. Rejected: comparing the held and sent contributions in
`EditEdition` (a second matching rule). Rejected: an `UPDATE author`
before the find-or-insert (two statements, and a `WHERE` restating the
index).

**The own authors are read before `update` deletes the contributions.**
`update` deletes the edition's `contribution` rows before inserting the
new ones. A statement that reads the own authors from `contribution` sees
none once they are gone, so step 3's green has the own authors read
before that delete. How is the implementer's. `JdbcEditionRepository`
sits at 10 functions and detekt's `TooManyFunctions` reports it at 11, so
a function it gains costs another its place.

**Two names sent matching one own author.** A save naming one own author
twice, under two roles and two spellings (`herge` writer, `Hergé`
artist), leaves the row with one of the two spellings, unpromised, since
`Contributions` iterates in no promised order. No scenario names the
case, and S5's scenario sends one spelling under both roles. Rejected:
refusing such a save (no rule of the spec).
