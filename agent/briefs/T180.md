## Goal
`RemoteIdentity.of` answers no identity for a blank `Remote-User`, as it does
for a blank `Remote-Email`, and reads `Remote-User`, `Remote-Email` and
`Remote-Groups` from the UTF-8 bytes the proxy sends, as it reads
`Remote-Name`. After that, no reader can be welcomed with an empty username,
and an address or username with an accent is stored as the reader wrote it.

## Rules in play

  filter a username, an email, a display name and the authorities; nothing
  else in the backend reads a `Remote-*` header, and `WelcomeReader`, the

- D07 — the class that decides is tested on its own: every new case is a

## Risks and decisions
**The groups are proven through a non-breaking space.** Libris reads one
thing from `Remote-Groups`, whether `libris-admin` is among the names, and a
group outside ASCII is not `libris-admin` whichever way its bytes are read,
since UTF-8 never puts a comma's byte inside a character. The only answer
the decoding changes is a Unicode space beside the group: read as UTF-8, the
existing trim drops it; read as ISO-8859-1, the space's first byte becomes
`Â`, which stays. So step 4 is the case that turns red, written in the shape
of *a group after a comma and a space is read*. Rejected: exposing the
groups on `RemoteIdentity` for the test (a public member no caller uses);
decoding the groups with no case (production code no test motivates, and a
mutation nothing catches).

**Blank is judged on the decoded text.** The user header is read through the
same decoding as the others and then refused when blank, as the email
already is; the order is the implementer's, and no step pins it, since no
proxy sends a username of Unicode spaces alone. Rejected: a fifth step for
a username of U+00A0 alone (a case no reader meets).

**Readers stored before the fix.** A reader whose username was sent with a
non-ASCII character was stored under its mangled form, and after this task
the decoded form finds no reader, so `WelcomeReader` would welcome a second
one with a new bookshelf. Every username of the tests is ASCII, and the
household's Authelia usernames are not readable from here, so the PR's
**Follow-ups** asks Tophe to check, before deploying, that no stored
username holds a character outside ASCII
(`SELECT username FROM reader WHERE username ~ '[^ -~]'`); any such row is
renamed to its decoded form by hand. Emails and display names already
stored are not touched by this task and are not read again (see *Out of
scope*). Rejected: a migration rewriting the stored usernames (a data change
the line does not ask, made blind to production's rows).
