# T015 — The BnF source

**Backlog line:** Backend: the BnF source. `infra.lookup`: the SRU client on
`LIBRIS_BNF_URL`, queried `bib.isbn all "<isbn>"`, ranked before Open Library
in the merge; an empty record set means it knows nothing (D02). The UNIMARC
record mapped: title, subtitle, authors with the role their function code
names and `WRITER` when it names none (PRD §3), series and volume number,
collection, publisher, publication year, page count, and the language as its
two-letter code. Tested over the recorded answers under
`src/test/resources/scenarios/bnf`, the full record and the one without pages
and year. Realises S1 (backend), S5, S6; un-skips `S1 Typed ISBN, found`,
`S5 Merged answer`, `S6 One source down` and
`S6 One source down, past the timeout`.

**Serves:** spec `fast-entry` S1 (backend half), S5, S6; PRD §4.7 (the BnF
gives roles, series and collection for French titles; sources degrade
gracefully) and §3 (Edition, Series, Volume number, Collection, Author, Role,
with their *Avoid* lists). Decisions D02 (`infra.lookup` holds the source
clients, the domain stays framework-free, the timeout is the adapter's and the
use case never sees time), D04 (no contract edit: the backend pin stays
`v0.3.0`), D07 (the gate, the slices, the scenario tests are Tophe's and are
only un-skipped), D08 (nothing is added to the environment), D10 (Kotlin and
commit conventions, members imported not qualified), D11 (the ISBN-13 as
thirteen digits, absent optional values `null`).

**First of its kind:** the first source that answers XML — and with it the
first use of the JDK's XML parser and the first mapping of an external code
list (UNIMARC function codes) onto a domain enum — and the first wiring that
*ranks* two implementations of one port, since until now `List<IsbnSource>`
held a single bean and the order was nobody's decision.

## Goal
When this task is done Libris asks two sources for an ISBN, the BnF first,
maps its UNIMARC record onto `SourceEdition`, and the four scenario methods
T014 left skipped go green: a typed ISBN answers the BnF's title, subtitle,
author with their role, série, tome, collection, éditeur, year, language and
page count, over Open Library's cover, listing both sources. It matters now
because it is the last backend piece of the phase: after it, `S1`, `S5`, `S6`
and `S7` are all proven end to end, and the frontend tasks (T016 to T019) run
against a backend that answers what the reader will actually read.

## Rules in play
- **D02** — the client lives in `fr.amory.libris.infra.lookup`, implements the
  `IsbnSource` port of `domain.lookup`, and depends on nothing in
  `infra.persistence` or `infra.web`. The domain does not change: no new type,
  no new field, no framework type in it. The port's contract on time is the
  adapter's to keep: the BnF answers within `LIBRIS_SOURCE_TIMEOUT` or the
  client answers `Failed`; the use case is not touched and never sees time.
- **D04** — no contract edit of any kind. `ApiContractTest` keeps its `v0.3.0`
  pin; the response shape does not move; if a mapped field cannot be expressed
  in the released document — it can, the four scenarios show the exact JSON —
  report `blocked` rather than bend either side.
- **D07 (the gate)** — `cd backend && ./gradlew check` is the gate and must be
  run plainly, one gate per command, not piped and not chained, or the sandbox
  records nothing. Never claim it passed without having run it in this
  session.
- **D07 (slices)** — the BnF client is tested where it lives, in
  `infra/lookup`, over WireMock, with no Spring context; shared stubs and
  helpers live in the `fixture` package; test bodies are Given / When / Then
  unless a single statement; a test written to learn a library is deleted
  before the pull request.
- **D07 (scenarios)** — the four scenario methods the backlog line names lose
  their `@Disabled` and nothing else in
  `src/test/kotlin/fr/amory/libris/scenario/` changes: no assertion, no stub
  call, no import. A scenario that has to change is a spec conversation, not
  this task. The recorded answers under `src/test/resources/scenarios/` are
  read, never edited, and none is added.
- **D08** — the environment is given: no Docker, no new service, and no
  network call to the real BnF from a test. WireMock and the two recordings
  already in the repository are the whole harness.
- **D10** — official Kotlin style, immutable by default, no `!!`, no
  `lateinit`; members imported rather than qualified when the bare name is
  unambiguous (`BNF`, `Failed`, `ofSeconds`); Conventional Commits with the
  scope `backend`, branch `task/T015-bnf-source`, the
  `Co-Authored-By: Claude <noreply@anthropic.com>` trailer; comments,
  configuration and build scripts say what, never why, and never cite `D##`.
- **D11** — the answer carries the asked ISBN as thirteen digits (the record's
  `010$a` carries hyphens and is not used); a field the record does not give
  is `null`, never a blank string.
- **PRD §3** — the words: Series is the *série* (One piece), Collection is the
  publisher's collection printed on the spine (Shonen manga), Volume number is
  the *tome*; an author has one display name; when a lookup gives no role, the
  role is `WRITER`.

## Risks and decisions
- **How the record is parsed.** Decided: the JDK, no dependency —
  `DocumentBuilderFactory` namespace-aware, then the `datafield` and
  `subfield` elements of the marcxchange namespace
  (`info:lc/xmlns/marcxchange-v2`), read through `getElementsByTagNameNS` (or
  `javax.xml.xpath` with `local-name()` predicates if that reads better), into
  whatever small shape makes the mapping readable — a map of tag to its
  subfields is the obvious one. Every XML library considered is a new
  dependency for a document of thirty fields, and Jackson's XML module is not
  on the classpath (T013 measured the same for its Kotlin module). Set
  `disallow-doctype-decl` to `true` on the factory: the answer comes off the
  public internet and a DOCTYPE in it has no business being expanded here.
- **What the client asks for.** Decided:
  `?version=1.2&operation=searchRetrieve&recordSchema=unimarcxchange&maximumRecords=1&query=bib.isbn all "<isbn>"`,
  the parameters verified against the live BnF endpoint on 2026-09-13, which
  answers exactly the recorded document for that ISBN. `maximumRecords=1`
  because an ISBN identifies one edition and the client maps the first record
  only. `LIBRIS_BNF_URL` is the whole endpoint, path included
  (`https://catalogue.bnf.fr/api/SRU`), because that is what the scenario
  harness registers (`bnf.baseUrl() + "/api/SRU"`).
- **Where the UNIMARC values come from.** Decided, read off the two
  recordings, and each pinned by a criterion:
  - title `200$a`; subtitle `200$e` (`200$b` is the general material
    designation and `200$f` a statement of responsibility — neither is used);
  - authors: fields `700`, `701` and `702`, in document order, the name being
    `$b` then `$a` separated by a space (`Eiichirō` + `Oda`), `$a` alone when
    there is no `$b`, and the role from `$4`. The `71x` fields (corporate
    bodies) are ignored: a company is not an author of PRD §3;
  - series `461$t` with the volume number `461$v` read as an integer, `null`
    when it is not one; collection `410$t`. **Not** the two `225` fields,
    though they carry the same words: `225$v` is the free text `tome 1` and
    telling the série from the collection there means reading indicators,
    while `461` (the set) and `410` (the collection) already say which is
    which, in the words of PRD §3;
  - publisher `210$c`; publication year the first four-digit group of `210$d`
    (`impr. 2013` → 2013). **Not** `100$a` and not `410$d`, which both carry
    2013 for this record: the record without pages and year has no `210$d`,
    and S5 needs it to answer nothing so that Open Library's year fills the
    field;
  - page count the number before `p.` in `215$a` (`1 vol. (203 p.)` → 203; a
    plain digit-grab would answer 1);
  - summary and cover URL: nothing. The BnF gives no summary in these records,
    and the cover is Open Library's by ISBN, which the merge rule of T014
    already forces;
  - `isbn13` is the asked ISBN, not `010$a`, which carries hyphens.
- **The function codes.** Decided: `070` → `WRITER`, `440` → `ARTIST`,
  `730` → `TRANSLATOR`; no `$4`, or a code the map does not hold, → `WRITER`
  (PRD §3: when a lookup gives no role, the role is `WRITER`). The three codes
  were verified on 2026-09-13 against live BnF answers — *Blacksad* gives
  `070` Díaz Canales, `440` Guarnido and `730` for its translator, *Largo
  Winch* and *Les vieux fourneaux* the same `070`/`440` pair. Since no
  recording in the repository carries `440` or `730`, the mapping is an
  `internal` top-level function in `BnfSource.kt` that `BnfSourceTest` calls
  directly with the four inputs, rather than untested data behind a private
  wall: a code list is exactly the kind of table that must be exercised by a
  test, and the alternative — inventing a record to stub — would be worse.
- **`COLOURIST` has no code.** Six BD records read on the live catalogue on
  2026-09-13 credit no colourist at all; the BnF puts the *dessinateur* under
  `440` and nothing else. Decided: no `COLOURIST` entry is invented. The role
  stays in the domain enum, unmapped, and the implementer adds a line to
  `agent/PROPOSED.md` so a real record can settle it later.
- **The language.** Decided: `101$a` is an ISO 639-2/B code and the answer is
  its two-letter code, from a map holding `fre → fr` and nothing else; a code
  the map does not hold answers `null`. Measured on this JDK: the standard
  library maps `fr` to `fra`, the *terminology* code, and knows nothing of the
  bibliographic `fre` the BnF sends, so no JDK call does this. A full
  bibliographic table is twenty entries no test would exercise; the map grows
  with the recordings, and the implementer notes it in `agent/PROPOSED.md`.
  `101$c` (the language of the original, `jpn` here) is not the edition's
  language and is ignored.
- **What "it knows nothing" is.** Decided: an answer carrying no
  marcxchange `record` element — which is what the recorded
  `9782000000013.xml` is, `numberOfRecords` 0 under HTTP 200 — is
  `NothingKnown`. A 5xx, a timeout, an unparseable body and a record with no
  `200$a` are all `Failed`, in one `try`/`catch` around the whole answer as
  `OpenLibrarySource` does (catching what the HTTP layer throws and what the
  parser throws, with the parameter named `ignored` so detekt's
  `SwallowedException` stays quiet). An SRU diagnostic answer carries no
  record either and therefore reads as nothing known; no scenario exercises
  it and no branch is written for it.
- **The ranking, and where it lives.** Decided: in the wiring, with `@Order`
  on the two `@Bean` methods of `LookupConfig` — the BnF first, Open Library
  second. `IsbnLookup` asks its injected list in order and `merge` keeps the
  first value given, so the order of that list *is* S5's "the BnF's value for
  every field the BnF gives". Bean declaration order alone is not a promise
  Spring makes, so the annotation is the point; sorting inside the use case
  would put a ranking of named sources in `application`, which depends on
  `domain` and must not know that the BnF is better at French titles.
  `LibrisApplicationTest` is what pins it, and S1 and S5 fail if it flips.
- **Configuration.** Decided: `SourcesProperties` gains `bnfUrl`, and
  `application.yaml` gains
  `bnf-url: ${LIBRIS_BNF_URL:https://catalogue.bnf.fr/api/SRU}` beside the
  Open Library key — the shape the tree already uses (T013's brief proposed
  `@param:Value`; the implementer chose `@ConfigurationProperties` and that is
  what exists, so follow the code). The timeout is shared: one
  `LIBRIS_SOURCE_TIMEOUT` bounds each source, which is what the port's
  contract says (D02) and what `S6 One source down, past the timeout`
  exercises. No `.env.example` entry: the defaults are the real sources and
  the gate needs neither variable.
- **The duplicated request factory.** After this task the JDK `HttpClient`
  with its connect and read timeouts is written twice in `infra.lookup`.
  Decided: extract it on green, as the refactor step of the last cycle, into
  one internal function of the package (`SourceHttp.kt`,
  `sourceRestClient(baseUrl, timeout)`), leaving both clients' behaviour and
  both tests unchanged. It is the same move T014 made with the cover address.
  If the extraction turns out to change either client's behaviour, drop it and
  say so in `agent/PROGRESS.md`: the duplication is cheaper than a surprise.
- **The cold JVM and the timeout case.** `OpenLibrarySourceTest` warms the
  client up in `@BeforeAll` under a 20 s timeout before the real cases run
  with 200 ms, because the first call on a cold JVM costs more than the
  timeout. The BnF client loads an XML parser on top of that, so keep the same
  warm-up, and if the timeout case still flakes, raise the test's timeout
  rather than the delay — the gate must not spend seconds waiting.
- **detekt gotchas that cost a cycle each** (from T014's run): imports must be
  in lexicographic order (`ImportOrdering`), and a data-class fixture is
  exempt from `LongParameterList` while a function of twelve parameters is
  not. A class of many small private mapping functions may reach
  `TooManyFunctions`; group the mapping into fewer functions rather than
  suppress the rule or edit `config/detekt/detekt.yml`, which this task does
  not change. Run `./gradlew detekt` before each commit.
- **If the BnF's answer cannot be mapped as written above.** The two
  recordings are in the repository and were read while writing this brief;
  every value in the criteria was taken from them and cross-checked against
  the four scenario methods. If one still disagrees, the recording wins over
  this brief for the *mechanism*, and the scenario wins over both for the
  *value* — a scenario that cannot pass without changing what it asserts is a
  spec conversation with Tophe: report `blocked`.
