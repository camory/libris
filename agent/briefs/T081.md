## Goal

answer, the form's row stays open with the name typed and says why under the
field; no row is added. This closes S3 and S9's creating case on the home

## Risks and decisions
**The composable decides what an answer means.** `useCreateBookshelf` maps
`/problems/conflict` to `taken` and every other problem, like a rejection,
to `unavailable`, as the backlog line and *Questions for the human* say for
a refusal the screen never provokes. The view and the row only render the
state. Rejected: the view switching on the problem `type` (a meaning tested
in the view instead of the application). Rejected: a third message for the
blank name (the screen never sends one; the spec gives it no sentence).

**The row picks its sentence by key.** `NewBookshelfRow` takes `failure`,
`"taken" | "unavailable"`, a literal union since a component imports no
`application` type, and shows `home.bookshelves.failure.<failure>`, so the
catalogue holds one entry per value and the component never branches (as
U06 says of the card). Rejected: the view passing the sentence (the words
chosen away from the component that draws them). Rejected: replacing
`creating` by one status prop (rewrites T080's cases for no new behaviour).

**The message lasts until the next answer.** A new `create` sets
`creating`, which carries no failure, so the message leaves while the
creation runs and the next answer replaces it (U05; the spec's *Creating*
has no message). Typing does not clear it. Rejected: clearing on input (no
document says so; a spec conversation if wanted).

**No danger outline.** U04's form in a list has fields with no border, and
mockups 6 and 8 show the field unchanged, the check still there. Rejected:
adding an outline for the refused field (U04's outline belongs to a bordered
field).

**The view's own cases, then the scenarios as guards.** As in T080, the
view's wiring is proven by `HomeView.spec.ts`, and the two scenario tests
are guards once the view is green. Rejected: the scenarios as the view's
red, with no view case (the view's behaviour would rest on the whole
application alone).
