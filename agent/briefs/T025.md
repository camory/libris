# T025 — The Found state without its sources

**Backlog line:** Frontend: the Found state without its sources. The frontend
pin moves to `v0.4.0` in `vitest.global-setup.ts`: the API client's test
against the mock fails, the mock answering no `sources`. Then `sources` leaves
`IsbnResponse`, `SourceEdition` and the fixtures; the *Sources* row, its chips
and the `isbn.card.sources` text leave `SourceEditionCard` (U06), with the
card's tests over them. The client reads the fields it knows and ignores the
rest, so a backend still on `v0.3.0` keeps answering it. Nothing else changes
behaviour; un-skips nothing. Realises the Found state of S1 as the spec now
reads it.

**Serves:** spec `fast-entry` — the *Found* state of the *Screen* section, which
now ends at the summary and says "The card never says which source answered",
and the *Contract* section, which names release `v0.4.0` and drops `sources`
from the answer; PRD §4.7; decisions D01, D04, D05, D07, D10, D11; rules U06 and
U08 of `docs/DESIGN.md`.

**First of its kind:** the first **response field the frontend stops reading**
— every pin bump so far added an operation or a field, this one removes one,
and it is the first task of the pair D04's rewritten order describes (frontend
first on a removal, backend second once this is deployed). Three conventions
follow from it and no document states them yet: a pin bump that removes is a
*red* on the existing client spec rather than a new case; the compatibility
clause of D04 ("the frontend reads the fields it knows and ignores the rest")
gets its first proof, an `infra/api` case over a stubbed `fetch` answering a
`v0.3.0` body, beside the mock-driven cases; and a frontend scenario body is
trimmed, for the first time, because the spec it mirrors changed (D07 —
see *Risks and decisions*, the reviewer repeats this line in its verdict and
Tophe settles it on the pull request).

## Goal
When this task is done the frontend speaks `v0.4.0`: the card shows what the
sources know and never who knew it, no type or fixture of the tree carries a
`sources` field, and the client still reads whole the answer of the backend
running in production, which is on `v0.3.0` and keeps sending that field. It
matters now because it is the first half of a pair: the backend may only drop
the field (T026) once this frontend is deployed, and until then the two halves
must live together.

## Rules in play
- **D01** — one side moves: `cd frontend && npm test` is the whole gate of this
  task, nothing under `backend/` or `deploy/` is touched.
- **D04** — the pin bump in `frontend/vitest.global-setup.ts`, `v0.3.0` to
  `v0.4.0`, is the only contract-related edit of this run, and it decides
  nothing about the contract itself; the document is never consumed from a
  branch. The compatibility rule is the point of the task: the frontend reads
  the fields it knows and ignores the rest, which is what lets a `v0.3.0`
  backend keep serving it until T026 is deployed.
- **D05** — the layers keep their jobs: `domain/SourceEdition.ts` is the shape
  the app knows, `infra/api` owns the hand-written response type, `ui/components`
  stays presentational. No code generation: the response type is edited by hand
  from the released document.
- **D07** — `cd frontend && npm test` is the gate, run plainly as the last
  command of its call; `infra/api` runs against `contracteer mock`, one case per
  response the contract declares and none it does not; a component test mounts
  with props and the real i18n and asserts what the reader sees, never a tag, a
  class or a colour; every body is `// Given`, `// When`, `// Then` unless it is
  a single statement. No scenario is un-skipped by this task, and the only edit
  `src/scenario/FastEntryScenarios.spec.ts` takes is the two lines named under
  *Acceptance criteria* — the spec conversation behind them is commit `d2fb14b`
  (#83).
- **D10** — TypeScript strict, ESLint with the boundaries rules and Prettier;
  code and identifiers in English; Conventional Commits with the scope
  `frontend`, branch `task/T025-found-without-sources`, the
  `Co-Authored-By: Claude <noreply@anthropic.com>` trailer on every commit.
- **D11** — a response field is added, never removed or renamed, *while the
  major version stands*: `v0.4.0` is the release that removes this one, and the
  order of the two sides is what keeps the pair compatible meanwhile. An absent
  optional value still arrives as `null`, which is why every other field of the
  card keeps its `null` branch.
- **U06** — the card is `surface`, a `border`, radius 14: the cover and the
  heading, then one row per field, then the summary, and **the summary is the
  card's last part**. Nothing follows it: no *Sources* label, no chip, and U06
  no longer describes a chip at all.
- **U08** — every French word lives in the `fr` catalogue; a word no component
  displays any more leaves the catalogue with it.

## Risks and decisions
- **The two lines of `FastEntryScenarios.spec.ts` are removed, decided here.**
  D07 says a task changes nothing in a scenario test but the skip it un-skips,
  and that a scenario which has to change is a spec conversation. That
  conversation happened: commit `d2fb14b` (#83, Tophe's own) rewrote S1 and the
  *Found* state so that the card never says which source answered, rewrote U06
  to end at the summary, and created this task line in the same breath —
  "Realises the Found state of S1 as the spec now reads it". The two
  `toContain` lines are the last sentence of the old spec left in the tree, and
  the gate cannot be green while they stand. The precedent is T021, whose brief
  authorised the same edit for the same reason. The edit is exactly two deleted
  lines; anything more is a blocker, not a judgement call. The pull request body
  states it, and the reviewer checks the diff of that file line by line.
- **The compatibility clause gets a test, decided here.** D04's "the frontend
  reads the fields it knows and ignores the rest" is live behaviour for as long
  as production runs `v0.3.0` against this frontend, and the backlog line states
  it as a requirement, so it needs a proof. `contracteer mock` cannot give it:
  the mock serves `v0.4.0` and never sends the extra field. The tree already
  has the shape for a case the contract cannot express — `FetchMeApi.spec.ts`
  stubs `fetch` for the 401 of D06 — so the client's spec keeps its four
  mock-driven cases, one per response the contract declares, and gains one
  stubbed case beside them. Rejected: proving it by reading the code only (not
  checkable), and a second mock served from a copy of `v0.3.0` (a second pinned
  document in the tree, which D04 forbids).
- **The client keeps passing the parsed body through, decided here.** It casts
  and answers; it does not copy the fields it knows into a new object. That is
  the smallest code that satisfies "ignores the rest", and it is why the new
  case asserts with `toMatchObject` and never with `toEqual`: at runtime the
  answer of a `v0.3.0` backend still carries `sources`, invisible to every type
  and read by nothing. An implementer who makes the case pass by rebuilding the
  object has written mapping code no screen needs.
- **The chips case becomes a negative case rather than simply disappearing,
  decided here.** The backlog line retires the card's tests over the row, but
  the removal still needs a red, and the spec states a rule worth keeping under
  test — "The card never says which source answered". One case in place of one
  case, so the card's spec neither grows nor loses its guard.
- **`queryAllByRole("button")` goes with the chips, decided here.** It proved a
  chip is not a button; with no chip left, the card has nothing that could act,
  and U06's "props in, nothing out" is a rule about the component's interface,
  not about a rendered role.
- **The `Source` type and the `source` block of the catalogue go too, decided
  here.** The backlog line names the field, the row, the chips and the
  `isbn.card.sources` text; `Source`, `source.BNF` and `source.OPEN_LIBRARY`
  have no other reader once those are gone, and CLAUDE.md admits no property or
  word no feature of the task exercises. *BnF* and *Open Library* keep their
  spelling in U08 as a typography example, which asks nothing of the catalogue.
- **The pin is a network fetch.** `contracteer mock` loads the pinned URL when
  the global setup starts it; `v0.4.0` was read on 2026-09-15 and its only
  difference from `v0.3.0` is the removal of `sources` from the `Isbn` schema,
  from its `required` list and from the `ONE_PIECE_1` example —
  `additionalProperties: false` and every other example are unchanged, so the
  S1 scenario's cover assertion and the three problem cases stay true.
- **The gate runs in the sandbox.** `npm test` needs `contracteer` on the PATH
  and Node 24 (D08); on Tophe's box the frontend gate runs inside the image
  (`agent/GOTCHAS.md`). The run reports the duration it measured, and quotes no
  figure from here.
