# T056 — The picture is normalised

**Backlog line:**
> - [ ] T056 Backend: the picture is normalised.
>       Before it is stored, a fetched picture taller than 600 pixels is scaled
>       to 600 tall, its proportions kept, and encoded as JPEG; one 600 tall or
>       less is kept as fetched, in its own format, its bytes unchanged.
>       Unit tests of the rule over generated pictures, one per case.
>       Realises S6; un-skips the backend tests of S6, both cases.

**Serves:** spec `covers` S6 (both cases), S4 ("stores it, normalised, under
a name made from its bytes"); PRD §4.7; decisions D02, D04, D07, D09, D10,
D12
**First of its kind:** the first domain code over the JDK's image libraries
(`javax.imageio`, `java.awt.image`), and with it the first package outside
`java..` and `kotlin..` that `ArchitectureTest`'s domain rule admits
(`javax.imageio..`).

## Goal
A picture the worker fetches taller than 600 pixels is stored scaled to 600
tall, as JPEG, under the name of the bytes stored; any other picture is
stored as fetched. Covers stay small on the phone and in the covers volume,
whatever size a source serves (Open Library's `-L` is 1200 tall).

## Risks and decisions
**The rule is `Cover.normalised()`, called by the use case before the
store's write.** The cover holds the bytes and the media type the rule
reads, so the value keeps the rule (D12); the use case only applies it at
the moment S4 names, and records the name of what it stored. One call site
serves every source, the cascade of T057 included. *Rejected:* normalising
inside `Cover.of`, which `FileCoverStore.read` calls too, so every served
cover would be decoded again, and a stored file taller than 600 would read
back under another name than its own; in each adapter, three copies; in
`FileCoverStore.write`, which would store bytes under a name that is not
theirs.

**The JDK's image libraries in the domain.** `ImageIO` is the only reader
and JPEG writer at hand without a dependency, and D02's rule 1 names "the
Kotlin/Java standard libraries"; `javax.imageio` is Java SE but sits outside
`java..`, so the ArchUnit rule is widened by that one package, the rule's
text unchanged. Tophe settles it on review (first of its kind). *Rejected:*
a domain port with an `ImageIO` adapter, a new port and bean for a pure
function the JDK computes; a library such as TwelveMonkeys or Scrimage, a
dependency the task does not need.

**A picture whose height cannot be read is kept as fetched.** The JDK has
no WebP reader, and the spec says a WebP never needs scaling, inventaire.io
being asked at 600 tall; a picture whose height is unknown is not known to
be taller than 600. The same holds for a broken picture, so that one bad
answer never throws out of the worker's run and stops the awaited covers
after it. Whether such bytes are a cover at all is S8's, in T058.
*Rejected:* answering no cover, which would drop every inventaire.io WebP.

**What the encoding leaves open.** The spec names no JPEG quality and no
background: the writer's default quality is kept, and a transparent area's
colour is not asserted. Step 3's alpha channel is there for the trap of the
gotchas item, not for a colour.

**Two covers compare as instances.** `Cover` has no `equals`, and
`FetchAwaitedCoversTest` compares the stored cover with the fetched one by
`shouldBe`, so a cover kept as fetched must be the same instance or the
existing WebP cases red; step 7 compares names, which are values. JPEG
encoding by `ImageIO` is deterministic (measured: the same picture written
twice gives the same bytes), so `normalised().name` is stable within a test.
