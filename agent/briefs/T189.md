## Goal
One `internal` function of `HeldEditionReads.kt`,
`readersBookshelvesOf(bookshelves, readerId)`, answers the reader's
bookshelves by id, and the three places read them through it. The
catalogue's use cases then say once which bookshelves a reader sees, and
under what role.

## Risks and decisions
**In `HeldEditionReads.kt`, `internal`, beside `readersCopiesOf`.** The
file is where the catalogue package already keeps the reads its use cases
share, both `internal` top-level functions taking their repositories as
arguments; the three callers sit in that package. Rejected: a factory on
`ReaderBookshelf`'s companion (a data class of the answer would call a
repository, against D12); a method of `BookshelfRepository` (a port
answering an application type, against D02); a new file (a third shared
read where the file of two exists).

**Named `readersBookshelvesOf(bookshelves, readerId)`.** It answers what
each caller already calls `readersBookshelves`, in the form of
`readersCopiesOf(bookshelves, copies, readerId, editionId)` beside it.
Rejected: `readersBookshelvesById` (the type says the map; the
neighbour's form has no `By`).

**Three moves, three commits.** The function appears with its first
caller in its own file, then each use case moves alone, so each commit is
proven by its own test class. Rejected: one commit (three callers whose
proofs differ).
