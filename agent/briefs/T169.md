## Goal
The frontend reads `v0.19.0`, the application holds the search's port
and client, and the ouvrages show the search box: typed words ask Libris,
its first page's rows replace the catalogue's. T170 to T176 add the rest
of the search on this skeleton.

## Rules in play
- D04 — the pin `v0.19.0` is the only contract edit. It adds the optional
  `q` on `GET /api/v1/books` and the required boolean `near` on its page.
- D05 — the client lives in `infra/api`, one per resource: `search` joins
  `FetchCatalogueApi`. The port is `application/SearchApi.ts`, as it is.
  `createLibrisApp` provides it, `bootstrap` builds it. `SearchField` is
  presentational: a model in, no port.

- D07 — in `src/scenario`, S1's `it.skip` turns `it`, each `open()` gains
  its `searchApi` port, and `SearchScenarios`' `open()` moves its
  `app.provide(searchApiKey, …)` fake into its ports. Nothing else.
- D10 — a use case is `use` + sentence, state and one verb; PRD §3's
  words; Given / When / Then; scope `frontend`; stepdown order.
- U03 — the box sits in the page's column, between the switch and the
  list, and scrolls with them: not sticky.
- U04 — search field: no label above it; `aria-label` *Rechercher dans le

- U07 — `Search` from `@lucide/vue` at 22, `muted`, at the box's left, 8

## Risks and decisions
**The deploy precondition is Tophe's.** No run can see what is deployed:
written on T168 deployed; the PR body says merging is not deploying.

**The client is `FetchCatalogueApi`.** D05: one fetch client per
resource; the search reads `/api/v1/books` as the browse does (headers,
status check, `bookOf`). `bootstrap` builds one instance for both ports.
Rejected: a `FetchSearchApi` (two clients for one resource).

**The trimming is `searchQueryOf(text): string` in the domain.** U04 puts
the rule reading a field in the domain; T170 adds the two characters to
it. The composable calls it; the field and the view never trim. Rejected:
`trim()` in the view or the field (U04).

**`useSearchCatalogue(searchApi)` holds `{ status: "ready" }`, then
`{ status: "found"; books: Book[] }`**, `ready` as `useAddBookToBookshelf`
names its wait for a verb. `search(text)` resolves once the answer is
held; no catch, `next` or `near` kept (T175, T173, T172 add them).
Rejected: a store (one screen reads it).

**`SearchField` is a model, the text as typed**, `defineModel<string>()`,
calling `t` for its words as `CatalogueSwitch` does; the view holds the
text and passes each change to `search`. Rejected: the words as props (no
second caller); an event of its own (T171's cross and T176's address set
the model).

**The box's place.** Shown unless the catalogue's state is `empty`
(S10: it leaves only over an empty first page), between `CatalogueSwitch`
and the rows, spaced as `1-box.jpg`.

**The observer stays the catalogue's.** Over found rows it may still ask
the catalogue's next page, hidden; the search's pages are T173's.
