## Risks and decisions
**Fit.** One run: one pin, one route on an existing controller, a use case
answering a constant, its result type, five test files touched. Rejected:
a split, since the bump reds the new operation and only the controller
greens it.

**`FindCatalogueEdition` in `library.application.catalogue`.** The answer
is "an edition of the reader's catalogue", the catalogue's `Book`, and
T112 applies the catalogue's rule beside `BrowseCatalogue` and
`FindCatalogueSeries`. The call reads `findCatalogueEdition(reader.id,
EditionId(id))`. Rejected: `FindBook` (PRD §3 avoids *book* for the
domain's edition); `FindEdition` (a read of the bibliography alone, which
this is not); `OpenEdition` (the act is the reader's, the use case finds).

**`FindCatalogueEditionResult`, `Found(held: HeldEdition)` and
`NoSuchEdition`**, as `FindCatalogueSeriesResult`: no such edition is an
outcome the controller answers. `HeldEdition` is what `BookResponse.from`
already maps, so the operation's answer reuses it whole, and the field is
`held` as `BookResponse.from(held)` names it. Rejected: a nullable answer
(the tree answers a find by a sealed result); `NoSuchOuvrage` (*ouvrage* is
the screen's word, the code's is *edition*).

**`CatalogueController.find`, not a new controller.** D02 gives
`web.catalogue` `/api/v1/books`, one controller per resource, as
`SeriesController` serves both `/api/v1/series` and its `{id}`. Rejected:
a `web.book` sub-package, which would import `BookResponse` across.

**The `Found` stub is part of step 3's green, not a guard.** The verifier
sends the generated `200` with a random id, and Mockito answers `null` to
an unstubbed call, seen as `403`: the stub is what makes that case green.
The keyed `404` then needs its own exact stub, as `findingASeriesAnswers`
pairs `Found` and `NoSuchSeries`. `Book.copies` has no `minItems`, so
`ASTERIX_1_HELD` with its one copy fills every constrained field.

**`EDITION_NOT_IN_MY_CATALOGUE` beside `NOT_IN_MY_CATALOGUE`.** The
existing fixture is the series' id and stays as it is. Rejected: renaming
it `SERIES_NOT_IN_MY_CATALOGUE`, a change this task does not need.

**Step 4 is a guard whose mutation reds both cases.** Until T112, the use
case answers `NoSuchEdition` whatever it is given, so the second S2 case
is green the moment it runs, whichever case is un-skipped first; no
mutation of this task's code tells the two apart. The guard earns its
place in T112, where the find reads copies and must leave Sam's alone.
