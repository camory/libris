## Risks and decisions
**Fit.** One run: one pin, one route on an existing controller, one
repository method, a two-line use case, seven test files touched.
Rejected: a split, since the bump reds the new operation and only the
controller greens it.

**`ListSeriesNames` in `bibliography.application.series`.** The task line
gives the read to the bibliography, and the series is its aggregate; the
sub-package follows `bibliography.domain.series`, as `cover`, `edition` and
`lookup` follow theirs. Named as `ListReaders`, the listing of a whole
house with no reader. Rejected: `library.application.catalogue` (the
catalogue is the reader's; these names are the house's); `FindSeriesNames`
(`Find` reads one in this tree, `List` reads all).

**`SeriesRepository.findAll(): List<Series>`, the names taken in the use
case.** A repository reads its aggregate (D12) and `findAll` is the verb
of `ReaderRepository` and `AwaitedCoverRepository`; the row goes through
`Series`' constructor, so a blank name could never be answered. Rejected:
a `findAllNames(): List<String>` on the port (a repository answering a
field, not its aggregate); a query port (one table, one statement).

**`ListSeriesNames` answers `List<String>`, the controller answers it as
it is.** The contract's answer is an array of strings: there is no field
to map, so no response type exists for D10's `from` to sit on, and the
controller still maps nothing. This is the *First of its kind* line.
Rejected: a `SeriesNamesResponse` wrapping the list (Jackson would write
an object, not the array the contract declares); the use case answering
`List<Series>` and the controller taking the names (a mapping in the
controller).

**The route in `SeriesController`, `web.series`.** D02 names a web
sub-package after the product word, not the path (`web.catalogue` serves
`/api/v1/books`), and the product word here is the series. Rejected: a
`web.seriesnames` sub-package with a controller of one method.

**No `distinct()`, no blank filter in the use case.** *Each once* is the
unique index on the name, *none blank* `Series`' `init` (D12: a use case
checking what the aggregate or the schema keeps has the rule in the wrong
place). T120 changes the index's expression; one row per name still holds.

**Step 6 is a guard.** Mockito answers an empty list to an unstubbed
`List` method, so the generated case is green at step 5 with `[]`, which
checks no item. The stub of two names is what makes the verifier read
the items' constraints; its mutation proves `uniqueItems` is read, which
the task line names.
