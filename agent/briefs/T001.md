# T001 — Backend skeleton

**Backlog line:** Backend skeleton. Spring Boot + Kotlin, JDK 25, Gradle Kotlin DSL
with `gradle/libs.versions.toml`; starters web, data-jdbc, flyway, actuator,
PostgreSQL driver; no Spring Security yet. Datasource from `LIBRIS_DB_*` (D08).
`V001__extensions.sql` creates `unaccent` and `pg_trgm` (D03). Packages
`domain`, `application`, `infra.web`, `infra.persistence` exist (D02).
`./gradlew check` runs all of D07: warnings as errors, detekt + formatting with
the D10 rules, JUnit 5 + Kotest assertions, the six ArchUnit rules, Kover XML.
Tests: Flyway migrated the given database and both extensions exist;
`GET /actuator/health` is UP (D09). `backend/README.md`: run, test.
**Serves:** PRD §5 (operability: health endpoint; testability); decisions D01,
D02, D03, D07, D08, D09 (health endpoint only), D10.

## Goal
When this task is done, `backend/` is a Spring Boot 4 / Kotlin application
that migrates the given PostgreSQL with Flyway, answers `GET /actuator/health`
with `UP`, and whose `./gradlew check` is the complete backend gate of D07 minus
Contracteer (no contract exists yet). It matters now because every later
backend task (T003, T005) builds on this gate and on the D02 package layout,
and the CI `backend` job starts running the moment `backend/gradlew` exists.

## Acceptance criteria
- [ ] `cd backend && ./gradlew check` exits 0 in the sandbox against the given
      database (`LIBRIS_DB_URL` points at `postgres:5432` there, not
      `localhost`, so a green run proves the datasource reads D08's variables).
- [ ] `cd backend && ./gradlew check --dry-run` lists `:detekt`, `:test` and
      `:koverXmlReport`; after a real run `backend/build/reports/kover/report.xml`
      exists.
- [ ] Warnings are errors: an unused local variable in a Kotlin source makes
      `./gradlew compileKotlin` fail. Verified once with a throwaway edit, then
      reverted; the PR body says so.
- [ ] detekt enforces D10 on production code: a `!!`, a `lateinit var` in
      `src/main`, and a formatting violation (a wrongly indented line) each make
      `./gradlew detekt` fail. Same throwaway-and-revert verification, stated in
      the PR body.
- [ ] `backend/src/main/resources/db/migration/V001__extensions.sql` creates the
      `unaccent` and `pg_trgm` extensions with `IF NOT EXISTS`.
- [ ] `FlywayMigrationIT` (Spring-level, rolled-back transaction) proves that
      `pg_extension` contains both `unaccent` and `pg_trgm` and that
      `flyway_schema_history` has a row with `script = 'V001__extensions.sql'`
      and `success = true`.
- [ ] `ActuatorHealthIT` (random port) proves `GET /actuator/health` answers
      200 with JSON `status` equal to `UP`.
- [ ] `ArchitectureTest` holds exactly six `@ArchTest` rules, one per D02 rule,
      in D02's order, each described with the rule's number and sentence.
- [ ] The directories `backend/src/main/kotlin/fr/amory/libris/{domain,application,infra/web,infra/persistence}`
      exist and are tracked by git.
- [ ] `backend/gradle/libs.versions.toml` pins every plugin and every library
      that is not managed by the Spring Boot BOM to an exact version (D10).
- [ ] `cd backend && ./gradlew dependencies --configuration runtimeClasspath | grep -c spring-security`
      prints 0: no Spring Security yet.
- [ ] `backend/README.md` states how to run (`bootRun` against the compose
      database of `docs/ARCHITECTURE.md` "Local development"), how to test
      (`./gradlew check` and what it runs), the three `LIBRIS_DB_*` variables
      with their defaults, and where the detekt and Kover reports land.
- [ ] `./gradlew check --no-daemon` also passes in the CI `backend` job of the
      pull request (JDK 25, PostgreSQL 18-alpine, `localhost:5432`).

## Test plan
All tests live in `backend/src/test/kotlin/fr/amory/libris/`, one `test` task
(no separate integration source set yet, see Risks). JUnit 5 is the runner,
Kotest `kotest-assertions-core` the assertion library (`shouldBe`,
`shouldContainAll`), nothing else from Kotest. Database-backed classes carry
the `IT` suffix. Write them in this order, each failing before its
implementation:

1. `ArchitectureTest` (`@AnalyzeClasses(packages = ["fr.amory.libris"],
   importOptions = [ImportOption.DoNotIncludeTests::class])`), six `@ArchTest`
   fields:
   1. `classes().that().resideInAPackage("..domain..")` only depend on classes
      in `java..`, `kotlin..`, `..domain..`,
      `org.springframework.data.annotation..`,
      `org.springframework.data.relational.core.mapping..`.
   2. `classes().that().resideInAPackage("..application..")` only depend on
      `java..`, `kotlin..`, `..domain..`, `..application..`,
      `org.springframework.stereotype.Service`,
      `org.springframework.transaction.annotation..`.
   3. `slices().matching("fr.amory.libris.infra.(*)..").should().notDependOnEachOther()`.
   4. `slices().matching("fr.amory.libris.(*)..").should().beFreeOfCycles()`.
   5. No class outside `..infra..` and `..domain..` implements an interface
      declared in `..domain..` (`noClasses().that().resideOutsideOfPackages("..infra..", "..domain..").should().implement(resideInAPackage("..domain.."))`).
   6. No class calls `save` on a `CrudRepository`, including through a
      sub-interface: `noClasses().should().callMethodWhere(target(name("save")).and(target(owner(assignableTo(CrudRepository::class.java)))))`.
   It proves the rules compile and run; with only `LibrisApplication` on the
   classpath they pass because `archunit.properties` sets
   `archRule.failOnEmptyShould=false` (see Risks). Spot-check rule 6 once with a
   throwaway class that calls `save` on a `CrudRepository` subtype: it must fail.
2. `FlywayMigrationIT`: `@SpringBootTest` + `@Transactional`, injects
   `JdbcClient`, queries `pg_extension` and `flyway_schema_history` as stated in
   the criteria. Fails while there is no datasource, no Flyway, no V001.
3. `ActuatorHealthIT`: `@SpringBootTest(webEnvironment = RANDOM_PORT)`,
   `@LocalServerPort` and `TestRestTemplate` (or `RestTestClient`) from
   `spring-boot-starter-web-server-test`, asserts status 200 and body
   `status == "UP"`. Fails until the actuator starter is on the classpath.

Green means `cd backend && ./gradlew check`, run plainly as the last thing in
its command so the sandbox records it (see `agent/prompts/implementer.md`).
Paste the test summary lines and the detekt/Kover task lines in the PR body.

## Risks and decisions
- **No Gradle in the sandbox.** Decision: bootstrap the wrapper from the
  official 9.7.1 distribution (current stable as of 2026-09-07, the download
  redirects to GitHub, which the sandbox can reach), then use only `./gradlew`.
- **Spring Boot 4.1.1** is the latest GA (4.2 is at milestone 1). Boot 4 split
  its starters: the web starter is `spring-boot-starter-webmvc`, Flyway has its
  own `spring-boot-starter-flyway`, and `@LocalServerPort` / `TestRestTemplate`
  come from `spring-boot-starter-web-server-test`, not from
  `spring-boot-starter-test`. Boot 4 uses Jackson 3 (`tools.jackson`), hence
  `tools.jackson.module:jackson-module-kotlin`. Decision: these names; all are
  Boot-managed artifacts, not new dependency categories.
- **Kotlin 2.3.21 rather than the newest 2.4.20.** Decision: pin the version
  Boot 4.1.1 manages, so the Gradle plugin and the stdlib the BOM resolves
  agree; it supports JVM target 25 (checked in the compiler's `JvmTarget`).
  Upgrading Kotlin is its own task (D10).
- **Versions managed by the Boot BOM** (Flyway 12.4.0, PostgreSQL driver
  42.7.13, JUnit Jupiter 6.0.3, Jackson 3.1.5) are not repeated in the
  catalog: one source of truth, and Boot tests them together. Decision: BOM
  through `platform()`, no dependency-management plugin.
- **detekt 1.23.8 on Gradle 9.7.1.** 1.23.8 is the only GA line (2.0 is
  pre-release). If its Gradle plugin fails to apply on Gradle 9.7, pin the
  wrapper to the newest Gradle 8.14.x instead and say so under *Deviations*;
  do not use a detekt pre-release. Gradle deprecation warnings from plugins are
  not compiler warnings and do not fail the build.
- **Flyway 12.4.0 with PostgreSQL 18.** A "newer than tested" warning is
  acceptable; an outright refusal blocks the task (report `blocked`, do not
  override the Boot-managed version silently).
- **ArchUnit fails empty rules by default** (`failOnEmptyShould` is true since
  1.0). Production code in T001 is `LibrisApplication` only. Decision:
  `archRule.failOnEmptyShould=false` in `src/test/resources/archunit.properties`
  with a comment; T005 fills the packages. The D02 packages are `.gitkeep`
  directories, since a Kotlin package exists only through a class and no
  class is justified yet.
- **D10 says detekt enforces "sealed types for states" and "constructor
  injection".** detekt has no rule for either. Decision: enforce what detekt
  can (`!!`, `lateinit`, `var` that could be `val`, formatting) and state the
  gap in the PR body under *Follow-ups* so Tophe can amend D10 or ask for an
  ArchUnit rule later. Do not edit `docs/ARCHITECTURE.md`.
- **Formatting style.** ktlint's default `ktlint_official` style differs from
  the Kotlin coding conventions that `kotlin.code.style=official` selects.
  Decision: `ktlint_code_style = intellij_idea` in `.editorconfig`, the ktlint
  name for the official Kotlin conventions, so the IDE and detekt agree.
- **One `test` task.** D07 distinguishes unit and integration tests by what
  they need, not by source set; the database is always given (D08). Decision:
  one source set, `IT` suffix on database-backed classes, nothing more until a
  task needs a split.
- **Shared database.** Tests migrate and never drop (D08). The sandbox
  database may already carry `flyway_schema_history` from an earlier run; V001
  is idempotent (`IF NOT EXISTS`) and must keep its first content, or Flyway's
  validation fails on the checksum. If that happens because you edited V001
  after a run, restore the first content and write the gotcha in
  `agent/PROGRESS.md`.
- **Health details.** Boot exposes `health` over HTTP by default and hides
  details; `{"status":"UP"}` is enough for T001. `info` is exposed in T003.
