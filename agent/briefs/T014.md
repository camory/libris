# T014 — The merge rule and several sources

**Backlog line:** Backend: the merge rule and several sources. The domain rule
of S5, tested field by field: the first source's value wins for every field it
gives, the next fills the fields it leaves empty, the cover stays Open
Library's by ISBN, and `sources` lists the ones that answered (D02). The use
case asks every source in turn and keeps what the ones that replied know; it
never sees time, a late source being a failed one by the port's contract
(D02); it still answers not-found when none knows and sources-unavailable when
none replies. Tested over two fakes: both answering, one failing, both
failing. No new source and no contract edit. Realises the rule S5 and S6
assert; un-skips nothing, both go green with T015.

**Serves:** spec `fast-entry` — the rule S5 and the two S6 cases assert, whose
scenario methods stay skipped until T015 brings the BnF; the *Contract*
section of that spec is untouched. PRD §4.7 (sources arrive one at a time,
each degrading gracefully when it fails or knows nothing; the cover by ISBN
from Open Library) and §3 (Edition, Series, Volume number, Collection, Author,
Role). Decisions D02 (the layers, the framework-free domain, the use case
never sees time), D04 (no contract edit: the pin stays `v0.3.0`), D07 (the
gate, the slices, the scenario tests are Tophe's), D08 (nothing is added to
the environment), D10 (Kotlin and commit conventions), D11 (the ISBN-13 as
thirteen digits, absent optional values serialised as `null`).

**First of its kind:** the first domain rule written as a function rather than
a type — `merge` in `domain.lookup`, and with it the first file of the domain
named after a rule instead of a type; the first port injected as a list of its
implementations; and the first shared fixture builder with defaults
(`fixture/SourceEditions.kt`), which the merge tests need to vary one field at
a time.

## Goal
When this task is done the answer of `GET /api/v1/isbn/{isbn}` is what several
sources know together: a domain rule merges the editions the sources that
replied gave, in the order they were asked, and the use case asks all of them
instead of one. It matters now because it is the whole of S5 and S6 except the
second source: T015 adds the BnF client, ranks it first, and the four skipped
scenario methods go green without another rule being written.

## Rules in play
- **D02** — the merge is a domain rule: it lives in `domain.lookup`, is
  framework-free, and depends on nothing but the Kotlin standard library and
  the types already in that package. The use case stays in `application`,
  depends on `domain` only, carries `@Service` and nothing else of Spring, and
  **never sees time**: a source that answered too late is `Failed` by the
  port's contract, which the adapter alone enforces. The five ArchUnit rules
  stay as they are and stay green.
- **D04** — no contract edit of any kind: `ApiContractTest` keeps its
  `v0.3.0` pin, the document is not consulted for a change, and the response
  shape does not move. If the merge cannot produce what the released document
  declares, report `blocked` with the question rather than bend either side.
- **D07** — `cd backend && ./gradlew check` is the gate and must be run
  plainly (not piped, not chained, one gate per command, or the sandbox
  records nothing); the domain rule is plain JUnit with Kotest assertions and
  no doubles, the use case plain JUnit over fakes of its port; shared test
  doubles and builders live in the `fixture` package; tests live beside the
  code they exercise and are named after it; test bodies are laid out
  Given / When / Then unless a single statement; a test written to learn a
  library is deleted before the pull request.
- **D07 (scenarios)** — this task un-skips nothing. Nothing under
  `backend/src/test/kotlin/fr/amory/libris/scenario/` changes, neither a body
  nor a `@Disabled` line, and nothing under
  `backend/src/test/resources/scenarios/` changes either.
- **D08** — nothing is added to the environment: no dependency, no property,
  no variable, no service. The two source variables keep their defaults.
- **D10** — Kotlin official style, immutable by default, constructor
  injection, no `!!`, no `lateinit`; a member is imported, not qualified, when
  its bare name is unambiguous; commits `feat(backend): …` on branch
  `task/T014-merge-rule`; no `D##`, no `U##` and no rationale in code, tests or
  configuration.
- **D11** — the merged answer carries the asked ISBN-13 as its thirteen
  digits, and a field no source gave stays `null` (the controller already
  serialises it as `null`, and nothing in `infra.web` changes here).
- **docs/DESIGN.md** — none: U01…U08 are screen rules and this task has no
  frontend side.

## Risks and decisions
- **Where the rule lives and what it is called.** Decided: a top-level
  function `merge` in `domain/lookup/Merge.kt`, taking the asked `Isbn13` and
  the editions in the order they were asked, answering one `SourceEdition`.
  The domain has held only types so far, so this is flagged as first of its
  kind: a rule that is a function needs no state and inventing a
  `MergedEdition` type would duplicate `SourceEdition` field for field, since
  the merged answer is exactly what the use case already puts in `Found`.
- **The merge of an empty list is not a case.** Decided: `merge` is called
  only with at least one edition; when no source knew, the use case answers
  `UnknownIsbn` or `SourcesUnavailable` and never calls it. The rule may read
  its first element directly; do not add a nullable answer or a default
  edition for a call that cannot happen.
- **What "empty" means for a field.** Decided: `null` for every nullable
  field, and an empty list for `authors`. No blank-string check, no trimming:
  a source that answers `""` for a subtitle has given a subtitle, and no
  scenario says otherwise. Deciding differently would be a rule about what a
  source may answer, which belongs to the source's task, not to the merge.
- **`authors` and `series` are whole values.** Decided: the rule works field
  by field on `SourceEdition` and does not descend into `SourceSeries` or into
  an author. A list of authors from two sources cannot be concatenated without
  a rule saying which duplicates to drop, and no document gives one; taking
  the first non-empty list is what S5 needs (the BnF gives the roles, Open
  Library gives `WRITER` for everyone) and what the reader reads as coherent.
  If this ever shows wrong on a real record it is a spec conversation.
- **The cover does not follow the rule.** Decided, and it is the reason the
  rule takes the ISBN: `S6 One source down, past the timeout` expects
  `https://covers.openlibrary.org/b/isbn/9782723488525-L.jpg` while only the
  BnF replied, so the cover cannot be a field of a source's answer being
  merged; it is derived from the asked ISBN, always, by the same rule that
  merges. The address therefore moves into the domain, where S5's "Open
  Library's cover by ISBN" is a product rule, and `OpenLibrarySource` calls
  that one function instead of keeping a second copy of the string: its
  answer, its test and its recorded files are unchanged.
- **What `sources` lists.** Decided: the sources whose knowledge is in the
  answer, that is those that answered `Known`, in the order they were asked. A
  source that replied "I know nothing" contributed no field and is not listed;
  the screen shows the list as the provenance of what it displays (the *Sources*
  chips of the spec's card). No scenario tells the two readings apart — S5 has
  both sources knowing, both S6 cases have one source down — so this is the
  planner's decision, not the implementer's, and it is reversible in one line.
- **Not-found or unavailable when the sources disagree.** Decided:
  `SourcesUnavailable` only when every source failed; as soon as one source
  replied and none knew, the answer is `UnknownIsbn` — including one failing
  while the other knows nothing. The backlog line reads "not-found when none
  knows and sources-unavailable when none replies", and telling the reader
  "try again later" when a source did reply that it knows nothing would be
  wrong. `IsbnLookupTest` pins all three cases.
- **The port injected as a list.** Decided: `IsbnLookup(private val sources:
  List<IsbnSource>)`, which Spring fills with every `IsbnSource` bean — one
  today. No qualifier, no `ObjectProvider`, no configuration change; the boot
  test already reads the list of sources and proves the wiring. Mockito's
  `@MockitoBean` of `IsbnLookup` in the web slice and the contract test is
  unaffected: they mock the use case, not its sources.
- **The three tests T020 wrote.** They exercise one source, which is now a
  list of one; rewriting them over two fakes as the test plan says is
  deliberate, not collateral: each new case still proves the mapping of one
  port answer, and the two-fake cases are what the backlog line asks for.
- **The fixture builder.** Decided: `fixture/SourceEditions.kt`, one function
  with every parameter defaulted, following `Isbn13s.kt`'s shape and naming.
  The T020 review deferred it here because the merge tests are the first that
  must vary one field at a time; `ApiContractTest` keeps its own `ONE_PIECE_1`
  literal, which names the document's example and must stay readable as such.
- **Nothing here needs the contract.** The merged edition fills the same
  response as one source's did, so `v0.3.0` is satisfied unchanged. If the
  merge is found to need a field the document does not declare — it should
  not — that is a contract conversation with Tophe: report `blocked` (D04).
