## Goal
The backend pins `v0.16.0`: every copy it answers names its bookshelf as a
`ReaderBookshelf`, with the reader's role on it read from the bookshelf's
memberships, and `DELETE /api/v1/copies/{id}` is served through a use case
that answers no such copy to any reader, so the three cases of S3 hold.
T131 removes the copy behind the same use case, result and controller.

## Rules in play
- D04 — the pin moves from `v0.15.0` to `v0.16.0` and nothing else of the contract changes.
- D07 — the pin bump is the first red; the role is tested in the use cases that compute it; the three S3 methods are un-skipped, never edited; no web test.
- D02 — `/api/v1/copies/{id}` is served from `web.copy` by `CopyController`, through a use case, never a repository.
- D10 — `RemoveCopy` is named by its sentence, `operator fun invoke` its one public member, held in a variable of its name.
- D10 — responses map themselves with `from`; the controller maps nothing; `when` arrows aligned; no `!!`; no rationale or `D##` in code.
- D10 — `ReaderBookshelf` gains `of` on its companion, decided here; `ListReaderBookshelves`' private helper is removed, not widened.
- D11 — no such copy is a result the controller answers `404` `/problems/not-found`; an id that is not a uuid is `ProblemAdvice`'s `400`.
- D12 — the role comes from `Bookshelf.roleOf`; the read model stays a data class of `application`; `of` answers null for a non-member.

## Risks and decisions
**Fit.** One run: one pin, one route, a use case answering a constant, its
result, one read-model shape change felt by four reads and the add. Rejected:
a split, since the bump reds the removal and every copy's schema at once,
and neither half turns the contract test green alone.

**`CopyOnBookshelf(copyId, bookshelf: ReaderBookshelf)`.** The contract's
`Copy.bookshelf` is now `ReaderBookshelf`, and `application` already has
the data class that mirrors it, answered by the bookshelves list with its
`ReaderBookshelfResponse`; the copy reuses both.
Rejected: a fourth field `role` beside `bookshelfId` and `bookshelfName`, a second shape of the same thing.

**`ReaderBookshelf.of(bookshelf, readerId)`, null for a non-member.** Five
use cases need the reader's view of a bookshelf, and `ListReaderBookshelves`
computes it in a private helper; the companion `of` holds it once, in the
form D12 gives `of`, and the helper goes.
Rejected: widening `ListReaderBookshelves`' helper (D10).
Rejected: a method on `Bookshelf`, which would name an `application` type from the domain.

**The three other reads are guards, not red steps.** `CopyOnBookshelf` is
one type: the first step that changes it must fix every caller and every
expectation, so the other cases cannot be red apart. Each is kept as a
guard whose mutation (a fixed `OWNER`) turns it red on the Salon.
Rejected: one red step per read with a temporary role, code written only to be replaced.

**The web answers change in step 4, not step 3.** `CopyResponse` serves
both the reads and the add, and the add has no role before step 4; step 3
keeps the web shape, so each commit compiles and step 4 turns every
`Copy` case green at once.

**`Added(copy: CopyOnBookshelf)`.** The add's `201` is a `Copy`, the very
shape the reads answer, so `CopyResponse.from(copy)` is the one mapping.
The role is read from the memberships, though only an owner adds, as the
line asks. Rejected: keeping `Added(copy, bookshelf)` and a second `from`.

**`RemoveCopy` in `library.application`, beside `AddBookToBookshelf`.** It
acts on a copy of a bookshelf, as the add does. The call reads
`removeCopy(reader.id, CopyId(id))`. Rejected: `DeleteCopy` (the PRD's word
is remove); a `copy` sub-package for one use case.

**`RemoveCopyResult` with `Removed` now.** The controller answers `204` on
it and the contract's `204` stub needs it, though `RemoveCopy` answers
`NoSuchCopy` until T131. Rejected: a nullable or `Boolean` answer — the
tree answers outcomes by sealed results (D11).

**`web.copy`.** `/api/v1/copies/{id}` is a resource of its own, and the
tree has one sub-package per resource. Rejected: `BookshelfController`,
whose paths sit below `/api/v1/bookshelves`.
