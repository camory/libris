# T005 — Backend authentication

**Backlog line:** Backend authentication. Precondition (human): `GET /api/v1/me`
in `api/openapi.yaml` (D04). Spring Security pre-authenticated header filter on
`Remote-User/Groups/Name/Email`; `ADMIN` when in `libris-admin`, `MEMBER`
otherwise; `GET /api/v1/me` answers the username, display name, email and role
read from the headers, nothing stored and no datasource; non-GET refused
without `X-Requested-With` (D06); `dev` profile trusts the headers,
`contract-test` profile authenticates a fixed member; Contracteer
verifier-junit (D04). Tests: filter, role, refusal, contract. The D02 ArchUnit
rules that these classes give something to check arrive here, the rest with
T006.
**Serves:** PRD §2 (Admin and Member), §4.10 (accounts live in Authelia), §5
(privacy: every request passes through Authelia); decisions D02, D04, D06, D07,
D10, D11.

Precondition checked: `GET /api/v1/me` is in `api/openapi.yaml` since PR #22 —
OpenAPI 3.0.3, one operation, one response, and the closed schema
`CurrentMember` requiring `username`, `displayName`, `email` (`format: email`)
and `role` (`MEMBER` or `ADMIN`), all non-nullable, the two names with
`minLength: 1`. The document must not change in this task (D04: edited with
Tophe, never by a headless run).

## Goal
When this task is done the backend knows who is calling: Traefik's Authelia
headers become an authenticated member with a role, `GET /api/v1/me` answers
what the contract describes, everything else under `/api` is refused without
those headers, and the answer is verified against `api/openapi.yaml` inside
`./gradlew check`. It matters now because T006 hangs the member profile on that
identity and T007's home view greets the member by name; and because this is
the run that turns Contracteer verification and the ArchUnit rules from
documents into part of the gate.

Read `agent/PROGRESS.md`'s T003 and "T005 preparation" entries first. Three
things carry over: the gate is recorded, so keep `cd backend && ./gradlew check`
plain and last in its command; there is no `@AutoConfigureMockMvc` in Spring
Boot 4.1.1, the HTTP test client is `RestTestClient`; and a Spring test class
needs `@Autowired` on its constructor (D10).

class RemoteHeaderAuthenticationFilter : AbstractPreAuthenticatedProcessingFilter() {
    override fun getPreAuthenticatedPrincipal(request: HttpServletRequest): Any? {
        val username = request.getHeader("Remote-User") ?: return null
        val groups = request.getHeader("Remote-Groups").orEmpty().split(",").map { it.trim() }
        return Member(username, request.getHeader("Remote-Name") ?: username, …)
    }

    override fun getPreAuthenticatedCredentials(request: HttpServletRequest): Any = "N/A"
}

class MemberPrincipal(val member: Member) : UserDetails {
    override fun getAuthorities(): Collection<GrantedAuthority> =
        listOf(SimpleGrantedAuthority("ROLE_${member.role}"))
    override fun getPassword(): String? = null
    override fun getUsername(): String = member.username
}

@Bean
fun authenticationManager(): AuthenticationManager {
    val provider = PreAuthenticatedAuthenticationProvider()
    provider.setPreAuthenticatedUserDetailsService { token -> MemberPrincipal(token.principal as Member) }
    return ProviderManager(provider)
}

@Bean
fun filterChain(http: HttpSecurity, authenticationManager: AuthenticationManager): SecurityFilterChain {
    val filter = RemoteHeaderAuthenticationFilter()
    filter.setAuthenticationManager(authenticationManager)
    val unsafeWrite = RequestMatcher { it.method != HttpMethod.GET.name() && it.getHeader("X-Requested-With") == null }
    return http
        .csrf { it.disable() }
        .sessionManagement { it.sessionCreationPolicy(SessionCreationPolicy.STATELESS) }
        .addFilterBefore(filter, AbstractPreAuthenticatedProcessingFilter::class.java)
        .authorizeHttpRequests {
            it.requestMatchers("/actuator/**").permitAll()
            it.requestMatchers(unsafeWrite).denyAll()
            it.anyRequest().authenticated()
        }
        .build()
}

}

## Risks and decisions
Everything below marked *measured* was run in a throwaway copy of `backend/` on
2026-09-08; nothing was left in the repository.

- **Dependencies.** *Measured*: these four, and no more, make the four test
  classes compile and pass —
  `implementation("org.springframework.boot:spring-boot-starter-security")`,
  `testImplementation("org.springframework.boot:spring-boot-starter-test")`,
  `testImplementation("org.springframework.boot:spring-boot-resttestclient")`,
  plus `dev.contracteer:contracteer-verifier-junit:4.0.0` and
  `com.tngtech.archunit:archunit-junit5:1.5.0`. The two Spring ones are
  BOM-managed and take no catalog entry (T003 precedent); Contracteer and
  ArchUnit are pinned in `gradle/libs.versions.toml` (D10). `spring-security-test`
  is **not** needed — the tests set real headers — and an unused dependency is
  what the reviewer blocked on in T003. Latest versions checked on Maven Central
  on 2026-09-08: contracteer 4.0.0 (the CLI in the sandbox is the same), archunit
  1.5.0.
- **Contracteer under JUnit 6.** `contracteer-verifier-junit:4.0.0` declares
  `junit-jupiter-engine:5.14.2`; the Spring Boot 4.1.1 BOM raises it to 6.0.3.
  *Measured*: the extension runs and reports its case normally under 6.0.3. No
  pinning, no exclusion, no `resolutionStrategy` is needed — do not add one.
- **Where the contract document is read from.** `@ContracteerTest(openApiDoc =
  "../api/openapi.yaml")`: the test JVM's working directory is `backend/`, and
  CI runs the gate from `backend/` too. *Measured*: it resolves. Rejected:
  copying the document into `src/test/resources`, which would give the backend
  its own drifting copy of the single source of truth (D04).
- **The `contract-test` profile authenticates a fixed member from test
  sources.** Contracteer generates the request from the contract, and the
  contract declares no security scheme (D06), so the generated `GET /api/v1/me`
  carries no `Remote-*` header and the chain refuses it. Decision: a nested
  `@TestConfiguration` in `ApiContractTest`, annotated `@Profile("contract-test")`
  and activated by `@ActiveProfiles("contract-test")` on the class, registers a
  servlet `Filter` at `Ordered.HIGHEST_PRECEDENCE` that wraps the request with
  the four headers of a fixed member. The production security chain is exercised
  unchanged and main sources gain no test-only bean. *Measured*: with the
  wrapper the case passes; without it the case fails on the 403, which is the
  throwaway check of the acceptance criteria.
- **No `application-dev.yaml`.** D06 says the `dev` profile trusts the headers
  the Vite proxy adds; *measured*: the default chain already trusts them, in
  every profile, because that is what D06's trust boundary asks for — in
  production the backend publishes no port and only Traefik can reach it. A
  profile file that sets nothing is configuration no test exercises
  (`CLAUDE.md`). Decision: no `dev` profile file in this task; say so in the PR
  body so Tophe can decide whether D06's sentence should be reworded. The
  profile becomes real the day dev must differ from production.
- **Which headers are required.** Decision, from the contract's schema:
  `Remote-User` identifies the member and its absence means unauthenticated
  (403); `Remote-Email` is required too, because `email` is required with
  `format: email` and no fallback is a valid address; `Remote-Name` is optional
  and falls back to the username, which satisfies `minLength: 1`;
  `Remote-Groups` is optional and its absence means `MEMBER`. Authelia sends all
  four (D06), so a refusal here means a misconfigured proxy, and a blanket 403
  is the visible failure. *Measured*: with only `Remote-User` the request is
  authenticated and `email` comes back empty — which is why the blank-email
  refusal is a criterion rather than an accident.
- **403 and not 401 for a refusal, with Spring Security's default body.** The
  contract declares no error response for `/me` and no frontend consumes one
  yet; D06 puts authentication upstream, so a 401 from Libris would mean nothing
  to Authelia. The shape of an error body is decided by the first operation in
  the contract that declares one.
- **`denyAll` before `anyRequest().authenticated()`.** The `X-Requested-With`
  rule is a `RequestMatcher` in the authorization chain, matched before the
  catch-all; order is what makes it work. *Measured*: without the header a POST
  is 403, with it the same POST reaches the dispatcher and is 405.
- **CSRF is disabled on purpose.** Spring Security's token CSRF protection
  would refuse every non-GET before the `X-Requested-With` rule is reached, and
  D06 replaces it with that header plus Authelia's SameSite cookie. Say it in
  the PR body; it is the kind of line a reviewer must not have to guess.
- **The authenticated principal is what the user-details service returns, not
  what the filter extracted.** `PreAuthenticatedAuthenticationProvider` replaces
  the token's principal, so the display name and email survive only if the
  `UserDetails` carries the `Member`. Hence `MemberPrincipal`. *Measured*: with
  a plain `User` the controller cannot answer the contract.
- **detekt, *measured* on the spike's own sources.** Two findings that the
  shapes above avoid, and that will come back if they are written differently:
  `EmptyFunctionBlock` on the `@ContracteerTest` method — a comment inside the
  block satisfies the rule, and `// nothing to seed` is a *what*, not a *why*
  (`CLAUDE.md`); `UnusedPrivateProperty` on the injected port, since Contracteer
  reads the field reflectively — declare it non-private rather than suppressing
  the rule. No `@Suppress` is needed anywhere in this task.
- **ArchUnit rule 1 must allow `org.jetbrains.annotations`.** *Measured*: the
  Kotlin compiler annotates a data class's members with
  `org.jetbrains.annotations.NotNull`, so
  `resideOutsideOfPackages("java..", "kotlin..", "..domain..")` fails with
  twenty violations on `Member` alone. Allow `org.jetbrains.annotations..` as
  part of "the Kotlin standard libraries"; note it in the PR body as the
  literal wording D02 implies. The Spring Data mapping annotations D02 also
  allows are not in the list yet: no `domain` class uses one until T006.
- **Only two of the six D02 rules ship here**, as the backlog line says: rule 1
  (`domain` depends on nothing else) and rule 4 (no cycles). Rules 2, 3, 5 and 6
  need an `application` package, a second `infra` package, ports and
  repositories — all T006. Do not write a rule with nothing to check; an
  ArchUnit rule that no class can violate passes forever and hides its own
  removal.
- **Test class names.** D07 names test classes after the Libris code they
  exercise and forbids a suffix that sorts tests by what they need. Decision:
  `MeControllerTest`, `SecurityConfigTest`, `ApiContractTest`,
  `ArchitectureTest` — the first two after their class, the last two after what
  they exercise (the API against its contract, the package structure), all with
  the `Test` suffix JUnit and Gradle default to. T003's brief proposed the same
  sentence for D07 and the class that carried it was removed before merge:
  propose it again in the PR body, since these four are the backend's first
  test classes.
- **`allWarningsAsErrors` covers the test sources.** A deprecated Spring
  Security API fails the build rather than warning. *Measured*: the shapes above
  compile clean on Spring Security 7.1.1 — `csrf { it.disable() }`,
  `ProviderManager`, `PreAuthenticatedAuthenticationProvider` and
  `AbstractPreAuthenticatedProcessingFilter` are all current.
- **Class locations that changed in Spring Boot 4.1.1**, *measured*, so nobody
  hunts for them: `org.springframework.boot.test.web.server.LocalServerPort`,
  `org.springframework.boot.resttestclient.autoconfigure.AutoConfigureRestTestClient`,
  `org.springframework.test.web.servlet.client.RestTestClient`.
- **Kover.** Coverage has no threshold (D07); `check` still runs
  `koverXmlReport` and must stay green.
- **The `images` job runs on this PR** and needs both test jobs green. Nothing
  in this task changes a Dockerfile, but a red gate means no image build at all.
