**Serves:** spec `catalogue` S1 (its order; the rest of S1 is T043's); PRD
§3 (*Edition*, *Series*, *Volume number*), §4.1 (*series and volume*);
decisions D02, D07, D10, D12
**First of its kind:** the first order an aggregate declares over its own
values, a `Comparator` on `Edition`'s companion that a use case applies; the
first text comparison of the domain that ignores accents.

## Goal
`GET /api/v1/books` answers the reader's editions in the order a shelf
reads, and `S1 The catalogue lists the house's editions` passes end to end.
The frontend of T047 lists the rows in the order of the answer and sorts
nothing, so the order is the backend's to give now; T045 makes it total and
pages it.

## Rules in play
- D12 — the order is a rule over the edition's values, so `Edition` declares
  it; `BrowseCatalogue` applies it and holds no key of its own; `HeldEdition`
  stays a data class with no rule.
- D02 — the order lives in `bibliography.domain.edition`, framework-free:
  the JDK alone (`java.text` is under the allowed `java..`), no new
  dependency; `library` reads it, `bibliography` knows nothing of the
  catalogue.
- D07 — the values of the order are proven by the domain's unit test and the
  use case's test over the fakes, no JDBC slice; `S1 The catalogue lists the
  house's editions` is un-skipped and nothing else of `CatalogueScenarios`
  changes; no hand-written web test, the contract is untouched.
- D10 — the words of PRD §3: no `shelf` in any name (the PRD avoids it for
  *Bookshelf*), `volume` never alone; the member is imported where it is
  used, not qualified, since its bare name says what it is; no visibility
  widens.

## Test plan
One step is one case is one commit; `./gradlew detekt` before each commit.
Each `EditionTest` case gives the editions in the order the rule refutes and
asserts the whole sorted list of titles (or of editions) with `shouldBe`, so
a comparator that ties keeps the input order and the case is red. The cases
build editions through the class's `edition(...)` helper, which gains the
parameters a case needs (`series`), its other values fixed.

0. **The outer red.** Remove `@Disabled("T044")` from S1 and run `./gradlew
   test --tests '*CatalogueScenarios'`: read the red on `$.books[*].title`.
   A red on anything else (the copies, `next`, the add) is not this task's
   to fix: stop and report `blocked` with the failure. Leave the file
   modified, uncommitted, until step 8.
1. **red then green — series name, or title.** `Tintin` tome 1 *Les cigares
   du pharaon*, then *Pierre et le loup* without a series: *Pierre et le
   loup* comes first, since the key of the Tintin is its series. Title order
   alone would answer the reverse. Creates the comparator on `Edition`'s
   companion.
2. **red then green — case.** `Naruto` tome 1, then *maus* without a series:
   *maus* comes first. A case-sensitive comparison puts `N` before `m`.
3. **red then green — accents.** `Fables` tome 1, then *Émile et les
   détectives* without a series: *Émile* comes first. A comparison that
   ignores case only puts `é` after `f`. If step 2's green already ignores
   accents (a `Collator` at primary strength does both), this step is a
   **guard**: mutation, compare the lowercase text without removing accents;
   red on *Fables* first.
4. **red then green — tome as a number.** `One piece` tome 10, then tome 2:
   tome 2 first. Before this step the two tie on the series and keep the
   input order.
5. **red then green — no tome last.** `Astérix` without a tome, then
   `Astérix` tome 1: tome 1 first. Kotlin's `compareBy` puts a `null` key
   first, so step 4's green is red here.
6. **red then green — then by title.** `One piece` tome 1 *Romance dawn*,
   then `One piece` tome 1 *À l'aube d'une grande aventure*: *À l'aube*
   first. A title compared as plain text puts `À` after `R`: the tie-break
   compares titles as the first key does.
7. **red then green — the use case applies it.** `BrowseCatalogueTest`:
   Léa's bookshelf holds a copy of `BAGGY` (One piece 2) inserted before a
   copy of `ROMANCE_DAWN` (One piece 1); her catalogue is `ROMANCE_DAWN`
   then `BAGGY`, asserted as `held.map { it.edition }`. Red while the answer
   follows the copies. The two existing cases stay as they are.
8. **green — the scenario.** Run S1 again, green; commit the removed
   `@Disabled("T044")` alone.
9. **Tidy on green**, the gate run plainly, then the documents: the task line
   ticked, a `PROGRESS.md` entry, `GOTCHAS.md` if a tool's behaviour cost a
   cycle, then the pull request.

**Not to be written:** a JDBC slice case, an `ORDER BY`, a migration or an
index (the order is not the database's, see *Risks and decisions*); a case
on two editions equal on every key (T045 makes the order total with the
id); a web-slice test; any edit of S1 but its `@Disabled`, or of S2.

## Risks and decisions
**The order is `Edition`'s, applied by the use case, not the query's.** The
backlog line, written before T043's review, says *ordered in the one query*
and *tests against PostgreSQL*. That review (Tophe, 2026-09-27, in
`PROGRESS.md` and the T043 PR) removed the one query: `BrowseCatalogue`
reads three repositories, and *the order of a shelf is a rule over the
edition's values* that `BrowseCatalogue` applies, adding no domain concept.
The spec's proof line for S1 asks a *unit test of the order*. So the rule
sits on the aggregate that holds the values (D12) as a comparator, and the
use case sorts with it. This brief supersedes the line on those two points;
the line's cases (case, accents, tome, missing tome, title) stand as unit
cases. *Rejected:* an `ORDER BY` in `EditionRepository.findByIds` — a
repository answering a listing order is the query the review removed, and
PostgreSQL's collation would decide the accents. *Rejected:* the keys in
`BrowseCatalogue` — the use case would hold a rule the aggregate can answer.

**A comparator on the companion, not a new type.** `Edition` is not made
`Comparable`: a data class whose `compareTo` answers 0 for two editions it
does not find `equal` breaks the contract sorted collections rely on, and
the PRD names other orders to come (title, added date). *Rejected:* a type
`EditionOrder` in the domain — a concept with no invariant, what the review
refused.

**The name `BY_SERIES_AND_VOLUME`.** PRD §4.1 names this sort *series and
volume*; *shelf* is on the PRD's avoid list, so *the order of a shelf* stays
the spec's phrase and never a name. Upper snake, a fixed value of the
companion, read imported as `sortedWith(BY_SERIES_AND_VOLUME)`. *Rejected:* `SHELF_ORDER` — the avoided word.

**Titles are compared as the first key is, ignoring case and accents.** The
spec says *then by title* after the rule on the first key; a title tie-break
that noticed accents would put *À l'aube* after *Romance dawn* while the
first key puts *Émile* before *Fables*. One comparison of text for the whole
order. *Rejected:* a plain string tie-break — two rules of text in one order.

**How accents go is the implementer's.** `java.text.Collator` for French at
primary strength, or `java.text.Normalizer` in NFD with the combining marks
removed then lowercased: both are the JDK, both meet the cases. Step 3 says
what to do if the first green already covers accents.
