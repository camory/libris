# T026 — The answer without its sources

**Backlog line:** Backend: the answer without its sources. Launched once T025 is
deployed. The backend pin moves to `v0.4.0` in `ApiContractTest`: Contracteer
refuses the `sources` the answer still carries. Then `sources` leaves
`IsbnResponse`, the controller and `LookupResult.Found`, which carries the
edition alone; the use case keeps knowing which sources replied, since
not-found and sources-unavailable depend on it (D02). The scenario tests drop
their assertions on `$.sources` and the S1 body its `sources` line. Nothing
else changes behaviour; un-skips nothing. Realises S1, S4 and S6 as the spec
now reads them.

**Serves:** spec `fast-entry` — S1, S4 and S6, and the *Contract* section, which
names release `v0.4.0` and ends "The answer never says which sources knew the
book: the backend keeps that for the two outcomes alone"; PRD §4.7; decisions
D01, D02, D04, D07, D08, D10, D11. No rule of `docs/DESIGN.md`: this task has no
frontend side.

**First of its kind:** the first **response field the backend stops sending** —
the second half of the removal pair D04 describes, and the first backend pin
bump that takes a field away instead of adding an operation or a field. Two
conventions follow from it and no document states them yet: a pin bump that
removes is a *red on the existing Contracteer verification* (the same single
`@ContracteerTest`, no new case, the document's `additionalProperties: false`
doing the refusing), and *an outcome of the application layer loses a member the
API no longer needs while the domain keeps the value it was made of* —
`LookupResult.Found` drops `sources`, `Source` and `IsbnSource.source` stay
where they are (see *Risks and decisions*). The reviewer repeats this line in
its verdict and Tophe settles it on the pull request.

## Goal
When this task is done the backend speaks `v0.4.0`: `GET /api/v1/isbn/{isbn}`
answers the twelve fields the release declares and never says which source
knew the book, and `LookupResult.Found` carries the edition alone. It matters
now because the frontend has already moved (T025) and the pair is only back in
step — one release, both sides — once this half ships.

## Rules in play
- **D01** — one side moves: `cd backend && ./gradlew check` is the whole gate of
  this task, and nothing under `frontend/` or `deploy/` is touched.
- **D02** — the light hexagon keeps its shape: `domain.lookup` keeps the source
  port and what a source answers, `application` owns the outcome
  (`LookupResult`), `infra.web` owns the response DTO. The use case still tells
  the three outcomes apart — known, nothing known, failed — because not-found

  answer* goes.
- **D04** — the pin bump in `ApiContractTest`, `v0.3.0` to `v0.4.0`, is the only
  contract-related edit of this run and decides nothing about the contract
  itself; the document is never consumed from a branch, and `camory/libris-api`
  is not touched. The backend now sends only what its pinned release declares.
- **D07** — the web slice is proven by Contracteer over stubbed use cases:
  the new verification is this task's first red and the controller its green;
  no hand-written web-slice test asserts a value the contract leaves free. The
  scenario class is the only place that asserts the values S1 names, and the
  edits it takes are exactly the five lines named under *Acceptance criteria*
  — the spec conversation behind them is commit `d2fb14b` (#83). No method is
  un-skipped, renamed, added or removed. Every test body stays `// Given`,
  `// When`, `// Then` unless it is a single statement.
- **D08** — the environment is given: the gate needs the sandbox PostgreSQL
  through `LIBRIS_DB_URL` / `LIBRIS_DB_USER` / `LIBRIS_DB_PASSWORD` for the JDBC
  slice and the scenario classes, and the network for the pinned document the
  Contracteer verifier loads. Nothing is created, no container, no service.
- **D10** — Kotlin official style, immutable by default, sealed types for
  states, no `!!`; a member imported, not qualified, when its bare name is
  unambiguous; detekt's `ImportOrdering` fails an import left out of
  lexicographic order after one is deleted. Conventional Commits with the scope
  `backend`, branch `task/T026-answer-without-sources`, the
  `Co-Authored-By: Claude <noreply@anthropic.com>` trailer on every commit.
- **D11** — "a response field is added, never removed or renamed, while the
  major version stands": `v0.4.0` is the release that removes this one, and the
  order of the two sides — frontend first, backend once it is deployed — is
  what kept the pair compatible meanwhile. Every other field keeps its `null`

## Risks and decisions
- **The launch condition — T025 deployed — is Tophe's, and this run cannot see
  it.** D04 lets the backend drop a field only once the frontend that stopped
  reading it runs in production; the backlog line states it as the condition to
  launch this task, and `libris.amory.fr` sits behind Authelia, so no run can
  check which revision is deployed. The brief is written on the condition being
  met, since Tophe launches the loop. The implementer inherits it: it does not
  verify, does not deploy, does not release, and states in the pull request body
  that merging is not deploying. If the implementer finds evidence to the
  contrary — the deployed revision named somewhere in the tree, say — it stops
  and reports `blocked` rather than shipping the removal.
- **The scenario class is edited, which D07 normally forbids — decided here.**
  D07 says a task changes nothing in a scenario test but the skip it un-skips,
  and that a scenario which has to change is a spec conversation. That
  conversation happened: commit `d2fb14b` (#83, Tophe's own) rewrote the
  *Contract* section — "The answer never says which sources knew the book" —
  and created this task line in the same breath, "Realises S1, S4 and S6 as the
  spec now reads them". The five lines are the last sentence of the old spec
  left in the backend tree, and S1's `STRICT` comparison cannot be green while
  the first stands. The precedents are T021 and T025, whose briefs authorised
  the same edit for the same reason. Exactly five lines and one comma; anything
  more is a blocker, not a judgement call.
- **The four skipped assertions go now, not in T024 — decided here.** They
  read a field that stops existing in this task. Leaving them would hand T024 a
  compilation-clean but false test to discover on un-skipping, and the backlog
  line names them: "The scenario tests drop their assertions on `$.sources`".
  T024 will assert which sources answered through the *values it merges*, not
  through a field of the answer.
- **`Source` survives the field it fed — decided here.** CLAUDE.md admits no
  property no feature of the task exercises, which could be read as an order to
  delete the enum along with the field. It is not: `IsbnSource.source` is the
  port's own statement of which source it is, `BnfSourceTest` and
  `LibrisApplicationTest` assert it today, and T024 merges "in the order of the
  sources", which is that property. After this task no *main* code reads it —
  an acceptable, documented gap of one task, not a dead type. Deleting it would
  be a second, unrelated change and T024 would write it back.
- **`Found` keeps its wrapper — decided here.** It becomes a data class of one
  property rather than being replaced by `SourceEdition` itself: `LookupResult`
  is the sealed class of the three outcomes (D10, and `ArchitectureTest`'s port
  rule refuses a sealed *interface* in `domain` — see `agent/GOTCHAS.md`),
  and flattening it would rewrite the controller's `when`, the use case and
  three tests for no behaviour.
- **The pin bump is a red, not a new case — decided here.** The verification is
  one `@ContracteerTest` method over the whole document; the document's
  `additionalProperties: false` on `Isbn` is what refuses the extra field. The
  run adds no Contracteer case, no stub and no example: the single `given` for
  `9782723488525` keeps answering the 200 the document's example describes.
- **The pin is a network fetch.** The verifier loads
  `https://raw.githubusercontent.com/camory/libris-api/v0.4.0/openapi.yaml` when
  the test runs; the release is immutable (D04) and was read on 2026-09-15 —
  `info.version: 0.4.0`, the `Isbn` schema's twelve fields, `required` over the
  twelve, `additionalProperties: false`, the four named examples of the path
  parameter unchanged. A load failure is an environment problem, never a reason
  to copy the document into the tree.
- **The gate needs the database.** The scenario classes and the JDBC slice boot
  against the PostgreSQL of D08; if `./gradlew check` fails on a connection
  refused, the agent database is down —
  `docker compose --env-file agent/.env -f agent/compose.yaml up -d postgres`
  (`agent/GOTCHAS.md`), not a change to the tests.
