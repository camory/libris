# T022 — The stand-in of the cover

**Backlog line:** Frontend: the stand-in of the cover. In `SourceEditionCard`,
the cover block holds an outlined book icon, `ui/components/icons/IconBook.vue`,
when `coverUrl` is null and when the image fails to load (U05, U06); the
picture, when it loads, as before. Component tests over the three cases: a
cover that loads, none, one that errors. No scenario un-skipped, S1's two
already pass. Realises the stand-in of the Found state.

**Serves:** spec `fast-entry` — the *Found* state of the *Screen* section
("the cover at the left, or its stand-in when the BnF has none or the image
does not load") and the *Contract* section's note that the BnF's cover URL is
handed out without being checked, so the catalogue answers an error where it
has no picture; PRD §4.7; decisions D05 (a component is presentational, props
in, nothing out), D07 (`npm test` is the gate, a component test mounts with
props and asserts what the reader sees), D10, D11 (`coverUrl: null` is what
"no source gave a cover" means); rules U01, U05, U06, U07 and U08 of
`docs/DESIGN.md`.

**First of its kind:** the first stand-in of a picture and the first icon drawn
at the empty-state size, 40 (U05, U06) — every icon so far is 22, beside a word
or inside a button. With it come the first component test that proves a
rendered icon (the stand-in is `aria-hidden` and carries no text, so no text or
role query reaches it: the case asserts the icon component is there, through
`findComponent(IconBook)`), and the first local state in a presentational
component (the card remembers that its image errored). What this task chooses —
the icon's size written in `IconBook.vue`, the stand-in decorative rather than
announced, and `findComponent` as the proof of an icon — is what every later
empty state and every later card will copy: the reviewer repeats this line in
its verdict and Tophe settles the conventions on the pull request, amending
`docs/DESIGN.md` with what the review decides.

## Goal
When this task is done, a card whose ouvrage has no cover, and a card whose
cover URL answers anything but a picture, both show the same outlined book icon
centred in the cover block, at the size and the place the picture would have
taken, instead of an empty grey rectangle or a browser's broken-image glyph. It
matters now because T021 made the BnF the only source and its cover URL is
built and never checked: the catalogue answers an error for every ouvrage it
has no picture of, so the failing image is the common case on the phone check
of the spec's *Done*, not the rare one.

## Rules in play
- **D05** — `SourceEditionCard` stays presentational: one prop, no emit, no
  inject, no API call; `ui/components` may import `domain` and other
  components only, which is what lets the card import `IconBook`
  (`eslint-plugin-boundaries` is the proof; `eslint.config.ts` is not
  touched). Tailwind CSS only, hand-written, mobile first.
- **D07** — `cd frontend && npm test` is the gate, run plainly as the last
  command of its call; a component test mounts with props and the real i18n
  and asserts what the reader sees, never a tag, a class, a colour or a
  pixel; every body is `// Given`, `// When`, `// Then` unless it is a single
  statement; `src/scenario/FastEntryScenarios.spec.ts` is not edited — no
  scenario is un-skipped by this task and the two `S1` cases must stay green.
- **D10** — TypeScript strict, ESLint and Prettier, identifiers and code in
  English, Conventional Commits with the scope `frontend`, branch
  `task/T022-cover-stand-in`, the `Co-Authored-By` trailer on every commit.
- **D11** — an absent optional value arrives as `null`, never omitted:
  `coverUrl: null` is "no source gave a cover", and the frontend decides what
  to show then.
- **U01** — the card and the icon name colour roles only (`text-muted`,
  `bg-border`): no slate, teal or red shade in a template.
- **U05** — the stand-in is the empty state's icon: an outlined icon, 40,
  `muted` at 60 %. One answer at a time in the place it will take, which the
  card already honours; the stand-in changes the size of nothing.
- **U06** — the cover block is 96 by 149, radius 6, `border` behind it while
  it loads, never stretched; when there is none, or the image does not load,
  **the same block** holds the outlined book icon, 40, `muted` at 60 %,
  centred. Everything else about the card is unchanged.
- **U07** — the icon is an inline SVG on a 24 grid, stroke 1.8, round caps and
  joins, `currentColor`, no fill, its own component under
  `ui/components/icons` named by what it shows (`IconBook`, the name U07
  already lists), no icon font, no icon package. It is not a button and it
  sits beside the ouvrage's own text, so it is decoration:
  `aria-hidden="true"`, like `IconAlert` and `IconBarcode`.
- **U08** — no French string lives in a component and this task needs no new
  word: the stand-in says nothing, it is a picture that is missing, and the
  card already names the ouvrage in its heading.

1. **Red — no cover.** In `SourceEditionCard.spec.ts`, a case *shows a book

   `agent/GOTCHAS.md` if it costs a cycle). **Green:** a `ref` the card sets
   from the image's `@error`, and the `v-if` of the image reads the

## Risks and decisions
- **The stand-in is decoration, `aria-hidden`, decided here.** U07 announces
  an icon only when it is alone as a button; this one sits beside the card's
  own heading, which names the ouvrage, and a reader who cannot see the cover
  gains nothing from being told a picture is missing. It also keeps the
  existing cover case honest: `queryAllByRole("img")` stays empty when there
  is no picture, which is what T018's case and the `S1` scenarios assert. A
  word for it would be a new `fr` entry and a screen decision no document
  states.
- **The proof of the icon is `findComponent(IconBook)`, decided here.** The
  stand-in has no text and no role, so D07's "text and roles" leaves a
  presentational element with nothing to assert — which is why T018 gave the
  skeleton no test at all. The backlog line asks for three component cases, so
  the card's test reaches for the component itself, which is neither a tag nor
  a class and does not survive a rename of the icon's markup. The alternatives
  rejected: a `data-testid` (a second addressing scheme, nothing a reader
  sees), and giving the SVG a role and a label only so a test can find it
  (wording invented for a test). This is part of the *First of its kind* line.
- **The icon's size is written in `IconBook.vue`, not passed as a prop,
  decided here.** Every icon of this tree hardcodes its `width` and `height`
  (22) and U07 gives the icon of an empty state exactly one size, 40, which is
  also the size U06 asks for here — the two uses this icon will ever have
  agree. A `size` prop would be an abstraction with a single value; the second
  size adds it.
- **The failure is remembered in the card, and is not reset when the prop
  changes, decided here.** `IsbnView` unmounts the card between two answers
  (the skeleton takes its place while the lookup runs), so a fresh answer
  always gets a fresh card and a `watch` resetting the flag on a new
  `coverUrl` would be production code no test of the application can reach
  (CLAUDE.md: the smallest implementation, no speculative abstraction). The
  day a screen shows the card for two editions in a row without unmounting
  it, that screen's task adds the reset with its case. One bullet in
  `agent/PROPOSED.md`.
- **The `v-else` block of today already exists**, grey and empty, so this task
  is one import, one `ref`, one `@error` and one icon inside it: if the
  implementer finds themselves restructuring the top part of the card, the
  design has drifted from U06 and the diff is too big.
- **The gate runs in the sandbox, not on Tophe's box.** `npm test` needs
  `contracteer` on the PATH and Node 24 (D08); on Tophe's machine the frontend
  gate runs inside the image (`agent/GOTCHAS.md`). No duration figure is
  quoted here: the run reports what it measured.
