# T156 — An edition's own series respelled for the house

**Backlog line:**

>       A save whose series' name matches the edition's own series, ignoring
>       case, accents and end spaces (PRD §3), gives that series the spelling

>       it, and no respelling merges two (D12). Any other name lands as T154

**First of its kind:** none

## Goal
A save that names its edition's own series in other capitals, accents or
end spaces respells that series for the house, so every edition of it
reads the spelling sent. The name index decides the match and the series
statement does the respelling, so no Kotlin code folds a name for it.

## Rules in play
- D02 — the port method sits on `SeriesRepository` (`bibliography.domain.series`),
  its statement in `JdbcSeriesRepository`; `EditEdition` depends on
  `domain` only; nothing in `library` or `web` changes.
- D07 — the one `@Disabled` line of *S5 …, its series* is removed and
  nothing else in `HeldEditionEditScenarios` changes; the rule is decided
  in the statement, so it is proven in the JDBC slice against PostgreSQL;
  the use case's part (which series is its own) in plain JUnit over
  `SeriesInMemory`; no test of a controller; `ApiContractTest`'s `tests=`
  unchanged from `main`.
- D10 — the repository keeps its verbs (`respellOrFindOrInsert`); the id
  parameter is named `ownSeriesId`, an aggregate's name with `Id`; SQL
  keywords upper case; Given / When / Then; no rationale and no `D##` in
  code.
- D11 — one SQL statement per port call; no optimistic locking: the last
  save's spelling wins.
- D12 — the match is the rule *no two series share a name*, kept atomically
  by `SeriesRepository`. The unique index on `BTRIM(name)` under
  `ignoring_case_and_accents` is its only implementation, so the respelling
  happens inside the statement that finds or inserts. The use case keeps
  the series the repository answers. The respelling runs in `EditEdition`'s
  existing transaction block. A respelling never merges two series: only
  the row the name lands on can change, and only when it is the own series.
- PRD §3 — case, accents and the spaces at the ends do not count; the index
  already matches all three (`JdbcSeriesRepositoryTest`'s three *a name the
  house holds* cases).

## Risks and decisions
**Fit.** One run: no migration, dependency or contract change. The work is
one port method with its statement, its fake, and one call in a use case,
three new cases. Rejected: splitting the statement from the use case (a
port method with no caller).

**The match decided by the index, inside the statement.** D12 makes the
unique index the only implementation of "no two series match". A Kotlin
folding would disagree with it on `Ø` and its kin (see the folding item of
`backend.md`), and could then respell into a name another series holds.
The conflict branch of the find-or-insert statement already lands on the
one row the name matches. It gives that row the name sent only when its id
is the own series', so the respelling is atomic and can merge nothing.
Rejected: `Series.isSameAs` in Kotlin (a second matching rule). Rejected:
an `UPDATE` by id then `findOrInsert` (two statements, and the match moved
into a `WHERE` that restates the index).

**A second port method rather than a parameter on `findOrInsert`.** About
thirty test lines call `findOrInsert(series)`, and `HoldEdition` must not
respell yet. No port in the tree declares a default value, and one would
be the first of its kind. So the port gains `respellOrFindOrInsert`, named
for what it may do, in order. Its `ownSeriesId` is nullable, so
`EditEdition` passes the held edition's series id without a branch.
Rejected: `findOrInsert(series, ownSeriesId: SeriesId? = null)` (a default
on a port, a new convention). Rejected: a required second parameter on
`findOrInsert` (thirty unrelated test lines changed).

**The spelling stored is the name as sent.** The respelling writes what
the insert would write, so S5's *the spelling sent* holds byte for byte.
Trimming is no rule of this spec's backend.
