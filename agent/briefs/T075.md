# T075 — A name Libris refuses

**Backlog line:**
> - [ ] T075 Backend: a name Libris refuses.
>       Creating a bookshelf with a blank name is answered `400`
>       `/problems/validation` on `name`; with the name of a bookshelf the
>       reader belongs to, whatever their role on it, compared ignoring case
>       and accents, `409` `/problems/conflict`; neither creates a bookshelf.
>       The blank name is refused where the name is built, the taken one by
>       the creation, which spans the reader's bookshelves (D11, D12).
>       Realises S3; un-skips the backend tests of S3, both cases.

**Serves:** spec `bookshelves` S3 and its *Contract* section (`POST
/api/v1/bookshelves`, keys `400_BLANK_NAME`, `409_TAKEN_NAME`); PRD §3
(*Bookshelf*, *Membership*); decisions D02, D04, D07, D10, D11, D12
**First of its kind:** the first value type of the `library` domain besides
the ids, `BookshelfName`, the first domain type ordering and matching text
ignoring case and accents (moved from T074's `ListReaderBookshelves`).

## Goal
A bookshelf's name is a `BookshelfName`, refusing a blank text where it is
built, and `CreateBookshelf` refuses a name the reader already has; T081's
screen says why, so both refusals are Libris's.

## Rules in play
- D07 — the `@Disabled` of `S3 A name Libris refuses, a blank name` and of
  `S3 A name Libris refuses, a name taken` are removed, nothing else of
  `BookshelvesScenarios` changes; the web edge is proven by
  `ApiContractTest`, whose `400_BLANK_NAME` case is the first red; no
  hand-written test of a controller or a request.
- D04 — the pin stays at `v0.11.0`; no contract edit. `NewBookshelf.name`
  is `minLength: 1`, `pattern: "\\S"` there: a blank name is a shape the
  contract refuses, so the edge refuses it.
- D12 — a value the domain can refuse is built through `of` on its
  companion, answering `null` for a blank text; `of` only checks, so the
  constructor stays public and `require`s the same rule (`CoverName`). The
  aggregate holds the value, so a row read back passes through it. The
  taken name spans the reader's bookshelves: the use case's rule, the
  sameness of two names the name's.
- D10 — the request turns itself into the application's type
  (`NewBookshelfRequest.validate`); the use case takes the value, never the
  text; `invoke` alone public; no visibility widens; the stepdown rule.
- D11 — the blank name is `400` `/problems/validation` with `errors:
  [{name, blank}]`, the code the controller already sends; the taken name
  a `NameTaken` result the controller answers `409` `/problems/conflict`,
  as it already does; no exception crosses a layer.
- D02 — `BookshelfName` in `library.domain.bookshelf`, the JDK alone.

## Risks and decisions
**Fit.** One run: one value type, one rule in one use case, two un-skips;
the type held by `Bookshelf` touches some twenty files, all but six by a
mechanical wrap in one refactor commit. Rejected: a split (the blank name
alone leaves a `Bookshelf.name` the taken name changes again).

**The blank name is refused at the edge, through `BookshelfName.of`.** The
contract says `pattern: "\\S"`, so a blank name is a shape the edge refuses,
as `IsbnController` refuses a text before `Isbn.of`; the use case takes the
value, so `BlankName` goes. The type is held by `Bookshelf`, so no
bookshelf, read back or built, has a blank name. The text is kept as typed,
not trimmed: no document says to trim it. Rejected: `BlankName` answered by
`CreateBookshelf` from a text (the use case would take the text); a
`require` on `Bookshelf` alone (a value the domain refuses has its `of`,
D12); `BookshelfName` as the use case's input only (two types, one rule).

**The sameness of two names is the name's; the taken name is the
creation's.** `BookshelfName.isSameAs` answers whether two names are one
ignoring case and accents; `CreateBookshelf` asks it of each bookshelf the
reader belongs to, whatever their role, through `findByMember`. Rejected:
the comparison in the use case (a rule the value can answer, D12); a query
port answering whether a name is taken (one repository read serves it).

**One comparison, in `BookshelfName`.** The order of S1 and the sameness of
S3 must agree: two names the same are two names that sort together. T074's
private comparison moves whole into `BookshelfName.kt`, spaces still
counting (the gotcha's measured facts stand), and `BookshelfName` is
`Comparable` through it. Its `equals` stays the value's, exact: *Salon* and
*salon* compare as `0` yet are not equal, which only `isSameAs` and sorting
read. Rejected: keeping two copies (they could part); a top-level function
of the domain (a file layout no document states).

**The read outside the transaction, the insert alone inside.** As
`AddMemberToBookshelf` does since T073. At PostgreSQL's default isolation a
read inside the block would not stop two creations racing either, and the
fake cannot tell one from the other; a refused name opens no transaction,
which step 8 asserts. The race, one reader creating the same name twice at
once, is accepted: the screen's check is busy while it runs. Rejected: a
unique index (the sameness ignores case and accents across the bookshelves
a reader belongs to, which no index of one table states); the read inside
the transaction (no guarantee gained, nothing a test can see).

**Read models keep a `String`.** `ReaderBookshelf` and `CopyOnBookshelf`
are shaped for the answer, with no rule. Rejected: `BookshelfName` in them
(forty more test lines for no rule).
