# T031 — The kind of a scanned ouvrage

**Backlog line:** Backend: the kind of a scanned ouvrage. Precondition (human):
the scenario class
`backend/src/test/kotlin/fr/amory/libris/scenario/KindScenarios.kt`, one skipped
test per scenario, each bearing the scenario's exact title (D07).
`ApiContractTest` pins `v0.5.0`, the only contract edit of the task; the renamed
schemas and the folded `ValidationProblem` change no byte of an answer, so the
`400` of the lookup stays as it is (D04). `domain`: `Kind`, and the rule over a
BnF record — a comic strip, marked in field 105, translated from Japanese,
Korean or Chinese, read from field 101 `$c`, is a `MANGA`; any other comic strip
a `BD`; everything else a `BOOK`. Unit tests of the rule, the comic strip
translated from English among them (D02). `infra.lookup`: the BnF source carries
the kind it read, Open Library names none, and the merge answers the kind a
source named, `BOOK` when none did, so the field is never absent. `infra.web`:
the answer carries `kind`, and Contracteer verifies `ONE_PIECE_1` with
`kind: MANGA`. S4 runs over the recorded answer of `9782380751673`, the ISBN
Open Library alone knows; the record without a field 105 is the rule's unit
test, and no new recording. Realises S1, S2, S3, S4; un-skips the four tests of
`KindScenarios.kt`.

**Serves:** spec `kind` — S1 *A manga*, S2 *A BD*, S3 *A book*, S4 *No record
says*, its *Contract* section (release `v0.5.0`, "the backend answers `BOOK`
when no record says, so the field is never absent") and its opening sentence
("The kind is read from the BnF record alone… Open Library never names a
kind"); PRD §3 for the word `kind` and its three values, PRD §4.7 for the
feature; decisions D01, D02, D04, D07, D08, D10, D11. The *Screen* section of
the spec and S1–S3's second `Then` line are T032's, the frontend twin.

**First of its kind:** the first **field of the answer Libris derives instead of
reading**. Every field the lookup answers today is a value a source wrote, taken
whole or picked between sources; `kind` is none of theirs — the BnF record marks
a form and a language of translation, Libris names a kind from them, and answers
one even when no record said anything. Three conventions follow that no document
states yet. *Where the default lives*: in the answer (`infra.web`), written once
as `?: BOOK`, so `SourceEdition.kind` keeps meaning "the kind a source named",
every branch of the chain is reachable and S4 proves the default end to end.
*Where a derived value is split*: the value the catalogue owns is `domain`'s
(`Kind` beside `AuthorRole`), the reading of the source's own encoding is the
adapter's (`kindOf` beside `authorRoleOf` in `infra.lookup`) — and this is the
first rule that reads UNIMARC *coded data*, fixed-length positions inside one
subfield, rather than the text of a subfield. *What a source that names nothing
carries*: `null` through `domain.lookup`, like every optional field, never the
default. The reviewer repeats this line in its verdict and Tophe reviews the
pull request interactively before merging, amending `docs/ARCHITECTURE.md` with
what the review settles.

## Goal
When this task is done, `GET /api/v1/isbn/{isbn}` answers a `kind` on every
`200` — `MANGA` for a BnF record that marks a comic strip translated from
Japanese, Korean or Chinese, `BD` for any other comic strip, `BOOK` for
everything else and for an ISBN no BnF record describes — and the backend is
verified against release `v0.5.0` of the contract, the four scenarios of
`specs/kind.md` running un-skipped over the recordings already in the tree. It
matters now because the bookshelf spec stores an edition with its kind and the
lookup is the only place that can fill it, and because the frontend task T032
cannot write a word of a card until the field is on the wire: D04 sends the side
that gains a field first.

## Risks and decisions
- **`Kind` lives at the root of `domain`, decided here.** D02 puts what the
  catalogue owns at the root — the aggregates, `Isbn`, `AuthorRole` — and keeps
  `domain.lookup` for the source port and what a source answers. The kind is an
  attribute of an edition that the bookshelf will store, not a fact about
  looking up, so it belongs beside `AuthorRole`, which travelled the same road:
  named by the lookup, owned by the catalogue.
- **The rule that reads the record lives in `infra.lookup`, not in `domain`,
  decided here.** The backlog line groups "`Kind`, and the rule" under `domain`,
  but its headings are loose groupings — the same line puts the merge, which is
  `domain.lookup`, under `infra.lookup`. What the rule reads is UNIMARC: a
  fixed-length coded string of field 105 and a three-letter language code of
  field 101 `$c`, both the BnF's own encoding, which D02 keeps out of a
  framework-free domain. `authorRoleOf`, a UNIMARC function code turned into a
  `domain` enum, is the precedent this follows exactly. The value stays the
  domain's, the reading stays the adapter's, and the unit tests the line asks
  for are written all the same, in `BnfSourceTest` beside the other rule cases.
  The reviewer should weigh this against the line; if Tophe wants a
  `domain`-side rule, it takes a second value type for "what field 105 said",
  which no scenario asks for.
- **`SourceEdition.kind` is nullable and the `BOOK` default is written once, in
  `responseOf`, decided here.** `null` means "no source named a kind", exactly
  as it does for every other optional field, so `merge` treats the kind like its
  neighbours and needs no special case. Defaulting inside `merge` instead would
  make the controller's elvis unreachable — dead code the compiler still
  demands, since the type of the field on the wire is non-null — and defaulting
  in both places would hide one of them from every test. The spec phrases the
  default as the backend's answer ("The backend answers `BOOK` when no record
  says"), which is where it now is; S4 exercises it end to end.
- **The field takes no default value and sits second, after `isbn`, decided
  here.** It mirrors the contract's order, and a parameter with no default reds
  every construction site the moment it is added, which is what makes every one
  of them state the kind its record carries instead of inheriting a `BOOK`
  nobody checked. The cost is one noisy compile in cycle 3; the test plan
  puts the expected values in first so the noise is one step, not ten.
- **A comic strip is the code `t` among the form-of-contents positions of field
  105 `$a`, positions 4 to 7, decided here.** Measured on 2026-09-18 over the
  four recordings — `||||t   00|a|` on both comic strips and on One Piece,
  `||||z   00|||` on the Carnets de l'apothicaire novel — and over live BnF
  records, which rules out the other position that differs between them:
  position 11 is `a` on a plain novel too, so it marks nothing about comics.
  Positions 4 to 7 are a set of codes, hence "among", not "at". If a record the
  run meets contradicts this, say so in the pull request body and do not widen
  the rule past what the spec describes.
- **The three languages are the BnF's own codes, `jpn`, `kor`, `chi`, decided
  here.** Field 101 `$c` names the language translated from in the source's
  encoding, which the `LANGUAGES` map converts to ISO 639-1 only for the
  answer's `language` field; the rule reads the raw code. Only `jpn` appears in
  a recording, so the unit test is what proves `kor` and `chi`, and it is why
  the rule's test passes codes directly rather than going through a record.
- **The pin bump leaves the tree red for three cycles, and that is D07's
  order.** The contract task opens with the bump and the controller is its
  green; the branch's last commit is green and the gate is run on it. The pull
  request body says which commit was red and why, since the code may not.
- **The JSON spelling of the enum is proven by the scenarios, not asserted
  anywhere else.** Jackson writes a Kotlin enum by its name, D11 requires the
  same word in Kotlin and in JSON, and `KindScenarios` reads `$.kind` off the
  wire for all three values. No `@JsonValue`, no serialiser, no converter: if
  one turns out to be needed, that is a finding for `agent/GOTCHAS.md`.
- **Contracteer must accept a required enum field on an answer it already
  verified.** Nothing suggests it will not — the `role` of an author is already
  a required enum — but if the verifier behaves unexpectedly on `v0.5.0`, D04 is
  explicit: block with the question, never work around it.
