# T035 — The ouvrage added to a bookshelf

**Backlog line:**
> Backend: the ouvrage added to a bookshelf.
> `library.domain.copy`: `Copy`, one edition on one bookshelf, with its
> `CopyId` and its repository;
> `library.infrastructure.persistence`: `V004__copy.sql` and the `JdbcClient`
> repository, proven by a slice test (D02, D11).
> `library.application`: the add use case takes the reader, a bookshelf and
> the ouvrage as the card shows it, kind included; it matches the house's
> edition by `isbn13` and creates it on the way when the house lacks it, then
> puts a copy on that bookshelf and answers it; it refuses a bookshelf the
> reader is not a member of, and refuses an `isbn13` that is not an ISBN-13,
> as the lookup refuses its path; without an `isbn13` there is nothing to
> match, so the house gets a new edition every time.
> Tests over fake repositories: the house lacking the ISBN (S2); another
> reader adding an ISBN the house holds, whose copy is the edition's second on
> a second bookshelf, and the same reader adding it again, the house still
> holding one edition for that ISBN (S3); the two refusals; the add without
> ISBN.
> Realises S2 and S3 on the backend; un-skips nothing, their scenario tests
> waiting for the API of T037.

**Serves:** spec `bookshelf` S2, S3; PRD §3 (*Copy*, *Edition*, *Bookshelf*,
*Membership*: an edition matched by ISBN is never doubled, a copy belongs to
one edition and sits on one bookshelf, a bookshelf is visible only to its
members); decisions D02, D07, D08, D10, D11, D12.

**First of its kind:** the first use case of one context driving a port of
another (`library.application` storing through `bibliography`'s
`EditionRepository`), the first aggregate holding another context's id (`Copy`
carries an `EditionId`), and the first command object a use case takes.

## Goal
When this task is done the backend adds an ouvrage to a bookshelf below the
API: the house's edition is matched by its ISBN-13 or created on the way, and
a copy of it lands on the bookshelf, stored in `copy`. It matters now because
T037 has nothing to call — the add of `v0.6.0` is what S2 and S3 still lack.

## Rules in play
- **D02** — `library.domain.copy` stays framework-free; `library` may see
  `bibliography.domain`, never the reverse; the use case lives in
  `library.application`, takes its ports by constructor and never carries
  `@Transactional`; the adapter lives in `library.infrastructure.persistence`.
  `ArchitectureTest` stays green without a new rule.
- **D07** — tests beside the code, Kotest assertions, bodies laid out
  `// Given`, `// When`, `// Then`; shared doubles in a `fixture` package; the
  slice test runs on the real database; the gate is `./gradlew check`. This
  task un-skips nothing: `scenario/BookshelfScenarios.kt` is not edited and
  its tests stay `@Disabled("T037")`.
- **D08** — no Docker: the slice test takes the given PostgreSQL through
  `@JdbcSliceTest`.
- **D10** — `V004__copy.sql`, SQL keywords upper case, identifiers lower
  snake_case, as `V003__edition.sql` writes them.
- **D11** — `CopyId` is a uuid v7 value class minted by `CopyId.new()`; the
  aggregate takes its id; the port exposes `insert`; the table is the singular
  `copy`; both foreign keys are declared and cascade; an outcome of the use
  case is a **result the controller answers**, never an exception.
- **D12** — `Copy` names the edition and the bookshelf **by their ids**; the
  rule spanning the edition and the copy is the use case's, guarded by one
  `TransactionOperations` block and proven by a fake recording state before and
  after; a refusable value has two doors, so thirteen-digit reading gets its
  own `Isbn.ofThirteen`.

## Acceptance criteria

- [ ] `V004__copy.sql` creates `copy` with both foreign keys cascading, and
      `JdbcCopyRepositoryTest` reads an inserted row back through `JdbcClient`
      on the real database.
- [ ] **S2** — the house lacking the ISBN: one add stores one edition carrying

- [ ] **S3, another reader** — an ISBN the house holds stores no second

      carries an `Isbn?`, a bad `isbn13` never reaches the use case.)
      A `NewBook` without an `isbn` gives the house a new

## Test plan
The gate is `cd backend && ./gradlew check`, run plainly and last; during red
and green run the one class. Commit each cycle before a mutation check —
`git checkout <file>` reverts to the last commit.

1. `JdbcCopyRepositoryTest`, `a copy inserted sits on its bookshelf and its
   edition`. Red: nothing exists. Forces `Copy`, `CopyId`, `CopyRepository`,
   `V004__copy.sql`, `JdbcCopyRepository`. Follow `JdbcBookshelfRepositoryTest`
   for the shape and for putting the rows the foreign keys need in place;
   assert the row with `jdbcClient`, since the port only inserts.
2. `two copies of one edition on one bookshelf stand beside each other` —
   **guard**, step 1 already satisfies it. Mutation: add
   `UNIQUE (edition_id, bookshelf_id)` to `V004__copy.sql`; the migration has
   already run, so apply the checksum recipe of `agent/GOTCHAS.md` before the
   red run, then revert and re-run green.
3. `a copy of an edition the house does not hold is refused` and `a copy on a
   bookshelf Libris does not know is refused`, both
   `shouldThrow<DataIntegrityViolationException>` — **guards**. Mutation: drop
   the matching `REFERENCES` from `V004__copy.sql`, same recipe as step 2.
4. `IsbnTest` gains three cases on a public `Isbn.ofThirteen`: thirteen digits
   with a sound check digit are read as they stand, an ISBN-10 is refused, a
   wrong check digit is refused. Red: it is private. Green: widen it.
5. `AddBookToBookshelfTest`, `the house lacking the ISBN gains the edition and
   the copy` (S2). Red: nothing exists. Forces `NewBook`, `AddBookResult`,
   `AddBookToBookshelf`, `EditionsInMemory`, `CopiesInMemory`. Asserts the one
   stored edition carries every field of the `NewBook` with its kind and its
   ISBN, the one stored copy names that edition and that bookshelf, and the
   answer is `Added` with that copy and that bookshelf. Build the use case
   through a private helper of the test class so step 11 changes one line.
6. `an ISBN the house holds reaches the existing edition` (S3, another reader
   on another bookshelf). Red on step 5's green, which always inserts. Asserts
   one edition stored, and the new copy carrying the house's `EditionId` and
   the second bookshelf as that edition's second.
7. `the same reader adding it again puts a second copy beside the first` (S3) —
   **guard**, steps 5 and 6 already satisfy it. Asserts two copies on the one
   bookshelf with two different `CopyId`s and one edition. Mutation: mint the
   copy's id from the edition (`CopyId(edition.id.value)`) instead of
   `CopyId.new()`.
8. `a bookshelf id no bookshelf carries is refused`, then `a bookshelf the
   reader is not a member of is refused`. Each red on the previous green: the
   first forces the read, the second the membership. Both assert
   `NoSuchBookshelf` and that both fakes stayed empty.
9. `an isbn13 whose check digit is wrong is refused`. Red. Asserts `NotAnIsbn`
   and nothing stored. Then `an ISBN-10 is refused` — **guard**, step 4's door
   already satisfies it; mutation: read the `isbn13` with `Isbn.of` instead of
   `Isbn.ofThirteen`.
10. `the ouvrage without an ISBN gives the house a new edition every time` —
    **guard**. Asserts two adds store two editions with different ids, both
    without an ISBN, and two copies. Mutation: answer `NotAnIsbn` when
    `isbn13` is null.
11. `the edition and the copy land in one transaction`. Red: the use case takes
    no `TransactionOperations` and records nothing. Uses
    `TransactionsObserving { editions.stored.size to copies.stored.size }` and
    asserts one `Transaction(before = 0 to 0, after = 1 to 1)`, as
    `ReaderVisitTest` does; the helper of step 5 gains the parameter,
    defaulting to `TransactionOperations.withoutTransaction()`.

## Risks and decisions
**The use case is `AddBookToBookshelf`, flat in `library.application` beside
`ReaderVisit`,** named for what it does as the other use cases are. Rejected: a
`library.application.add` sub-package — the tree groups use cases only where a
concern already has several files, and this one has three.

**The ouvrage the card shows becomes a `NewBook` data class in
`library.application`,** carrying `isbn13` as the text the API sends and the
rest in the `bibliography.domain` types, so the use case, not its caller,
decides whether that text is an ISBN-13. Rejected: taking an `Edition` — an
aggregate takes its id, and there is no id before the house is asked; taking
the lookup's `EditionPreview`, which is the lookup's answer and whose ISBN is
not nullable; thirteen parameters on `add` — detekt refuses more than six.

**The outcome is a sealed class `AddBookResult`,** `Added` with the copy *and*
its bookshelf, `NotAnIsbn`, `NoSuchBookshelf`: an outcome of a use case is a
result the controller answers (D11), and the `Copy` of `v0.6.0` carries its
bookshelf's name, which the use case has already read to check the membership.
A class, not an interface — the ArchUnit port rule breaks on sealed interface
variants (`agent/GOTCHAS.md`). Rejected: exceptions for the two refusals;
answering the `Copy` alone and making T037 read the bookshelf again.

**An unknown bookshelf and a bookshelf the reader is not a member of are the
same refusal,** `NoSuchBookshelf`: a bookshelf is visible only to its members
(PRD §3) and the contract answers `404 /problems/not-found` for both; telling
them apart would tell a reader that a bookshelf they cannot see exists.

**`Isbn.ofThirteen` becomes public** so the add refuses exactly what the lookup
path refuses: thirteen digits starting `978`/`979` with a sound check digit.
Rejected: `Isbn.of`, which accepts an ISBN-10 and strips separators, neither of
which the `isbn13` field of the contract allows; a regex in the use case,
which would put a rule of the value outside the value.
*Overturned on Tophe's review, 2026-09-22:* `ofThirteen` stays private —
widening it is an API change of the value type no rule asks for — and the
pattern of the contract is the web adapter's, as `IsbnController` already
does it with `ISBN_PATH` then `Isbn.of`. `NewBook` carries `isbn: Isbn?`, the
value type being the door; `NotAnIsbn` is gone, the `400` of a bad `isbn13`
is T037's controller answering the contract's validation problem.

**One `TransactionOperations` block wraps the edition insert and the copy
insert,** both ids minted before it, as `ReaderVisit` does: a copy pointing at
an edition no one stored is the state this rule forbids (D12). The block is
entered even when the edition already exists, which costs one empty transaction
and keeps one path.

**The table carries no column for a date, an owner or a state** — only what
this task uses (`CLAUDE.md`); nothing in S2, S3 or S4 asks who added a copy or
when. `copy` is a non-reserved word in PostgreSQL and needs no quoting.

**The fake of `EditionRepository` lives in `bibliography/fixture/`,** beside the
port it doubles, and the library's test imports it; a second fake under
`library/fixture/` would double the port the day it grows a method.
