# T013 — The ISBN-13 value type and the Open Library source

**Backlog line:** Backend: the ISBN-13 value type and the Open Library source.
`domain`: the ISBN-13 value type — thirteen digits, check digit verified,
refusing anything else — and the source port, which answers what one source
knows about an ISBN, or nothing at all: title, subtitle, authors with their
roles, series and volume number, collection, publisher, publication year,
language, page count, summary, cover URL (D02, D11, PRD §3). `infra.lookup`:
Open Library, base URL `LIBRIS_OPEN_LIBRARY_URL`, the edition followed from
`/isbn/<isbn>.json`, its authors fetched by key with the role `WRITER`, the
cover URL built from the ISBN and never fetched, the call bounded by
`LIBRIS_SOURCE_TIMEOUT`; an unknown ISBN is nothing known, a failure or a
timeout is a failure, and the caller tells the two apart. Tested against
WireMock over the recorded answers under
`src/test/resources/scenarios/open-library`; the whole application still boots
with neither variable set. No use case, no controller, no contract edit;
un-skips nothing.

**Serves:** spec `fast-entry` — no scenario of its own; it is the source half
of S1, S4, S5, S6 and S7, all of which go green in T014, T015 and T020. PRD
§4.7 (sources arrive one at a time, each degrading gracefully when it fails or
knows nothing; the cover by ISBN from Open Library) and §3 (Edition, Series,
Volume number, Collection, Author, Role and their *Avoid* lists). Decisions
D02 (the packages and the framework-free domain, ports as plain Kotlin
interfaces, `infra.lookup` for the source clients), D07 (`./gradlew check` is
the gate, tests beside the code they exercise, Given/When/Then bodies, the
scenario tests are Tophe's), D08 (the environment is given: no Docker, no
Testcontainers), D10 (Kotlin conventions, sealed types for states, detekt,
Conventional Commits), D11 (ISBN-13 stored normalised — thirteen digits, no
separators, validated on input).

## Goal
When this task is done the backend owns the two domain pieces every later task
of the phase leans on — the `Isbn13` value type and the `IsbnSource` port with
the answer it carries — and one real implementation of that port, Open
Library, proven against WireMock over the answers already recorded in the
repository: a known ISBN, an unknown one, a failing source and one answering
past the timeout. It matters now because it is the first outbound client of
Libris: it settles how a source is configured (its base URL and timeout as
constructor arguments, defaulted so the application boots without them), how
it says "I know nothing" as against "I am broken", and it is what T020's use
case injects one task later. Nothing calls it yet, which is deliberate: the
component is complete and fully tested on its own, and the endpoint is T020.

## Acceptance criteria
- [ ] `fr.amory.libris.domain.Isbn13` accepts exactly thirteen digits whose
      last one is the ISBN-13 check digit of the first twelve, exposes those
      thirteen digits, and answers a refusal for anything else — a wrong check
      digit, a wrong length, separators, spaces, letters, the empty string. It
      does not normalise and does not convert an ISBN-10: the typed text is
      the frontend's business (S3, T016). Proof: `Isbn13Test`.
- [ ] `fr.amory.libris.domain.IsbnSource` is a plain Kotlin interface, free of
      any framework type, that names its source and answers, for one
      `Isbn13`, one of three things: what it knows, that it knows nothing, or
      that it failed. Proof: `ArchitectureTest`'s domain rule stays green, and
      `OpenLibrarySourceTest` reaches all three answers through the interface.
- [ ] The answer carries every field the backlog line lists — title, subtitle,
      authors with their roles, series with its volume number, collection,
      publisher, publication year, language, page count, summary, cover URL —
      plus the ISBN-13 it describes, with the words of PRD §3 and none of its
      *Avoid* words. Proof: it compiles and `OpenLibrarySourceTest` asserts
      each field Open Library fills and the nullity of each field it does not.
- [ ] `fr.amory.libris.infra.lookup.OpenLibrarySource` implements the port,
      takes its base URL and its timeout as constructor arguments, and names
      itself `OPEN_LIBRARY`. Proof: `OpenLibrarySourceTest` constructs it over
      WireMock's base URL with a short timeout, with no Spring context.
- [ ] On a known ISBN it follows `/isbn/<isbn>.json` to the edition document,
      fetches every `authors[*].key` at `<baseUrl><key>.json`, and answers
      what it knows: for `9782723488525` over the recorded answers, the title
      `One Piece - Édition originale Tome 01`, the subtitle `Romamce Dawn - À
      l'aube d'une grande aventure`, the two authors `尾田栄一郎` and
      `Shueisha` both with the role `WRITER`, the publisher `Shônen Manga`,
      the publication year 2013, the page count 207, the ISBN-13
      `9782723488525`, the cover URL
      `https://covers.openlibrary.org/b/isbn/9782723488525-L.jpg`, and nothing
      at all for series, collection, language and summary. Proof:
      `OpenLibrarySourceTest`.
- [ ] The cover is never fetched: over a known ISBN, WireMock received the
      edition request, the request it redirected to and one request per
      author, and no other. Proof: `OpenLibrarySourceTest`, asserting on the
      requests WireMock recorded.
- [ ] An ISBN Open Library does not know — `/isbn/<isbn>.json` answering 404
      with an HTML body, as the recorded behaviour of the real source is —
      is nothing known, not a failure. Proof: `OpenLibrarySourceTest`.
- [ ] A source that answers 5xx, a source whose author call answers 5xx, and a
      source that answers past the configured timeout are each a failure, told
      apart from nothing known by the answer's type alone, with no exception
      escaping the client. Proof: `OpenLibrarySourceTest`, three cases, each
      under a timeout short enough to cost no wall clock.
- [ ] The whole application boots with neither `LIBRIS_OPEN_LIBRARY_URL` nor
      `LIBRIS_SOURCE_TIMEOUT` set: `LibrisApplicationTest` is unchanged and
      green, and `env | grep LIBRIS_` shows neither variable in the sandbox
      (`backend/.env` holds the three database variables only, unchanged).
- [ ] `src/test/kotlin/fr/amory/libris/scenario/` does not change: `git diff
      main -- src/test/kotlin/fr/amory/libris/scenario` is empty, the six
      scenario methods of `FastEntryScenarios` are still `@Disabled`, and the
      recorded answers under `src/test/resources/scenarios/` are untouched —
      the Open Library test reads them, adds none and edits none.
- [ ] The contract does not change: the `openApiDoc` of `ApiContractTest`
      still pins `v0.1.0`. `git diff main -- src/test/kotlin/fr/amory/libris/ApiContractTest.kt`
      is empty.
- [ ] No new dependency and no change to `gradle/libs.versions.toml`,
      `build.gradle.kts`, `backend/.env.example`, `deploy/` or any Dockerfile.
      `git diff main --stat` touches `backend/src/**` only, plus

- [ ] `cd backend && ./gradlew check` is green, run plainly in this session:

## Test plan
Green suite: `cd backend && ./gradlew check`, run plainly — nothing piped or
chained after it, or the sandbox hook refuses the call. While iterating,
`./gradlew test --tests 'fr.amory.libris.domain.Isbn13Test'` and
`--tests 'fr.amory.libris.infra.lookup.OpenLibrarySourceTest'` are enough;
both are plain JUnit, no Spring context, so a cycle costs seconds (see the
gate-speed note in `agent/PROPOSED.md`).

Order, one test at a time, red before green:

1. `src/test/kotlin/fr/amory/libris/domain/Isbn13Test.kt` — the value type
   first, because the port and the client both take it. Cases, each a
   Given/When/Then body unless it is a single statement:
   `9782723488525` is accepted and exposes its thirteen digits; the contract's
   other two valid examples `9782000000006` and `9791000000008` are accepted;
   `9782723488526` is refused, which is the contract's `400_NOT_AN_ISBN`
   example and proves the check digit is computed, not ignored;
   `978272348852` and `97827234885250` are refused, which proves the length;
   `978-2-7234-8852-5`, `9782723488525 ` and `97827234885X5` are refused,
   which proves no normalisation happens here. Kotest assertions, as
   `ReaderVisitTest` uses them.
2. `src/test/kotlin/fr/amory/libris/infra/lookup/OpenLibrarySourceTest.kt` —
   one `WireMockServer(options().dynamicPort())` started and stopped by the
   class, `reset()` between cases, and the client built over
   `wireMock.baseUrl()` with a timeout of about 200 ms. Read
   `FastEntryScenarios.openLibraryKnows` first and stub exactly the shape it
   stubs — `/isbn/<isbn>.json` answering a 302 to
   `<baseUrl>/books/OL33773404M.json`, that document, and one document per
   author key — because the same stubs must satisfy this client when T015
   un-skips the scenarios. Load the recorded answers the way that method does,
   from `/scenarios/open-library/...` on the test's classpath; copy the two
   lines rather than extract a helper, since the scenario file may not change.
   Cases, in this order, each proving one thing:
   - the source names itself `OPEN_LIBRARY`;
   - a known ISBN is known, field by field, including the two authors with
     the role `WRITER` and the cover URL built from the ISBN — this is the
     case that proves the redirect is followed at all, the risk the split of
     T013 called out;
   - the requests WireMock recorded are the edition, the redirect target and
     the two authors, and nothing else — the cover is never fetched;
   - a 404 with an HTML body is nothing known;
   - a 500 on the edition is a failure;
   - a 500 on an author is a failure;
   - a fixed delay longer than the client's timeout is a failure, and the case
     returns well under a second.
3. The Open Library client, grown one case at a time behind those tests. No
   test of the Spring wiring: that the bean is created with its defaults is
   already proven by `LibrisApplicationTest`, which must stay green without
   the two variables — run it once the client is annotated, and delete any
   scratch test of the wiring before the pull request (D07).

`ArchitectureTest` needs no new rule: its five rules already cover the new
packages, and the domain rule is what keeps `IsbnSource` and the answer free
of Spring. Nothing in `FastEntryScenarios` is touched, so `./gradlew check`
must report the same six skipped scenario methods as it does on `main`.

## Risks and decisions
- **Does the request factory follow Open Library's redirect?** The unknown the
  split of T013 named. Decided: the client builds its own `RestClient` over a
  JDK `HttpClient` configured to follow redirects and to use the given timeout
  for the connection, with the same timeout as the read timeout of the request
  factory, rather than relying on whichever factory Spring Boot detects. The
  known-ISBN case is what proves it, against the 302 the scenario stubs.
- **What the timeout bounds.** In this task it bounds each HTTP request the
  source makes — the edition, the redirect it follows, each author — not the
  lookup as a whole. That is what S6's stub exercises (a fixed delay on the
  first request against a 1 s configuration), and T014's line already owns the
  per-source bound of the whole call. If the sum of several bounded requests
  ever matters, it is the use case's business, not the client's.
- **Configuration and the defaults.** The client takes `baseUrl: String` and
  `timeout: Duration` as constructor arguments so a test can construct it, and
  Spring supplies them from `@param:Value("\${LIBRIS_OPEN_LIBRARY_URL:https://openlibrary.org}")`
  and `@param:Value("\${LIBRIS_SOURCE_TIMEOUT:5s}")` — the exact variable
  names the scenario harness registers, so the same placeholder resolves an
  environment variable in production and a registered property in the tests.
  The defaults are the real source and five seconds; they are what lets the
  application boot with neither variable set, which the backlog line demands.
  No `application.yaml` key and no `.env.example` entry: a property namespace
  is a convention that outlives this task, and the gate needs neither
  variable. Use `@param:` explicitly, as `FastEntryScenarios` does with
  `@param:Qualifier`: an annotation on a constructor parameter without a
  use-site target is a warning, and warnings are errors here.
- **Nothing known against a failure.** Decided: a sealed answer, three
  variants — what it knows, nothing known, failed — so the caller tells them
  apart on the type and no exception crosses the port (D10, sealed types for
  states). The client catches what its HTTP layer throws in one place and
  answers failed; a 404 is the only status mapped to nothing known. An answer
  the client cannot map (an edition document with no title) falls in that same
  catch and is a failure, which needs no test of its own: a source answering
  nonsense is a broken source.
- **Names.** `Isbn13` with a factory answering the value or a refusal;
  `IsbnSource` for the port; `Source` for the enum of the two sources the
  contract names; `SourceAnswer` for what a source answers; `SourceEdition`,
  `SourceAuthor`, `SourceSeries` for what it knows — prefixed because
  `Edition`, `Author` and `Series` are the aggregates of PRD §3, which this
  feature does not store and must not squat; `AuthorRole` because PRD §3 uses
  *role* for both an author's role and a bookshelf member's. Local,
  reversible, the planner's.
- **The full enums now.** `Source` declares `BNF` and `AuthorRole` declares
  the four roles of PRD §3 and of the contract, though Open Library only ever
  answers `OPEN_LIBRARY` and `WRITER` in this task. The closed sets are the
  domain's vocabulary, fixed by PRD §3 and by the contract's `role` and
  `sources` enums; a partial enum would be a statement about the domain that
  neither document makes. T015 maps the other three roles.
- **No Kotlin module for Jackson.** Measured on the current tree: the test
  runtime classpath carries `jackson-databind` 2.21.5 through Spring Boot
  4.1.1 and no `jackson-module-kotlin` and no `jackson-module-parameter-names`,
  so binding those documents to Kotlin data classes would need a dependency
  this task must not add. Decided: read the few fields the mapping needs from
  the parsed document with Jackson's tree model, which the starter already
  provides. If that proves impossible, the task is blocked with the question,
  not unblocked with a dependency.
- **Which author name, and which publisher.** Open Library's author document
  carries both `name` (`尾田栄一郎` in the recorded answer) and
  `personal_name` (`Eiichirō Oda`); the edition document carries three
  publishers. Decided: `name`, the field Open Library documents as the
  author's name, and the first publisher. No scenario pins either — S1 reads
  the BnF's values and S6 asserts only the title, the cover and the sources —
  so both are local and reversible. The publication year is the four-digit
  year read out of `publish_date` (`Jul 15, 2013` → 2013), nothing when there
  is none.
- **The covers host is a constant.** `https://covers.openlibrary.org/b/isbn/<isbn>-L.jpg`
  is built in the client and not derived from `LIBRIS_OPEN_LIBRARY_URL`: the
  scenario test expects that literal URL while the base URL is WireMock's. It
  is never fetched, so no variable and no stub for it.
- **detekt.** The check-digit arithmetic uses 3, 10 and 13; detekt's default
  configuration has `MagicNumber` active. Name the constants rather than
  suppress the rule, and keep the names free of any *why* (D10, no rationale
  in code, and no `D##` anywhere in code or tests).
- **Nothing calls the client at the end of this task.** That is the shape the
  split chose, and it is why the boot test matters: the bean is created on
  every boot with its defaults, and T020 injects the port one task later.
