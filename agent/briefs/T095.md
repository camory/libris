# T095 — The cover of a series

**Backlog line:**
> - [ ] T095 Backend: the cover of a series.
>       Each series of T093 answers the cover of its first edition in the
>       order a shelf reads, catalogue S1's: by tome, an edition without a
>       tome after the numbered tomes, then by title; its address as a
>       `Book`'s, or none when that edition has none, another edition's
>       never standing in (D11, a pick by position). The first edition of
>       each series is found in SQL through `CatalogueEditions`, with the

>       alike but for their id. Unit tests of the use case: the first
>       edition's cover; none when the first has none and the second has
>       one. S3's first red, the spec giving it no backend scenario test.

## Goal
`CatalogueEditions` gains a second read, the first edition of each series
the reader holds in the order a shelf reads, and `ListCatalogueSeries`
answers each series with that edition's `coverName`, where T093 left it
`null`. With it the backend answers the whole `Series` of `v0.12.1`, and
T096 may start once it is deployed.

## Rules in play
- D02 — the SQL lives in `JdbcCatalogueEditions`, the port in
  `library.domain.copy`; the controller and `SeriesResponse` (it already
  maps `coverName` to `coverUrl` through `coverPathOf`) stay unchanged.
- D07 — the order is proven in `JdbcCatalogueEditionsTest`, the JDBC slice;
  the cover rule in `ListCatalogueSeriesTest`, plain JUnit over fakes; no
  web, contract or scenario test changes (S1 compares names only).
- D10 — the port's method reads with its receiver,
  `catalogueEditions.findFirstOfEachSeries(readerId)`; the use case keeps
  one public `invoke`; SQL keywords upper case, identifiers snake_case;
  test fixtures below the class and its helpers; Given, When, Then.
- D11 — a pick by position: the order is total, the edition's id its last
  key; the port answers a `Set`, no order promised, and the series list
  stays in no promised order.
- D12 — a read the repositories cannot serve gets the query port of its
  context, answering ids; no aggregate is rebuilt from the join, the
  editions still come from `EditionRepository.findByIds`.

## Test plan
Suite: `cd backend && ./gradlew check`. One step, one case, one cycle, one
commit, in this order; `./gradlew detekt` before each commit. Each green is
the smallest that passes the cases so far, since the next red depends on
it. Persistence cases build with the class's `edition(...)` and `heldOn`
helpers and assert `catalogueEditions.findFirstOfEachSeries(lea.id)
shouldBe setOf(...)`; each inserts the edition expected *last*, so that a
missing key picks the wrong one.

1. **Red, `JdbcCatalogueEditionsTest`** (`JdbcCatalogueEditions`).
   `the first of each series is its first tome`: Léa holds *Aux prises avec
   Baggy* (`One piece`, 2), *Romance dawn* (`One piece`, 1), *La serpe
   d'or* (`Astérix`, 2), *Astérix le Gaulois* (`Astérix`, 1), inserted in
   that order; answered the ids of *Romance dawn* and *Astérix le
   Gaulois*. Two series, so that one edition for the whole catalogue is
   red. Red: the method does not exist. Green: `findFirstOfEachSeries` on
   `CatalogueEditions`, implemented by `CatalogueEditionsAnswering` too
   (see Files); in SQL one edition per series, the lowest tome, no
   reader filter yet.
2. **Red, `JdbcCatalogueEditionsTest`** (`JdbcCatalogueEditions`).
   `the first of a series is the first the reader holds`: Tom holds
   *Astérix le Gaulois* (`Astérix`, 1) on his bookshelf, Léa *La serpe
   d'or* (`Astérix`, 2) on hers; answered *La serpe d'or*. Red: step 1
   reads every edition. Green: the reader's editions alone, the semi-join
   of `findPage` (`EXISTS` over `copy` and `membership`).
3. **Guard, `JdbcCatalogueEditionsTest`** (`JdbcCatalogueEditions`).
   `the first of a series has a tome when one of its editions has one`:
   *Astérix et ses amis* (`Astérix`, no tome) then *Astérix le Gaulois*
   (`Astérix`, 1); answered *Astérix le Gaulois*. Green on arrival:
   PostgreSQL puts nulls last in an ascending order. Mutation: the tome
   key `NULLS FIRST`, answered *Astérix et ses amis*.
4. **Red, `JdbcCatalogueEditionsTest`** (`JdbcCatalogueEditions`).
   `without a tome, the first of a series is the first by title`: *Le
   Petit Nicolas* then *À la récré du Petit Nicolas*, both of `Le Petit
   Nicolas`, no tome; answered *À la récré du Petit Nicolas*. Red: no key
   after the tome. Green: the title `COLLATE ignoring_case_and_accents`;

5. **Guard, `JdbcCatalogueEditionsTest`** (`JdbcCatalogueEditions`).

6. **Red, `JdbcCatalogueEditionsTest`** (`JdbcCatalogueEditions`).

7. **Red, `ListCatalogueSeriesTest`** (`ListCatalogueSeries`).

## Risks and decisions
**Fit.** One run: one port method, one SQL statement, one use-case field,
eight short cases in two existing test classes. Rejected: a split between
the persistence and the use case (the port method would land with no
caller, and the use case alone is two cases).

**The port answers the set of first editions' ids.** `ListCatalogueSeries`
already groups the reader's editions by series to count them and read
their kind; the cover is that of the group's edition the set names, so the
rule "another edition's cover never stands in" is the use case's, tested
over the fake. Rejected: a `Map` from series name to id (Kotlin would
match the name the SQL reads, a second key for the same row); answering
the cover names from SQL (the cover is the edition's, read already, and
"none" would need a null in the answer); a `List` (D11: no order is
promised, and `in` is the only question asked of it).

**The first is the first the reader holds (step 2).** S3's order is
catalogue S1's, an order over the reader's catalogue, and S1 answers each
series from the reader's editions alone; the count is over those too. A
tome 1 on a bookshelf the reader does not belong to is not on their shelf,
and its cover is not theirs to see. The backlog line lists five cases of
order; this sixth is the reader's scope, which no case of order reds.
Rejected: a guard (step 1's smallest green reads every edition, so it is a
real red).

**Two series in step 1.** Every other case holds one series, so a
statement answering the single first edition of the whole catalogue would
pass them all; step 1 is where "of each series" is red. Rejected: a
seventh case for the partition (the first tome's case carries it at no
cost).

**Which cases are guards.** PostgreSQL orders nulls last ascending, so
step 3 passes on step 2's green; `ignoring_case_and_accents` and byte order
both count spaces, so step 5 passes on step 4's green. The space case
guards against a comparison that ignores spaces (glibc's `en_US`,
`java.text.Collator`), which this tree measured once
(`agent/gotchas/backend.md`). The sandbox and CI run `postgres:18-alpine`,
whose `en_US.utf8` is byte order under musl (measured 2026-10-15: `Les`,
`Naruto`, `maus`, `Émile`), so step 4's titles, `À` against `L`, red the
plain title as well as no title. Step 6's red relies on the first row
scanned being kept among equal keys, as the page's id case did; should it
pass on arrival, it becomes a guard whose mutation is the id key
`DESC`, and the PR says so.
