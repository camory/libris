# T057 — The cascade for an edition with no chosen source

**Backlog line:**
> - [ ] T057 Backend: the cascade for an edition with no chosen source.
>       The worker asks, for an awaited cover with no chosen source,
>       inventaire.io, then Open Library, then the BnF, its picture read from
>       the record's ark, stopping at the first picture and storing it as T066

## Goal
An awaited cover with no chosen source is fetched from the first source,
in the house's order, that has a picture, the BnF among them, and an edition
stored before covers awaits one; S7 is green, S12's editions taken the same way.

## Risks and decisions
**The cascade lives in `FetchAwaitedCovers`, ordered by `CoverSource.order`.**
The use case already chooses among its fetches by the awaited cover's
source; with none, it asks them all, sorted once by the enum's `order`
field, the order the lookup's candidates use (`CoverCandidates`), and stops
at the first picture (`firstNotNullOfOrNull`). Spring's list order is not
the house's. *Rejected:* the list's order as given, which depends on bean
declaration; `@Order` on the beans, a second statement of an order the
enum holds; `AwaitedCover.asks(source)`, a rule of no aggregate's existence
moved for no case.

**`BnfSource` fetches by its own search, then the covers address.** The
port takes the ISBN (T066), and the BnF names its picture by the ark of its
record, so the fetch sends the search `lookUp` sends and reads the ark as
`coverOf` does: one place for each. The covers address is a setting so the
scenarios reach the stub, as Open Library's is. *Rejected:* fetching the
candidate's public address, which the stub cannot serve; a second adapter
class repeating the search; a lookup through the use case's port first.

**The BnF candidate keeps its public address.** *FastEntryScenarios*
asserts it whole, and D07 forbids editing them; Open Library's candidate was
moved onto its setting by Tophe, with the scenario edit. The asymmetry is
proposed, not resolved. *Rejected:* building the candidate on the setting,
which reds *FastEntryScenarios*.

**A missing BnF cover is a failure, read as `null`.** Probed on 2026-10-04:
`/couverture?&appName=NE&idArk=ark:/12148/cb486302521&couverture=1`
answers `200 image/jpeg`; an ark without a cover answers `500 text/html`.
`nullOnFailure` meets both a failure and a miss, as for Open Library's
fetch.

**V008 names the editions by what they lack.** The migration cannot tell
when an edition was stored. Since V006 every add of an edition with an ISBN
inserts its awaited cover, and only a stored picture ends a wait and names
the cover; so the editions with an ISBN, no `cover_name` and no awaited
cover are exactly those stored before covers. The `NOT EXISTS` also keeps
the primary key of `awaited_cover` from refusing the migration.
*Rejected:* every edition with an ISBN, which collides with existing rows
and would fetch again an edition's stored picture; `ON CONFLICT DO
NOTHING` alone, which still gives a wait to an edition whose picture is
stored.

**Every add now asks the sources.** A scenario add with no chosen source
starts the cascade on `applicationTaskExecutor`; unstubbed WireMock answers
`404`, fast and read as `null`. Bookshelf S4 was reworked by Tophe for it
(`8d54a3f`). If any other scenario reds at the gate, stop and report
`blocked` naming the case: editing it is not this task's.

**Proposed D02 sentence**, for the PR body: the BnF adapter "answers the
edition and its cover's address, and fetches its picture for the worker".
