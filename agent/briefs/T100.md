>       Every hand-drawn icon gives way to its Lucide counterpart at the same
>       size and colour: `IconHome` → `House`, `IconBarcode` → `ScanBarcode`,

## Goal
Every icon on screen is a Lucide icon drawn at the size and in the colour
the hand-drawn one had, and `src/ui/components/icons` no longer exists.
U07 now names no hand-drawn icon, so the tree catches up with the rule.

## Risks and decisions
**`:size` on each icon, not a Tailwind size class.** The tree's one sized
Lucide icon, `IsbnView`'s cross, says `:size="22"`, and the prop writes
the `svg`'s own `width` and `height`. Rejected: keeping `size-8` /
`size-5.5` over Lucide's 24 (the element would say two sizes); a default
size in `LUCIDE_CONTEXT` (resizes the six icons already Lucide's).

**`shrink-0` on every replacement.** Each hand-drawn root carried it, and
most of these icons sit in a flex row beside a sentence that may wrap (the
messages, the card's rows). Keeping it is what "the same size" means on a
narrow screen; jsdom lays nothing out, so the *Done* checks it. Rejected:
adding it only where a flex row is read today (a judgement per site, for
no saving).

**One step per spec file, the deletion as the red of untested sites.** The
task rewrites existing cases; the cases of one file about one icon go red
from one import and green from one template change, so splitting them
would make steps with no code between. Where no case finds an icon,
deleting its file is the red the existing specs give. Rejected: new cases
for those sites (widens the suites in a task that changes no behaviour).

**The card's cover stand-in stays at 48.** U06 draws it at 48; U07's list
now says 22 for "the stand-in of a missing cover", which reads as the rows'
(`CatalogueRow`, `SeriesRow`, the origin of that phrase in `PROPOSED.md`).
The task line asks for the same size, so 48 stays; the PR body proposes
U07 say "the stand-in of a row's missing cover". Rejected: 22 on the card
(contradicts U06 and the task line).
