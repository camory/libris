## Risks and decisions
**The composable knows loading and empty alone.** No case of this task
shows a series or a failure, so `listed` arrives with T097 and
`unavailable` with T098, each red first there; until T097 any answer reads
empty, on an address no link reaches before T099. Rejected: `listed` and
`unavailable` now (states no test of this task motivates).

**`/catalogue` becomes a parent, the tab a custom slot.** vue-router marks
a link active on a child of its route's parent, which is how *Accueil* is
current on a bookshelf; the *Catalogue* tab then takes the same slot.
Rejected: a flat `/catalogue/series` route (a sibling route is never
active for the tab). Rejected: a path-prefix check in the tab (a rule the
router already answers).

**The series view repeats the header.** It reads `catalogue.title` and
`catalogue.hint`, the four lines of `CatalogueView`'s header, so the header
is the catalogue's word for word. Rejected: a shared header component (it
changes `CatalogueView`, which this task leaves untouched).

**A skeleton of its own.** `SeriesRowSkeleton` draws the series row's
silhouette, a 48 × 74 cover and two lines (mockup *2-loading*), as
`BookshelfRowSkeleton` and `MemberRowSkeleton` draw theirs. Rejected:
`CatalogueRowSkeleton` (four lines, an ouvrage's row).

**The words.** A `series` block in the catalogue, one block per view as
`home`, `bookshelf` and `catalogue`; `series.empty` holds the sentence.
Rejected: `catalogue.series.empty` (`catalogue.series` holds the overline
of an ouvrage's series per kind).

**The client checks the status.** Every list client of the tree,
`FetchReadersApi.known()` and `FetchBookshelvesApi.memberships()`, throws
*The … answered <status>* on anything but `200`, with a case over a stubbed
`fetch`; `FetchSeriesApi` does the same. Rejected: no check, as T079's
brief once said (the tree has since settled the other way).

**The port joins `LibrisPorts` before the view uses it.** Step 4 comes
before the view injects the port, so no app-level test meets a missing
key; `open()` changes as in T046 and T079. Rejected: providing it beside
`createLibrisApp` in `open()` (the scenario then tests a wiring `bootstrap`
does not have).

**The kind matcher stays in the client's spec.** `src/fixture` holds
`aKind` but no nullable kind; the spec writes its own `toSatisfy`.
Rejected: a new fixture shape (`src/fixture` is the precondition's, kept
unchanged).

**S5 un-skipped as a guard.** By step 11 it passes, so it comes last, as
in T079. Rejected: un-skipping it first, red for ten commits.
