# T023 — The ISBN in one class, both writings

**Backlog line:** Both sides: the ISBN, one class for both writings. The PRD
calls it an ISBN: `Isbn13` becomes `Isbn` on both sides, the value being the
thirteen digits, and holds every rule of the identifier: made from either
writing, the thirteen digits or the old ten ending in a digit or X, separators
dropped, each writing checked with its own rule; the thirteen digits exposed;
the ten, for 978 alone, derived with its own check digit. The frontend's
`isbn13Of` moves into it. The API admits thirteen digits alone, as the
contract's pattern says: the controller keeps that check and answers
`400_NOT_AN_ISBN` to a ten; no contract edit. Unit tests on both sides over the
writings and the refusals, the existing ones kept; nothing else changes
behaviour. Realises the rule of S3 again; un-skips nothing.

**Serves:** spec `fast-entry` — the rule of `S3 Not an ISBN` ("unit test of the
ISBN rule: thirteen digits kept, ten converted, check digit verified,
separators dropped") and the *Contract* section's "thirteen digits; the client
turns the typed text or the barcode into the ISBN-13 first"; PRD §3, the
glossary's word and the rule "An Edition may have one ISBN, stored as the
thirteen digits of its ISBN-13, which is what the EAN-13 barcode on the book
carries. An ISBN-10 typed by hand is converted on entry"; decisions D01, D02,
D04, D05, D07, D10, D11. No rule of `docs/DESIGN.md` is in play: no screen, no
word and no component changes.

**First of its kind:** the first value object of the frontend `domain` — every
module there is a type (`Reader`, `SourceEdition`) or a pure function
(`isbn13Of`), none is a class — so this task sets the shape every later
frontend value will copy: `export class Isbn`, a private constructor, a
`readonly digits`, and a static factory `Isbn.of(text): Isbn | null` that
answers the value or a refusal, mirroring the backend's `Isbn.of`. With it
comes the backend's first value type with two factories, one per writing it
admits (`of` for what a reader types or a barcode carries, `ofThirteenDigits`
for what the API's path admits), which is how the API's own check stays a rule
of the identifier rather than a regex in a controller. It is also the first
task to rename a name `docs/ARCHITECTURE.md` cites by name (D02 lists
`Isbn13` among what lives at the root of `domain`): the run does not edit the
document, it proposes the one-word amendment in the pull request body
(CLAUDE.md). The reviewer repeats this line in its verdict and Tophe settles
these conventions on the pull request, amending `docs/ARCHITECTURE.md` with
what the review decides.

## Goal
When this task is done, one class on each side carries every rule of the
identifier the PRD calls an ISBN — both writings in, the thirteen digits out —
and no code outside it knows what an ISBN looks like: the view, the barcode
adapter, the BnF source and the controller all ask the class. It matters now
because the same rule lives twice in two shapes that already disagree (the
backend accepts any thirteen digits whose check digit is right, the frontend
only a `978`/`979` one, and only the frontend knows the old ten), and every
later feature that takes an ISBN — the hand-typed entry of PRD §3, the import,
the search — would copy whichever half it met first.

## Risks and decisions
- **The second factory is `Isbn.ofThirteenDigits`, decided here.** The task
  line says the API admits thirteen digits alone and the controller keeps that
  check; making the check a second factory of the value type keeps every rule
  about what an ISBN looks like in the one class (the point of the task) and
  leaves the controller a one-liner, while a regex or a length test in
  `infra.web` would be the rule leaking back out. The name says what it
  admits; a shorter `ofDigits` says less. Rejected: `Isbn.of(text)?.takeIf {
  it.digits == text }` in the controller — correct, but it hides the API's
  rule in a comparison nothing names.
- **The Bookland prefix becomes a rule of both factories, decided here.** The
  backend accepts any thirteen digits with a right check digit today, the
  frontend only `978`/`979`; one class cannot hold both answers. The
  frontend's is the one that stands: the contract's path pattern is
  `^97[89][0-9]{10}$`, the PRD ties the ISBN to the EAN-13 barcode on the
  book, and S2 reads only codes starting with 978 or 979. The visible change
  is that `GET /api/v1/isbn/4006381333931` now answers `400` instead of
  looking the code up at the BnF — an answer the contract never described,
  for a request its pattern excludes, which is why the backlog line can still
  say nothing else changes behaviour. It is asserted in `IsbnTest` and in
  `IsbnControllerTest`.
- **The frontend `Isbn` has no `isbn10`, decided here.** The ten is derived
  for one caller, the BnF's CQL query (T021), which is backend code; adding it
  to the frontend would be a property no test and no feature of this task
  exercises, which CLAUDE.md forbids. Both sides *read* the ten writing, which
  is what "made from either writing" asks for; only the backend *derives* one.
  The day a frontend screen shows the ten, its task adds the property with the
  case that wants it — one bullet for `agent/PROPOSED.md`.
- **`SourceEdition.isbn13` becomes `isbn` on the backend, decided here.** The
  type no longer carries the thirteen in its name and every file holding that
  field is already being touched by the rename; the JSON field stays `isbn13`
  (D11 — a response field is never renamed), as does the frontend type that
  mirrors it. If this rename turns out to make the diff harder to read, drop
  it and say so in `agent/PROGRESS.md`: nothing else depends on it.
- **`docs/ARCHITECTURE.md` is not edited by this run.** D02 lists `Isbn13`
  among what lives at the root of `domain`; after this task that name is
  false, but the rule it states — the catalogue's own values live at the root,
  a concern's in a sub-package — is untouched, so the run proposes the wording
  in the pull request body and Tophe amends the document (CLAUDE.md). The same
  goes for the earlier briefs and `agent/PROGRESS.md` entries that name
  `Isbn13`: they are the diary of their day and are not rewritten.
- **The frontend class must stay nominal.** A TypeScript class whose only
  member is a public `digits` would be structurally interchangeable with
  `{ digits: string }`; the private constructor is what makes `Isbn` a type
  only `Isbn.of` can produce, which is the whole guarantee the view relies on.
  Do not export the constructor, and do not add a `toString`, a `valueOf` or

- **The web-slice test needs a reader.** The security chain authenticates

  types, or the slice fails to start.
