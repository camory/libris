## Goal
`author_name_unique` ignores case, accents and the spaces at a name's ends,
as `series_name_unique` does since `V014`, and `Contributions.of` matches
names the same way. *herge* followed by a space then lands on the stored
*Hergé*, whose spelling stays, before T144 onward lets the reader type
authors in the form.

## Rules in play
- D12 — the name's rule spans every author: the unique index is what
  keeps it, resolved inside `INSERT_AUTHOR`'s one statement; the
  repository links the edition to the id that statement answers. No lookup
  of a name before the insert, in Kotlin or SQL.
- D12 — `Contributions.of` keeps one contribution per author and role, the
  names matched ignoring case, accents and the spaces at their ends, the
  first spelling kept; the folding is private to `Contributions.kt`, no
  public member gained (D10), no other type folds an author's name.
- D02 — the schema changes through a Flyway SQL file; the statements stay
  hand-written SQL over `JdbcClient` in `JdbcEditionRepository`.
- D11 — the migration is `V015__author_name_ignoring_case_and_accents.sql`;
  `V003` and every merged migration stay byte for byte as they are; the
  contribution's primary key `(edition_id, author_id, role)` stays.
- D07 — the S5 method of `AuthorsEditScenarios` is un-skipped and nothing
  else in that file changes but its now unused `Disabled` import; the
  index is proven in the JDBC slice, the folding in `ContributionsTest`,
  plain JUnit; no web test, no contract change.
- D08 — the slice and scenario contexts migrate through `CleanSchema` as
  they do; nothing drops or recreates the database.
- D10 — SQL keywords and functions upper case (`BTRIM`, `COLLATE`, `ON
  CONFLICT`), identifiers snake_case; no rationale and no `D##` in code or
  SQL.

## Risks and decisions
**Fit.** One run: one migration of two statements, two SQL constants, one
domain function, five unit and slice cases, one un-skip; seven files and
three documents. Rejected: a task for the domain folding apart (the
backlog line puts both in T143, and neither needs the other's code).

**The index of `V014`, applied to authors.** The collation of `V005` under
`BTRIM`, as the series name: one matching of a name in the schema for the
whole house. Measured in the sandbox PostgreSQL on 2026-11-08, on a
temporary table with that index: `herge ` answers the stored *Hergé* row,
`Jo Nesbo` the stored *Jo Nesbø*, `René  Goscinny` (two inner spaces) and
`Akira Toriyama` followed by a tab rows of their own. Rejected: `unaccent`
(D03's search migration brings it, not this task); a lookup in Kotlin
before the insert (the rule out of the index and out of its one
statement, D12).

**A second folding, in `Contributions.kt`.** D12 gives `Contributions.of`
the per-author-and-role rule with the names matched as PRD §3 matches
them, so the domain folds too. The folding is `BookshelfName`'s (NFD,
marks dropped, lower case) plus the end spaces, private to the file.
Rejected: importing `BookshelfName`'s (`bibliography` never depends on
`library`, and it is private); moving it to a package both contexts see (a
shared kernel is a convention no document states: the PROPOSED item asks
it); `java.text.Collator` at `PRIMARY` (it ignores inner spaces, the index
does not, see the gotcha); `œ`/`æ` and other letters the index matches
(step 6 makes any gap harmless, so the folding stays at what S5 names).

**`ON CONFLICT DO NOTHING` on the contribution.** ICU's level 1 matches
more than any Kotlin folding does (`Ø` and `O`, measured above); two such
names of one role pass `Contributions.of` and meet one author id, and
without it the add fails on the primary key. S5 says Libris keeps one
should they reach it, so the insert keeps the first link. Rejected: a
Kotlin folding chasing ICU (never equal); reading the author ids before
the links (a second statement per name, for the same answer).

**Rows already stored.** The spec records that on 2026-11-08 no two
authors of staging or production matched so, so `V015` merges nothing.
Should a pair appear before the deploy, `CREATE UNIQUE INDEX` fails,
PostgreSQL rolls the migration back whole, the start is refused and the
previous tag runs on the untouched schema, as for `V014`. Rejected: a
merge in `V015` (which spelling stays is a product question no document
answers).
