# T009 — Reader on every request

**Backlog line:** Reader on every request. Starts with the contract, decided
with Tophe on 2026-09-09 (D04): `CurrentReader` gains `id`, `type: string`,
`format: uuid`, `nullable: false`, listed in `required`; the operation summary
becomes "The reader making the request: their profile and role"; nothing else
in `api/openapi.yaml` changes, and `ApiContractTest` going red on it is the
task's first red step. `application`: the visit use case — given the username,
email and display name of the request, find the reader by username or insert
them; the display name is seeded from the header on the first visit and then
owned by Libris (PRD 4.10); two simultaneous first visits end with one row.
`infra.web`: the filter calls the use case on every request and sets the
`Reader` entity as the principal of the authentication, with the authorities
mapped from `Remote-Groups`; the T005 principal class goes, controllers take
`@AuthenticationPrincipal` (D06). `/me` answers the stored reader plus the id,
the role derived from the authorities. The Contracteer setup truncates and
seeds before every case (D04). Tests: first visit inserts, the next visit
returns the stored reader and keeps the display name Libris owns, two
concurrent first visits, the filter with a stored reader, contract. The last
D02 ArchUnit rule: `application` depends only on `domain`.

**Serves:** PRD §4.10 (a reader exists in Libris from their first visit, and
Libris owns their display name afterwards); decisions D02 (the light hexagon
and its ArchUnit rules), D04 (contract first), D06 (Authelia forward-auth, the
`Reader` entity as principal, no custom principal class), D07 (the gates and
the test styles), D08 (the PostgreSQL of the environment), D11 (uuid v7 ids
from the constructor, ids as strings in JSON).

## Goal
After this task every authenticated request carries a stored `Reader`: the
filter turns the Authelia headers into a row in `reader` — found or inserted —
and puts that entity, with the authorities from `Remote-Groups`, in the
security context; `/me` answers the stored reader, id included. It matters now
because every later feature (loans, holds, the admin screens) needs a reader id
to hang rows on, and because the display name Libris owns (PRD 4.10) can only
exist once the reader is a row rather than a header.

## Risks and decisions
- **The pre-authenticated provider cannot carry the entity.**
  `PreAuthenticatedAuthenticationProvider.authenticate()` replaces the token's
  principal with whatever its `AuthenticationUserDetailsService` returns, i.e.
  a `UserDetails`, so a framework-free `Reader` can never survive it. D06 wants
  the entity as principal and no custom principal class, so the filter builds
  the `PreAuthenticatedAuthenticationToken` itself and there is no provider and
  no `AuthenticationManager` any more. Decision taken locally: the trust
  boundary, the headers, the role mapping and every refusal are unchanged —
  the seven `SecurityConfigTest` cases pin them. **The PR body must propose**
  rewording the D06 sentence that says the filter runs "via Spring Security's
  pre-authenticated header filter" (precedent: T005's PR asked the same way
  about the `dev` profile sentence).
- **`OncePerRequestFilter` skips the error dispatch by default.** With the
  default `shouldNotFilterErrorDispatch() = true` the Servlet ERROR dispatch to
  `/error` re-runs the security chain with no authentication and a 405 comes
  back as 403 (measured:
  `a write carrying the X-Requested-With header reaches the application`
  failed with `Status expected:<405 METHOD_NOT_ALLOWED> but was:<403
  FORBIDDEN>`). T005's filter was a `GenericFilterBean` and ran on every
  dispatch. Overriding it to `false` restores that behaviour. Do not "fix" this
  by relaxing a security rule.
- **A domain exception, not Spring's.** `application` may not see
  `org.springframework.dao.DuplicateKeyException` — that is exactly what the
  new ArchUnit rule forbids, and widening the rule would amend D02. So the
  adapter translates to `DuplicateUsernameException` in `domain` and the port
  stays framework-free.
- **No `@Transactional` on the visit.** Inside one transaction a constraint
  violation aborts it, and the find that follows fails too (measured: the retry
  select came back as
  `UncategorizedSQLException: … uncategorized SQLException for SQL [select id,
  username, email, display_name …]`). In production the filter runs outside any
  transaction, so each statement commits on its own and the catch-then-find
  fallback works. This is why the concurrency case is tested against fakes and
  not against PostgreSQL: a rolled-back Spring-level test cannot see another
  connection's uncommitted row, and D07 forbids running test classes in
  parallel.
- **The name `ReaderVisit` / `visit`** — the task line calls it "the visit use
  case" and `application` has no naming convention yet beyond D02 ("use
  cases"). Chosen locally: the class is the use case, one public method,
  no suffix (`…UseCase`, `…Service`) and no interface. If a document later
  fixes a suffix, one rename covers this class.
- **`MeControllerTest` must truncate before every case.** Once Libris owns the
  display name, `a reader without a display name is called by their username`
  depends on what earlier cases stored (it observed `Juliette` where it wanted
  `juliette`). Truncating is the HTTP-level rule of D07 anyway.
- **The ArchUnit rule lists no transaction package.** The allowed packages are
  `java..`, `kotlin..`, `org.jetbrains.annotations..`,
  `org.springframework.stereotype..`, `..domain..`, `..application..`.
  `org.springframework.transaction.annotation..` was deliberately left out:
  nothing uses `@Transactional`, and D02 allows it only when a use case needs
  it. Add it in the task that first needs it, not here.
- **The YAML summary must be quoted.** `The reader making the request: their
  profile and role` contains a colon; unquoted it is not valid YAML.
- **Never chain a file write and a gate in one Bash call.** The sandbox hook
  refuses the whole call — including the heredoc that was writing a test — and
  the next run then measures a stale tree. Write files, then run the gate as
  the last thing in its own call.
- **Measured shape of the finished task:** eleven files touched, 25 tests,
  detekt clean, no new dependency; a full `test detekt koverXmlReport` run took
  about a minute warm.
