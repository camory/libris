## Goal
`GET /api/v1/series-names` and `GET /api/v1/author-names` answer only the
names some edition of the house carries, so that a name left behind by a
save (T154) is no longer suggested. The name rows stay: nothing is deleted.

## Rules in play
- D02 — the new port sits in `bibliography.domain.series`, its adapter in
  `bibliography.infrastructure.persistence`; `ListSeriesNames` depends on
  `domain` only; nothing in `library` or `web` changes.
- D07 — the one `@Disabled` line of S6 is removed and nothing else in
  `HeldEditionEditScenarios` changes; reads proven in the JDBC slice
  against PostgreSQL, the use case in plain JUnit over fakes; no test of a
  controller; `ApiContractTest`'s `tests=` unchanged from `main`.
- D10 — a query port has no `Repository` suffix and is named by what it
  answers (`CarriedSeries`), its read `findAll()` as `AuthorNames`'; the
  use case exposes `operator fun invoke` alone; SQL keywords upper case;
  fixtures below the class; no rationale and no `D##` in code.
- D11 — a complete list in no promised order: no `ORDER BY`; each name
  once.
- D12 — a repository joins no other aggregate: `JdbcSeriesRepository`
  gains no join; a read that answers a series' name reads it through
  `SeriesRepository` (`findByIds`); only the ids no repository can serve
  in a few queries come from a query port, built from one statement; name
  rows are never deleted, and `findOrInsert` keeps landing on them.
- PRD §3 — a name typed again lands on the kept row under its spelling:
  the unique indexes already decide it (`JdbcSeriesRepositoryTest`'s three
  *a name the house holds* cases, T154's S5 *another series* and *another
  author*); nothing changes there.

## Risks and decisions
**Fit.** One run: no migration, dependency or contract change; two
statements, one port, one use case's constructor, each mirroring code the
tree has. Rejected: a split by name (two tasks for one scenario).

**The authors: `JdbcAuthorNames`' statement changes, the port keeps its
name.** An author exists for the domain only as a `Contribution` of an
edition (D12); the author row is persistence's. So "every author name" is
the carried ones, and `AuthorNames.findAll` stays true. Rejected: a
renamed port (a diff through the use case and its fake for no new
meaning).

**The series: a query port answering ids, the names read through
`SeriesRepository`.** A series is an aggregate kept when no edition is in
it, so `SeriesRepository.findAll` cannot narrow without lying, and its
adapter may not join `edition` (D12: a repository joins no other
aggregate). Which series some edition carries is a read no repository
serves in a few queries (it would read every edition), hence a query port
in the concern's sub-package, `bibliography.domain.series`, answering
`Set<SeriesId>` as `CatalogueEditions.findFirstOfEachSeries` answers
`Set<EditionId>`; the names then come through `SeriesRepository.findByIds`,
as D12 asks of a read answering a series' name. Named after the spec's
word, *carries*. Rejected: a `SeriesNames` port answering the names in one
statement (a series' name read outside `SeriesRepository`). Rejected: an
`EditionRepository` method (a repository answers its aggregate, and
`JdbcEditionRepository` sits at detekt's `TooManyFunctions` threshold).
Rejected: `SeriesInUse` (not the spec's word).

**`SeriesRepository.findAll` removed.** `ListSeriesNames` was its one
caller; a port method nothing calls is code no feature exercises.
Rejected: keeping it for a later reader.
