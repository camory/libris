**Serves:** spec `fast-entry` — the cover of S1, the one source of S4 and S7;
PRD §3 (cover, source); decisions D02, D04, D07, D08, D10, D11
**First of its kind:** the first task that retires an adapter and a domain rule
instead of adding one — `OpenLibrarySource` and `Merge` are deleted with their
tests, their recordings and their configuration, and the scenario class loses
two methods. Two smaller firsts ride along: the first UNIMARC **controlfield**
read (003, until now only datafields were parsed), and the first derived form
of an ISBN in `domain` (the ten a 978 ISBN converts to).

## Goal
When this task is done the backend has one source, the BnF, and every edition
it answers carries the catalogue's own cover URL; the merge rule, the Open
Library adapter and the second WireMock of the scenario harness are gone. It
matters now because the spec was rewritten around the single source
(`docs: the BnF alone, with its cover`), because a record made before 2007 is
invisible to Libris until the BnF is asked with the ten digits too, and because
T022 needs a `coverUrl` that is sometimes a picture and sometimes a 404 to show
its stand-in against.

## Rules in play
- D02 — `domain.lookup` keeps the port and what a source answers; the merge
  rule leaves with the second source, so `domain/lookup/Merge.kt` is deleted,
  not kept unused.
- D02 — `domain` is framework-free: the ten a 978 ISBN converts to is an ISBN
  rule, so it lives on `Isbn13` in `domain`, with no framework type and no
  annotation.
- D02 — the port's contract on time does not change: the bound is the
  adapter's, the use case never sees time, a BnF answering past
  `LIBRIS_SOURCE_TIMEOUT` is `Failed`.
- D02 — `infra.lookup` holds the BnF client alone; `infra.*` never depends on
  another `infra.*`, and the ArchUnit rules run inside `check`.
- D04 — contract first, and this task makes no contract edit: the backend stays
  pinned to `v0.3.0`, `Source.OPEN_LIBRARY` stays in the enum because the
  document still declares it, and `ApiContractTest` is not touched.
- D07 — the gate for this task is `cd backend && ./gradlew check`, run plainly
  and last in its command; nothing on the frontend changes, so `npm test` is
  not this task's gate.
- D07 — each layer is tested in isolation: `application` over fakes of its
  ports (`SourceAnswering`), `infra.lookup` against WireMock over the recorded
  answers, shared doubles in the `fixture` package, tests beside the code.
- D07 — the Contracteer test proves structure and types, never values, over
  stubs that mirror the document's examples; the released `ONE_PIECE_1` example
  still names the Open Library cover and both sources, so `ApiContractTest`
  keeps its stub exactly as it is.
- D07 — one scenario method per scenario or case, bearing the scenario's exact
  title, asserting the exact values the spec names. The spec now has no S5 and
  no S6 and titles S7 *The source down*; the backlog line, written out of that
  spec conversation, names the edits `FastEntryScenarios` takes. Those edits
  and nothing else land in the class, and no method is un-skipped.
- D07 — one test boots the whole application: `LibrisApplicationTest` follows
  the properties and the wiring that change here.
- D08 — the environment is given: the only BnF a test talks to is the recorded
  answers under `src/test/resources/scenarios/bnf`.
- D10 — Kotlin official style, immutable by default, no `!!`, no `lateinit`,
  a member imported and not qualified; Conventional Commits with the `backend`
  scope and the `Co-Authored-By` trailer; branch `task/T021-bnf-alone`.
- D11 — an absent optional value is serialised as `null`: a record whose field
  003 is missing or holds no `ark:/` answers `coverUrl: null`, never an empty
  string.
- D11 — the API shapes do not move: `LookupResult.Found` keeps its list of
  sources, so the response still carries `sources` as an array.
- CLAUDE.md — no rationale in code and no D## or U## number in code, tests,

## Risks and decisions
- **One request, not two.** The BnF is asked once, with a CQL `or`:
  `bib.isbn all "<thirteen>" or bib.isbn all "<ten>"`. Measured against
  `https://catalogue.bnf.fr/api/SRU` on 2026-09-14: the One Piece record comes
  back whole for the `or` query, and `9782253098058` answers one record for
  `… or bib.isbn all "2253098051"` where the thirteen digits alone answer zero.
  Two requests would spend two timeouts and break the port's promise to answer
  inside one; `maximumRecords=1` still takes a single record.
- **Where the ten lives.** On `Isbn13` in `domain`, not in the adapter: it is a
  rule about the ISBN, framework-free and unit-testable, and it mirrors where
  the frontend keeps its own conversion (T016). It answers nothing when the
  digits do not start with 978, since only a 978 ISBN has a ten-digit form.
  The check digit is the mod-11 one, weights 10 down to 2, `X` when the
  remainder is 1 — `9780804429573` → `080442957X` proves that branch.
- **The use case takes one source, not a list of one.** `IsbnLookup` receives a
  single `IsbnSource`; `LookupResult.Found` keeps its `sources` list so the
  controller, the response DTO and the contract do not move. A list of one
  would keep the shape of a merge that no longer exists.
- **The bean keeps its name.** `LookupConfig.bnfSource` stays `bnfSource` and
  simply loses `@Order`; a bean of `infra.lookup` may not be named `bnf`,
  the scenario harness owns that name (`agent/GOTCHAS.md`).
- **How the cover is built.** A function beside `authorRoleOf` turns field 003
  into the URL, so it can be tested directly the way the role mapping is, and
  no third recording is invented for the arkless case. The ark is the control
  field from `ark:/` on; the URL is
  `https://catalogue.bnf.fr/couverture?&appName=NE&idArk=<ark>&couverture=1`,
  the two ampersands included, as the spec writes it. The parser, which reads
  `datafield` elements today, must also collect `controlfield` elements.
- **The scenario class is edited, which D07 normally forbids.** The spec
  conversation already happened — `docs: the BnF alone, with its cover` (#73)
  and `docs: the BnF is asked with the ten as well` (#76) — and the backlog
  line names the edits, so they are the task's: S5 and S6 go, the
  past-the-timeout case moves under S7, and S1 follows the one source. The
  rename of `S7 Every source down` to `S7 The source down` is not a new
  convention: D07 asks for the scenario's exact title and the spec now writes
  that one; the number is kept, as the spec conversation decided. Nothing else
  in the class changes.
- **The contract example and the answer now differ.** The pinned `v0.3.0`
  `ONE_PIECE_1` still carries
  `https://covers.openlibrary.org/b/isbn/9782723488525-L.jpg` and
  `["BNF","OPEN_LIBRARY"]` — checked against the pinned document on 2026-09-14
  — while the application answers the catalogue's cover and `["BNF"]`. The
  Contracteer test proves structure and types, never values, so it stays green
  untouched. Write a follow-up in `agent/PROPOSED.md`: the next release of
  `camory/libris-api` should give `ONE_PIECE_1` the catalogue's cover and the
  single source.
- **The hand check of the phase.** *Done* asks Tophe to type an ISBN-10 by hand
  and read its card. `9782253098058` / `2253098051` is found by the ten, but
  its record comes back as a diagnostic with no fields in `unimarcxchange`
  (measured 2026-09-14), so Libris answers "unknown ISBN" for it. Note in the
  PR body that the hand check needs a pre-2007 book whose UNIMARC record the
  BnF serves; this task changes nothing about that.
- **Traps to expect** (`agent/GOTCHAS.md`): run `./gradlew detekt` before each
  commit — `ReturnCount` allows two returns, `ImportOrdering` is lexicographic,
  and a constructor argument left unused after `SourcesProperties` shrinks
  trips `UnusedPrivateProperty`. Keep `BnfSourceTest`'s `@BeforeAll` warm-up
  and its long timeout, and keep a real recorded answer behind the delay of
  `answersTooLate`.
