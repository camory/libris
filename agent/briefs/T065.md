# T065 — The house keeps a cover

**Backlog line:**
> - [ ] T065 Backend: the house keeps a cover.
>       The covers' store writes a picture under a name made from its bytes,
>       its media type beside it, as `FindCover` reads them; an edition records
>       the name of its stored cover; the catalogue answers `coverUrl`, the
>       cover operation's address, null while none is stored (D11, D12). The
>       edition's former `coverUrl` and its `cover_url` column, a source's
>       address that nothing reads any more, leave in the same migration. Tests
>       of the store over a temporary directory, of the JDBC slice and of the
>       catalogue's web slice; no fetch, no worker; un-skips nothing.

**Serves:** spec `covers` S4 (second and third *Then*: "stores it … under a
name made from its bytes", "the catalogue answers the edition with its
cover's address"), S5 (the media type saved beside the picture, in
`<name>.type`), S11 (the catalogue's `coverUrl`), its Contract section
(`Book.coverUrl`, the cover operation's `name`); PRD §3, §4.7; decisions
D02, D04, D07, D10, D11, D12
**First of its kind:** the first adapter that writes files
(`FileCoverStore.write`), and the first migration that drops a column
holding production rows (`edition.cover_url`).

## Goal
Libris can store a picture in its covers directory under the SHA-256 of its
bytes, an edition holds the name of its stored cover, and the catalogue
answers that cover's address. The worker of T066 then only has to fetch,
write and record; the source's address the edition kept until T051 goes.

## Rules in play
- D02 — `Cover` and `CoverStore` stay in `bibliography.domain.cover`,
  `FileCoverStore` in `bibliography.infrastructure.persistence`;
  `CatalogueController` (`library.infrastructure.web`) reads the edition's
  `CoverName` and depends on no class of `bibliography.infrastructure.web`
- D04 — the pin stays `v0.8.2`, no contract edit; `Book.coverUrl` is the
  relative address of the cover operation, `/api/v1/covers/<name>`, as the
  contract's example `OnePiece2Owned` writes it
- D07 — the domain rule in a unit test; the store over a `@TempDir`; the
  JDBC slice from a schema cleaned and migrated by Flyway, so it migrates
  `V007`; the web-slice case exists because the backlog line asks for it and
  the schema cannot say which address; no scenario test un-skipped or
  edited; every case of two or more statements carries the Given / When /
  Then markers
- D10 — the edition's field is `coverName`; the port keeps a verb of its
  own, `write`, beside `read`; no visibility widened; SQL keywords upper
  case; Kotlin layout kept by hand (`=` bodies on the next line, last
  parameter and `)` on one line)
- D11 — `V007__edition_cover_name.sql`, never edited once merged; the name
  is a nullable `text` column, not unique (two editions may share a
  picture); the dropped column's values are lost, as the backlog line says
- D12 — the rule that names a cover lives on `Cover`, which holds the
  bytes; the edition holds a `CoverName` value, never a `Cover`; a row read
  back passes its name through `CoverName`'s constructor

## Test plan
One step is one case is one commit; `./gradlew detekt` before each commit;
a step is committed before its guard's mutation is checked. A step marked
red that is green on arrival becomes a guard: its commit body names the
mutation that reds it, checked and reverted, and the PR body lists it.

1. **red then green — a cover is named by its bytes.** `CoverTest`:
   `Cover("image/png", "test".encodeToByteArray()).name` is
   `CoverName("9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08")`,
   the name the contract's example uses. Creates `Cover.name: CoverName`,
   public, read-only.
2. **guard — a hash beginning with zeros keeps its zeros.** `CoverTest`:
   the bytes of `"cover 59"` are named
   `005cbc1fbb9398468b932b0a7417723d1134b4cad70831f5587e236583f1a458`.
   Mutation: format the digest with `BigInteger(1, digest).toString(16)`;
   the name is then 62 digits and `CoverName`'s constructor throws. If
   step 1's code is that mutation, this step is red first.
3. **red then green — a written cover is read back.** `FileCoverStoreTest`:
   a `Cover` of `image/webp` over `recordedBytes("covers/small.webp")`,
   written with `write(cover)`, is answered by `read(cover.name)` with that
   media type and those bytes. Creates `CoverStore.write(cover: Cover)`,
   answering nothing, and `FileCoverStore.write`: the picture in the file
   named by `cover.name.value`, then the media type as the text of
   `<name>.type`, the layout the existing read cases fix.
4. **guard — a cover written twice is still that cover.**
   `FileCoverStoreTest`: the same cover written twice is read back with its
   media type and bytes. Mutation: write the picture with
   `StandardOpenOption.CREATE_NEW` (`FileAlreadyExistsException`).
5. **red then green — the edition records its cover's name.**
   `JdbcEditionRepositoryTest`: `onePieceTomeOne()` carries
   `coverName = CoverName(…)` (any 64-digit name) in place of its
   `coverUrl`; *an inserted edition is read back whole by its ISBN-13*
   reds. Creates `Edition.coverName: CoverName?` in place of `coverUrl`,
   last parameter, no default; every `Edition(...)` of the tree passes
   `coverName = null` (listed below); `V007__edition_cover_name.sql`
   (`ALTER TABLE edition DROP COLUMN cover_url;` then `ALTER TABLE edition
   ADD COLUMN cover_name text;`); `INSERT_EDITION` and `SELECT_EDITIONS`
   write `coverName?.value` and read it back through `CoverName`. The first
   red is a compile error; read the behavioural red too, by having the
   repository read `null`: `data class diff … Edition`, then revert.
   Removing `coverUrl` has no red of its own: nothing reads it since T052.
6. **guard — no cover is read back as none.** `JdbcEditionRepositoryTest`:
   `bare()` takes `coverName = null`; *an edition whose optional fields are
   all absent is read back whole* stays green. Mutation: read the column
   with `CoverName(rs.getString("cover_name"))`, no null check.
7. **red then green — the catalogue answers the stored cover's address.**
   `CatalogueControllerTest`, new case *a held edition with a stored cover
   is answered with its address*: `ROMANCE_DAWN` with a `coverName`
   answers `coverUrl` `"/api/v1/covers/<that name>"`. Creates the mapping
   in `CatalogueController.bookOf`; the address is built there, from the
   name's `value`.
8. **guard — no stored cover is answered as null.** The existing case
   *a held edition is answered with no cover while none is stored*,
   `ROMANCE_DAWN` with `coverName = null` since step 5, unedited.
   Mutation: build the address as `"/api/v1/covers/${held.edition.coverName?.value}"`
   (answers `/api/v1/covers/null`). No commit of its own; listed in the PR
   body.
9. **Tidy on green**, the gate run plainly, then the documents: the task
   line ticked, a `PROGRESS.md` entry, the PR, its body naming the guards'
   mutations and the first-of-its-kind line.

**GOTCHAS.md:** the backend-tests item *A cover is the file named by its

## Risks and decisions
**The name is `Cover.name`, the SHA-256 of the bytes.** The cover holds the
bytes, so it answers its own name (D12), and the store, the worker and any
test read the same rule; 64 lower-case hexadecimal digits is what
`CoverName` and the contract's pattern accept, and the contract's example
name is the SHA-256 of `test`. `java.security` is a JDK library, which the
domain rule of `ArchitectureTest` allows. *Rejected:* hashing in
`FileCoverStore`, which hides the rule in an adapter and makes the worker
ask the store for the name; `CoverName.of(bytes)`, an `of` that would
answer `null` for nothing.

**`write(cover)` answers nothing.** The caller already has `cover.name`.
*Rejected:* answering the `CoverName`, a second way to the same value.

**The picture before its media type, overwrite allowed.** `read` answers a
cover only when both files are there, so writing the `.type` last means a
half-stored cover is no cover; two editions can carry the same picture, so
a second write of one name, the same bytes, must not fail (step 4).
*Rejected:* refusing an existing name, which would fail the second
edition's fetch.

**The address is built in `CatalogueController`.** It is the web edge's
knowledge of the cover operation's path, and D02 forbids
`library.infrastructure.web` to reach `CoverController`; the path is
written a second time there. *Rejected:* a shared constant in
`shared.infrastructure.web`, which names a bibliography operation in a
package that knows no context; a helper for T055, which has no caller
yet.

**The edition holds the name, written by `insert` only.** S4 has the
catalogue answer the edition with its cover, and `BrowseCatalogue` reads
editions through `findByIds`, so the name on `Edition` reaches the answer
with no change to the use case. Recording a name on a stored edition needs
a write the port does not have; its shape belongs to T066, its first
caller. *Rejected:* an `update` on `EditionRepository` now, with no caller
in this task.

**`cover_url` is dropped, its values lost.** The backlog line orders it:
the column holds sources' addresses that nothing has read since T052, and
T057 asks the sources again by ISBN. *Rejected:* keeping it until T057,
dead data in every edition read.
