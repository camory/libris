# T018 — The card of the answer

**Backlog line:** Frontend: the card of the answer. A presentational component
showing what the sources know: subtitle, authors with the French word of their
role, série and tome, collection, publisher, year, the language in French, page
count, the ISBN-13, the summary, the cover image, and the sources as `BnF` and
`Open Library` (D05, PRD §3). A field the sources did not give shows nothing at
all. Component tests over its props, the view shows it on a found ISBN.
Realises S1 on the frontend; un-skips `S1 Typed ISBN, found, with hyphens` and
`S1 Typed ISBN, found, the old ten`.

**Serves:** spec `fast-entry` — S1 on the frontend and the *Screen* section's
Found state (and its Searching state, see *Risks*); PRD §4.7, §3 (*ouvrage*,
*série*, *tome*, *collection*, *auteur*, a role as the activity: scénario,
dessin, couleurs, traduction; the *Avoid* lists); decisions D05 (the layers, a
component is presentational and takes props), D07 (`npm test` is the gate, a
component test mounts with props and asserts the rendered text, never a tag or
a class, a scenario is un-skipped and never edited), D10 (strict TypeScript,
identifiers in English, UI text in French, Conventional Commits), D11 (the API
sends keys, the frontend owns the wording); rules U01, U02, U03, U05, U06 and
U08 of `docs/DESIGN.md`.

**First of its kind:** the first card and the first chips of U06 — and with
them the first `ui/components` component that takes a domain value as a prop,
the first `<img>` the application renders, the first skeleton of U05, the first
shared sample value in `src/fixture` (`SourceEditions.ts`, beside the fakes of
the ports), and the first `fr` catalogue sections that are not a screen's
wording but the words for the codes the API answers (`role`, `language`,
`source`, keyed by the code, U06). What this task chooses for the card's parts,
for those sections and for the skeleton is what every later screen showing an
ouvrage will copy: the reviewer repeats this line in its verdict and Tophe
settles the conventions on the pull request, amending `docs/DESIGN.md` with
what the review decides.

## Goal
When this task is done, a reader who types an ISBN the sources know reads the
whole card of the mockup: the cover, *One piece · tome 1* over *Romance dawn*,
its subtitle, *Eiichirō Oda · scénario, dessin*, the rows *Collection*,
*Éditeur*, *Année*, *Langue*, *Pages* and *ISBN*, the summary when there is
one, and the chips *BnF* and *Open Library* — and a field no source gave simply
has no row. It matters now because S1 is the scenario the whole feature exists
for: the two `S1` methods are the last skipped ones of the typed path, and the
phone check of the spec's *Done* ("scan a manga and a BD and read both cards,
sources included") is a check of this card.

## Rules in play
- **D05** — the card is a presentational component under `src/ui/components`:
  props in, nothing out, no API call; it may import `domain` and nothing else
  of the application (`eslint-plugin-boundaries` is the proof and
  `eslint.config.ts` is not touched). The view of `ui/views/isbn` imports it.
  Tailwind CSS only, hand-written, mobile first.
- **D07** — `cd frontend && npm test` is the gate; a component test mounts it
  with props and the real i18n and asserts the rendered text, never a tag, a
  class, a colour or a pixel; every body is `// Given`, `// When`, `// Then`
  unless it is a single statement; the two scenario methods the backlog line
  names lose their `.skip` and nothing else in
  `src/scenario/FastEntryScenarios.spec.ts` changes; shared test values live in
  `src/fixture`.
- **D10** — TypeScript strict, ESLint and Prettier, identifiers and code in
  English, UI text in French, Conventional Commits with the scope `frontend`,
  branch `task/T018-answer-card`, the trailer on every commit.
- **D11** — the API sends keys and the frontend owns the wording: `WRITER`,
  `BNF`, `fr` are keys, and the French words for them live in the `fr`
  catalogue; absent optional values arrive as `null`, never omitted, and are
  what "the sources did not give" means.
- **U01** — the card names colour roles only (`bg-surface`, `text-muted`,
  `text-accent`, `border-border`): no slate, teal or red shade in a template.
  The roles are already declared in `src/ui/style.css`.
- **U02** — the steps this card uses: overline 12/semibold uppercase tracked in
  `accent` for *série · tome*, card title 20/bold for the title, lead
  15/regular for the subtitle, body 14/regular for the author lines, the rows
  and the summary, label 13/semibold for the row labels, the word *Sources* and
  the chips. `overline` and `lead` are the two steps this task adds to
  `style.css`; no size between the steps, none written in a class.
- **U03** — the card is a block of the content, 20 below the button; 14 between
  its parts, 16 of padding, radius 14.
- **U05** — one answer at a time in the place the answer will take: the card
  replaces a message and a message replaces the card (already true of the
  view). While the lookup runs, the grey silhouette of the card stands where
  the card will appear, at the size it will take, no animation, and leaves with
  the busy button.
- **U06** — the card: `surface`, a 1 px `border`, radius 14, 16 of padding, its
  parts 14 apart. Top part side by side — the cover 96 by 149, radius 6, a
  `border` block behind it while it loads or when there is none, never
  stretched; at its right, 6 apart, the overline, the title, the subtitle in
  `lead` `muted`, then one line per author, the name in `text` and its roles
  after a middle dot in `muted`. Middle part — one row per field, the label
  left in `muted`, the value right in `text`, 7 of vertical padding, a `border`
  hairline above each row, in the order *Collection*, *Éditeur*, *Année*,
  *Langue*, *Pages*, *ISBN*; a field with no value has no row and the card
  never says *inconnu*. Then the summary when there is one, as a paragraph in
  `body`. Bottom part — the word *Sources* in `label` `muted`, then one chip
  per source: a word in a pill, 1 px `border`, radius 999, 4 by 10 of padding,
  no background, never a button, wrapping 8 apart. The card decides nothing
  about what it is given, and the words it shows for a role or a language come
  from the `fr` catalogue, keyed by the code the API answers.
- **U07** — no icon is added by this task; the cover is an `<img>`, not an
  icon, and it carries an `alt` that names the ouvrage.
- **U08** — every word comes from the `fr` catalogue and no component holds a
  French string; the roles are the activity (*scénario*, *dessin*, *couleurs*,
  *traduction*, PRD §3); proper names keep their spelling (*BnF*,
  *Open Library*, *Eiichirō Oda*) and a title is shown as the source gives it;
  the middle dot ` · ` joins two facts on one line.

## Risks and decisions
- **The component is `SourceEditionCard`, decided here.** It is named after the
  value it shows, `SourceEdition` — what the sources know, which is not yet an
  `Edition` of the catalogue (PRD §3) — and it sits flat under
  `src/ui/components` beside `AppFooter.vue`, its spec next to it (D07). The
  alternative, `EditionCard`, would claim the name of the aggregate the
  *ajouter* feature will store.
- **The words for the API's codes are three catalogue sections keyed by the
  code, decided here:** `role.WRITER` … `role.TRANSLATOR` (*scénario*,
  *dessin*, *couleurs*, *traduction*, PRD §3), `source.BNF` and
  `source.OPEN_LIBRARY` (*BnF*, *Open Library*), `language.fr` (*français*).
  U06 says the words come from the `fr` catalogue keyed by the code; the
  sections sit beside `home` and `isbn` rather than inside `isbn`, because they
  are the household's vocabulary and every later screen showing an ouvrage
  needs the same words. The proper names go through the catalogue like the
  rest, so that no component holds a display string (U08). This is part of the
  *First of its kind* line.
- **A language the catalogue does not know shows its code, decided here.** The
  contract allows any ISO 639-1 code and the backend's map holds one entry
  today (`agent/PROPOSED.md`), so a code with no French word will arrive; the
  row then shows `en` rather than `language.en`, which is D11's rule that the
  frontend falls back when it does not know a key. Use `te()` from `useI18n()`
  for the test. Only the codes a case exercises are added to the catalogue —
  `fr`, and nothing else.
- **Only the language needs that fallback, decided here.** `role` and `source`
  are closed enumerations of the contract and of `domain/SourceEdition.ts`, so
  TypeScript makes a missing word a compile-time matter; a runtime fallback
  there would be code no test can reach.
- **An author appears once, with all their roles, decided here.** The API
  sends one entry per role (PRD §3: an author who wrote and drew has two
  links) and U06 asks for "one line per author … and its roles": the card
  groups by name, keeps the order the API sent, and joins the roles with
  `", "`. The separators are punctuation, not wording: the middle dot lives in
  the catalogue's pattern (*{name} · {roles}*, U08), the comma in the join.
- **The trap of the split line.** The author line and the overline are one
  element with a nested `muted` span, and
  `@testing-library/dom`'s `getByText` matches an element's own text nodes, so
  a plain-string query for *Eiichirō Oda · scénario, dessin* finds nothing.
  Assert on the card's whole text (`wrapper.text()`, whitespace normalised with
  one small helper in the spec), which is what
  `FastEntryScenarios.showsTheOnePieceCard` already does with
  `host.textContent`. If it costs a cycle anyway, it is one item for
  `agent/GOTCHAS.md`.
- **The cover carries an `alt` that names the ouvrage, decided here.** The S1
  scenario reads the cover through `getAllByRole("img")`, and an `<img>` with
  an empty `alt` has the role `presentation`, which would make the scenario
  fail on a query that finds nothing; an absent `alt` fails the accessibility
  the app owes its reader anyway. The catalogue entry is *Couverture de
  {title}*.
- **The rows are markup in the card, not components, decided here.** U06
  describes one card with three parts; a `CardRow` or a `Chip` component drawn
  from a single use would be an abstraction with a test of its own for no
  behaviour the card's cases do not prove. The second screen that shows a row
  or a chip extracts them.
- **The skeleton ships here, decided here.** It is the *Searching* state of the
  spec's *Screen* section and of U05, and its whole job is to be the size of
  the card, so it cannot be written before the card exists — T017 deferred it
  to this task for that reason. It is `aria-hidden` and carries no text, so no
  test asserts it (D07 forbids asserting a class, exactly as for T017's
  `danger` outline); the PR body says so, and the phone check of the spec's
