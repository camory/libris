# T017 — The lookup screen, typed ISBN

**Backlog line:** Frontend: the lookup screen, typed ISBN. The route `/isbn`
and its view: the field labelled `ISBN`, the `Chercher` button, the rule
applied before anything leaves, the title of the answer shown, and the three
messages of the scenarios taken from the `fr` catalogue (D05). A refused text
names it and sends no request; an unknown ISBN and unavailable sources each
say so, switching on the problem's `type` (D11). The fake of the port lands in
`src/fixture`; the view test provides it through the injection key (D07). The
home page links to `/isbn`, so the reader reaches the screen from the
installed app. Realises S3, S4 and S7 on the frontend; un-skips
`S3 Not an ISBN, wrong length`, `S3 Not an ISBN, wrong check digit`,
`S4 Unknown ISBN` and `S7 Every source down`.

**Serves:** spec `fast-entry` — S3, S4 and S7 on the frontend, and the *Screen*
section's Ready, Searching, Not an ISBN, Unknown ISBN and Sources unavailable
states; PRD §4.7 (the reader types an ISBN and reads what the sources know),
§3 (*ouvrage*, *série*, *tome*, *collection*, *auteur*; the *Avoid* lists);
decisions D05 (the layers, the injection keys, `createLibrisApp` wires the
ports), D07 (`npm test` is the gate, a view test mounts with the real i18n and
a fake port through its key, a test asserts text and roles and never a tag or
a class, a scenario is un-skipped and never edited), D10 (strict TypeScript,
Conventional Commits, identifiers in English, UI text in French), D11 (the
frontend maps a problem's `type` to its own wording, with a fallback for a key
it does not know); rules U01 to U05, U07 and U08 of `docs/DESIGN.md`.

**First of its kind:** the first screen built to `docs/DESIGN.md` — the first
colour roles and type steps declared as Tailwind theme tokens in
`src/ui/style.css` (U01), the first icon component under
`src/ui/components/icons` (U07), the first form control and the first message
(U04, U05) — and, on the application side, the first fake of a port that
answers an outcome union (`src/fixture/FakeIsbnApi.ts`), the first second
route, and the first port added to `LibrisPorts` since `meApi`. What this
task chooses for the tokens, the icon and the message will be repeated by
every screen: the reviewer repeats this line in its verdict and Tophe settles
the conventions on the pull request, amending `docs/DESIGN.md` with what the
review decides.

## Goal
When this task is done a reader opens the installed app, follows the home
page's link to `/isbn`, types an ISBN with or without hyphens, presses
*Chercher*, and reads either the title the sources know or the one message
that says what went wrong: *ISBN invalide* without a request leaving,
*ISBN inconnu*, or *Erreur lors de la recherche, veuillez réessayer plus
tard.* It matters now because it is the first screen the household will touch
and the first one drawn to the design rules written from the mockups
(`docs/DESIGN.md`, 2026-09-12): the rule and the client of T016 stop being
code no one can reach, and T018's card has a screen to land in.

## Rules in play
- **D05** — `domain/` stays pure (the rule of T016 is imported, not rewritten);
  `application/` holds the port and its key (both exist); the view lives in
  its own folder under `src/ui/views`, is imported by the router alone, and
  injects `isbnApiKey`; `createLibrisApp` is the one place ports are wired and
  `bootstrap` the one place the real ones are built. Tailwind CSS only,
  hand-written components, mobile first. The boundaries rules of ESLint are
  the proof and `eslint.config.ts` is not touched.
- **D07** — `cd frontend && npm test` is the gate; a view test mounts with the
  real i18n and a fake port provided through its injection key and awaits
  `flushPromises` before asserting; it asserts what the reader sees, text and
  roles, never a tag or a class; every body is `// Given`, `// When`,
  `// Then` unless it is a single statement; the four scenario methods the
  backlog line names lose their `.skip` and nothing else in
  `src/scenario/FastEntryScenarios.spec.ts` changes.
- **D10** — TypeScript strict, ESLint and Prettier, identifiers and code in
  English, UI text in French, Conventional Commits with the scope `frontend`,
  branch `task/T017-lookup-screen`, the trailer on every commit.
- **D11** — the API sends keys and the frontend owns the wording: the view
  switches on the problem's `type` and maps it to an i18n key, with a fallback
  for a key it does not know; `errors` of a validation problem is not read.
- **U01** — the six colour roles and the accent are declared once as Tailwind
  theme tokens in `src/ui/style.css`, each resolving to its light or dark
  value there, the scheme following `prefers-color-scheme`; the view and the
  icon name roles only (`bg-surface`, `text-muted`, `border-danger`), never a
  slate or teal shade.
- **U02** — the system font stack, and the steps of the scale this screen
  uses: page title 22/semibold for the `h1`, card title 20/bold for the title
  of an ouvrage, field 18/regular, button 16/semibold, body 14/regular,
  label 13/semibold. No size between the steps. The ISBN the field holds uses
  tabular figures.
- **U03** — one column designed at 390 px, capped at 480 and centred above
  that: a header with the page title and one hint sentence in `body` `muted`
  ending with a full stop, then the content; 20 between blocks and at the
  sides, 8 between a control and what belongs to it; radius 12 on controls.
  The footer of `App.vue` already sits under every screen.
- **U04** — the field: its label above it in the `label` step and `muted`, a
  50-tall box on `surface` with a 1.5 px `border` outline, radius 12, the
  placeholder an example of a valid value, a numeric keyboard, and the text
  kept exactly as typed; a refused field takes a `danger` outline and keeps
  its text. The primary button: under the field, 8 below, full width, 50
  tall, `accent` with white text, its label the infinitive *Chercher*; while
  the lookup runs it is busy — *Recherche en cours…*, a spinner at its left,
  dimmed, accepting nothing — and the field stays editable; it comes back to
  itself whatever the answer is.
- **U05** — one answer at a time, under the control that asked: a message
  replaces the title of a previous answer and a title replaces a message. A
  message is a round alert icon of 22 and one sentence in the `body` step,
  both in `danger`, 8 apart, under the field. No toast, no success message.
- **U07** — the alert icon is an inline SVG on a 24 grid, stroke 1.8, round
  caps and joins, `currentColor`, no fill, its own component
  `src/ui/components/icons/IconAlert.vue`, `aria-hidden` because the sentence
  beside it carries the meaning. No icon font, no icon package.
- **U08** — every sentence and label comes from the `fr` catalogue and no
  component holds a French string; the reader is addressed as *vous*; the
  page title is the infinitive with its object, *Ajouter un ouvrage*; the
  action in progress ends with an ellipsis; a message of a few words takes no
  full stop, a sentence does.

## Test plan
Green suite: `cd frontend && npm test`, run plainly — nothing piped or chained
after it, or the proof hook refuses the call. While iterating,
`npx vitest run src/ui` mounts components and needs no mock;
`npx vitest run src/scenario` starts `contracteer mock` through the global
setup (about four seconds) and needs `contracteer` on the PATH.

Read `src/ui/views/home/HomeView.spec.ts` first: it is the shape a view test
has here — `mount` from `@vue/test-utils`, `plugins: [createLibrisI18n()]`,
`provide: { [key]: fake }`, `flushPromises` before the assertion.

1. **The tokens and the route, first.** `style.css` gains the roles and the
   steps, `router.ts` the `/isbn` route, `IsbnView.vue` the header of U03 with
   the title and the hint, `i18n.ts` their two entries; the first case of
   `src/ui/views/isbn/IsbnView.spec.ts` asserts the title *Ajouter un ouvrage*
   and the hint sentence are rendered. Nothing about colour or size is
   asserted (D07): the look is proven by reading and by the phone check of the
   spec's *Done*.
2. **Red → green, the screen, one case per cycle** in `IsbnView.spec.ts`, each
   mounting the view with `createLibrisI18n()` and a `FakeIsbnApi` under
   `isbnApiKey`, each body Given / When / Then:
   - *the title and the hint* (step 1);
   - *a text that is not an ISBN sends nothing*: type `978272348852`, click
     *Chercher*, then `ISBN invalide` is shown, the field still reads
     `978272348852`, and `fake.asked` is empty;
   - *the rule decides what is asked*: type `978-2-7234-8852-5`, then
     `fake.asked` is `["9782723488525"]` and the title of the edition the fake
     answered is shown; a second case types the old ten `2723488527` and
     asserts the same `asked`;
   - *no source knows it*: a fake answering
     `{ outcome: "problem", type: "/problems/not-found" }` makes the screen
     show `ISBN inconnu`;
   - *no source answered*: `/problems/sources-unavailable` makes it show
     `Erreur lors de la recherche, veuillez réessayer plus tard.`;
   - *a problem the screen does not know*: `/problems/teapot` shows the same
     sentence — the fallback of D11;
   - *an answer replaces the previous one*: after a found title, submitting a
     text the rule refuses shows `ISBN invalide` and the title is gone;
   - *the button is busy while the lookup runs*: over a fake whose answer
     never arrives, after the click the button's accessible name is
     `Recherche en cours…` and it is disabled, while the field is not; then,
     over a fake that answers, after `flushPromises` the button is *Chercher*
     again.
   The edition the fake answers is a `SourceEdition` value declared in this
   spec, not in `src/fixture`: only the fake of the port is shared this task
   (the backlog line), and T018's card decides whether a sample edition
   becomes a fixture.
3. **The home page's link.** One case in `HomeView.spec.ts`: the view renders
   a link named *Ajouter un ouvrage* whose `href` is `/isbn`. `RouterLink`
   needs a router: add `createLibrisRouter()` to the test's plugins (a spec
   may import any layer, D07) and `await router.isReady()` if the link renders
   empty without it. The two existing cases keep their assertions.
4. **The ports.** `createLibrisApp.spec.ts` gains `isbnApi: new FakeIsbnApi(…)`
   in the ports it passes — any answer will do, the home view never asks it —
   and keeps its single assertion. This is the cycle that makes `LibrisPorts`
   and `bootstrap` change.
5. **The four scenarios, last.** Remove `.skip` from `S3 Not an ISBN, wrong
   length`, `S3 Not an ISBN, wrong check digit`, `S4 Unknown ISBN` and
   `S7 Every source down`, and change nothing else in the file: they are
   Tophe's, and a scenario that has to change is a spec conversation. They
   boot the real application through `bootstrap` over `contracteer mock`, so
   they prove the wiring the view tests fake: the route, the provided port,
   the real client, the real ISBNs of the contract's examples. Expect them to
   pass without new production code; if one fails, the cause is in the wiring
   or in the accessible names, not in them.
6. **Tidy on green**, then the full gate, then the pull request.

**Not to be written:** a component test for `IconAlert.vue` (an icon has no
text and emits nothing; the message cases mount it); a spec for `router.ts` or
`style.css`; a test that asserts a class, a tag, a colour or a pixel size; a
case for the 400 the API can answer (the rule means it never reaches a reader,
and `FetchIsbnApi.spec.ts` already covers the client's side of it); a case for
a 401, a network failure or a status the contract does not declare; a
Playwright test; a snapshot test.

## Risks and decisions
- **The field must keep the `textbox` role, decided here.** The scenarios find
  it with `getByRole("textbox", { name: "ISBN" })`. An `<input type="number">`
  has the role `spinbutton` and a `type="search"` the role `searchbox`: both
  make all four scenario methods fail on a query that finds nothing. The field
  is `<input type="text" inputmode="numeric">` — which is also how U04's
  "numeric keyboard" is obtained without the spinner arrows — and its
  accessible name comes from a `<label for>` carrying the text `ISBN` exactly.
- **A button, not a form, decided here.** `<button type="button" @click>` is
  what the scenarios click by name, and it keeps jsdom out of form submission
  entirely; a `<form @submit.prevent>` would buy the keyboard's go key at the
  price of a behaviour the spec does not ask for and jsdom implements its own
  way. The follow-up is noted above.
- **The flow lives in the view, not in a composable, decided here.** D05
  allows a use case as a composable in `application/`, but this screen's flow
  is three refs and one `await`, with one caller; a composable would be a
  layer with a test of its own for no behaviour the view test does not
  already prove (D07's "each layer is tested in isolation" assumes the layer
  exists). When the *ajouter à une bibliothèque* spec adds a second caller of
  the lookup, that is the task that extracts it.
- **The message is markup in the view, not a component, decided here.** U05
  describes one message shape and this is the first screen to show one; a
  shared `AppMessage` with props and its own test would be an abstraction
  drawn from a single use. The second screen that shows a message extracts
  it — as does T018 if the card needs one.
- **Every problem but `/problems/not-found` shows the generic sentence,
  decided here.** The spec gives three messages and the screen has three
  states; D11 requires a fallback for a key the frontend does not know, and
  *Erreur lors de la recherche, veuillez réessayer plus tard.* is exactly
  what is true of any answer the screen cannot explain, including the
  `/problems/validation` the rule should make unreachable. One map with one
  entry and a default, rather than a `switch` that must grow with the
  contract.
- **The `danger` outline is for a refusal of what was typed, decided here.**
  U04 gives it to "a field the answer refuses"; the spec's *Screen* says the
  outline for *Not an ISBN* and, for *Unknown ISBN*, "the same", and names
  only the message for *Sources unavailable*. So: outline on *ISBN invalide*
  and *ISBN inconnu*, no outline when the sources are down, since nothing is
  wrong with what the reader typed. No test asserts it (D07 forbids asserting
  a class); it is proven by reading and by the phone check of the spec's
  *Done*.
- **The hint names scanning before T019 ships it.** *Scannez le code-barres ou
  saisissez l'ISBN.* is the sentence the spec's *Screen* section gives, and
  inventing a temporary one would be product wording no document states.
  It stands, and the barcode icon arrives one task later. Say it in the PR
  body so Tophe can refuse it on the review.
- **Tailwind v4 has no `dark:` variant to configure here.** U01 asks for one
  set of role names resolving to a light or a dark value under
  `prefers-color-scheme`, so the roles are CSS custom properties declared on
  `:root` and overridden inside `@media (prefers-color-scheme: dark)`, exposed
  to Tailwind through `@theme inline` in `src/ui/style.css`; the utilities
  (`bg-surface`, `text-muted`, `border-danger`) then carry the scheme for
  free and no component names a scheme. The type steps are declared the same
  way, as `--text-*` tokens, which is what keeps a size between the steps of
  U02 out of a template. Only the roles and the steps this screen uses are
  declared: `card title`, `overline`, `lead` and `tab` arrive with the card
  and the tab bar. This is the *First of its kind* line: if Tophe prefers
  another mechanism, `docs/DESIGN.md` gains it on the review.
- **The icon lives under `src/ui/components/icons/`, a folder the boundaries
  config does not name.** `eslint.config.ts` matches the element
  `ui-components` on `src/ui/components`, which covers its sub-folders, and
  the pattern sits above `src/ui` and `src` in the array, where order decides
  (`agent/GOTCHAS.md`). The icon imports nothing, so no policy is even
  exercised; if ESLint reports otherwise, the fix is a finding for
  `agent/GOTCHAS.md`, not a change to `eslint.config.ts`.
- **`HomeView.spec.ts` mounts without a router today.** A `RouterLink` needs
  one: the case adds `createLibrisRouter()` to the plugins. If the link's
  `href` reads empty before the router is ready, `await router.isReady()`
  first. `createLibrisRouter` imports `HomeView`, which the spec also
  imports — that is a spec importing its own layer, which D07 allows.
- **The scenarios spy on `fetch` after mounting.** `S3` asserts no request
  left at all, so the view must ask nothing on mount and the screen must
  carry nothing that fetches — one more reason the tab bar, which the home
  view's `/me` call would follow, stays out of this task.
- **The sandbox runs the gate, this box does not.** `npm test` needs
  `contracteer` on the PATH and Node 24, which the sandbox has (D08); on
  Tophe's machine the frontend gate runs inside the image
  (`agent/GOTCHAS.md`). No duration or coverage figure is quoted here: the
  run reports what it measured.
