## Goal
When Libris does not answer a search, the screen says so in the list's
place; when it does not answer a search's next page, the rows already
listed stay with the sentence under them. A reader whose network drops
mid-search then reads why nothing comes, not a list frozen or a skeleton
standing for ever.

## Risks and decisions
**One `unavailable` state holding what stays listed.** As
`useBrowseCatalogue` does, a failure keeps the books already listed, none
for a first page, and adds `query` and `near` so that the nearest keep
their sentence and label above the rows that stay. Rejected: a flag on
`found` and `near` beside `loadingMore` (two shapes for one failure, and
every existing `toEqual` rewritten); a bare `{ status: "unavailable" }`
for a first page (a second state for the same message).

**No next page after a failure.** `searchMore` asks nothing over
`unavailable`, as `browse` asks nothing after its own; the message stays
until a new search replaces it (U05). Rejected: asking again when the
last row comes back into view, which no scenario describes and which
would take the message away under the reader's eyes.

**A late failure is dropped like a late answer.** T174's rule reads the
search an answer belongs to, whatever it holds; a failure of a search the
reader already replaced says nothing about the one shown. Rejected:
showing any failure, which would put the message over the latest
search's rows.

**The view's message follows the list shown.** While a search is shown,
its message is the only one, and the catalogue's error stands only under
the catalogue's own rows; the margin above the message reads the rows
drawn. This answers the `agent/PROPOSED.md` item from T169's and T173's
reviews, since T175 writes the search's message in that same place and
U05 forbids two messages at once. Rejected: a second paragraph beside the
catalogue's (both sentences over a catalogue that failed and a search that
failed); leaving the item open.

**A key of the catalogue's own.** `catalogue.search.error` holds the
words `isbn.error` holds, as each screen keeps its own error key
(`catalogue.error` beside `series.error` and `bookshelf.error`). Rejected:
reading `isbn.error` from the catalogue.
