## Goal
The backend serves the whole of `v0.6.0`: the reader's answer names their
default bookshelf, the lookup carries their copies, and a book is added to a
bookshelf over HTTP. It serves T033 to T036 to the frontend of T038 to T040.

## Rules in play
- D04 — the pin moves from `v0.5.0` to `v0.6.0`, nothing else of the contract.
- D07 — the pin bump is the first red, the controllers its green; the six
  tests of `BookshelfScenarios` are un-skipped, nothing else; `FastEntryScenarios
  > S1 Typed ISBN, found` gains `"copies": []`, declared in the PR body; a
  hand-written web test covers only what the contract cannot express.
- D02 — the lookup's controller calls `LookupIsbnForReader`, so it moves to
  `library.infrastructure.web`: the bibliography may not see the library.
- D06 — every controller takes the reader with `@AuthenticationPrincipal
  Reader`; the principal stays the `Reader`, unchanged.
- D10 — the new use case is named by its sentence and exposes only `operator
  fun invoke`; no visibility of a domain type widens (`Isbn` gains nothing).
- D11 — a problem has `type`, `title`, `status`, no `detail`, `errors: [{field,
  code}]` when it refuses fields; the advice arrives with its first case.
- D12 — the edge refuses through the domain's `of` doors (`Contribution.of`,
  `SeriesEntry.of`, `Isbn.of`), never by catching a constructor's exception.

One step is one case is one commit; `./gradlew detekt` before each commit; a
step is committed before its guard's mutation is checked. `./gradlew test
--tests '*ApiContractTest'` lists the contract cases one by one.

1. **red — the pin.** `ApiContractTest` loads `…/v0.6.0/openapi.yaml`, and
   `FIXED_READER` gains `"x-requested-with" to "XMLHttpRequest"`, without

## Risks and decisions
**The bookshelf's name comes from a use case of its own.** The principal holds
the default bookshelf's id only; `FindDefaultBookshelf` reads the `Bookshelf`.
*Rejected:* the name on `Reader` — an aggregate carrying another's data (D12).
*Rejected:* the controller reading `BookshelfRepository` — the edge calls use
cases only (D02).

**Where each field is refused.** `isbn13` by the lookup's own check, shared as
one function: the backlog line says *as the lookup checks*, and two copies of a
pattern drift. `title` by `isNotBlank()` at the edge, since `Edition` offers no
`of` door and a blank title would reach its `require` as a `500`; `authors` and
`series` through `Contribution.of` and `SeriesEntry.of` (D12). A missing
required field, a wrong enum value or a wrong JSON type fails the reading of
the body and is the advice's `400`, with no `errors`. *Rejected:* making
`ISBN_PATH` public on `IsbnController` — a private member widened for a new
caller (D10). *Rejected:* Bean Validation annotations — a dependency and a
second way of refusing, for four checks.

**Field names and codes.** An error names the request field as the JSON does:
`isbn13`, `title`, `authors`, `series`; code `not-an-isbn` as the contract
writes it, `blank` for the three others, documentation only (D11). *Rejected:*
indexed paths (`authors[1].name`) — no client tells two authors apart yet.

**The advice overrides two handlers only**, each proven by a case. The other
inherited handlers answer Spring's problem, `detail` included, for failures no
contract declares (a `405`, a `415`): the PR body proposes it as a follow-up.
*Rejected:* stripping `detail` from every inherited problem — no test of this
task motivates it. *Rejected:* `spring.mvc.problemdetails.enabled` — it cannot
set the `type`.

**The harness sends what the app sends.** The chain refuses a write without
`X-Requested-With`, which neither the contract nor the scenarios send; the
verifier's fixed headers and the scenario client's default header add it, as
`FIXED_READER` stands for Authelia. *Rejected:* the header in each scenario
call — an edit of a scenario (D07). *Rejected:* opening the chain in tests.
