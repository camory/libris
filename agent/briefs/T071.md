**Serves:** spec `covers` S8 (its last paragraph, *one edition never stops
the run*), S9 (the run takes the editions one at a time); PRD §4.7;
decisions D02, D04, D07, D10, D11, D12
**First of its kind:** the first use case that catches whatever its ports
throw: `FetchAwaitedCovers` catches any `Exception` of one edition's take
and goes on, where the one catch of `application` today
(`WelcomeReader`) names the exception it expects; the only catch-all of the
backend is the adapters' `nullOnFailure`.

## Goal
When a fetch, a normalisation or a store throws for one awaited cover, the
run keeps that cover's attempt dated and takes the next edition, instead of
ending there and leaving every later edition to the next waking, a day
later. T070 removed the known throw (a huge header's `OutOfMemoryError`);
this task makes the run hold against the ones nobody has met yet.

## Rules in play

  catch sits there, around one edition's take; `ExecutorCoverWorker`
  (infrastructure) runs the use case once per waking and is unchanged; the
  application imports nothing new, so `ArchitectureTest` is unchanged and
  `application` gets no logger
- D04 — no contract edit, no pin bump; `ApiContractTest` unchanged
- D07 — the use case in plain JUnit over the fakes of its ports, in

  that the line names; no scenario test is un-skipped or edited; Given / When /
  Then on every case of two statements or more; a fake that only this class
  uses is a private top-level class of the test file, below the test class,
  as `ReadersLosingTheRace` is in `WelcomeReaderTest`
- D10 — `catch (_: Exception)`, Kotlin's form for an exception never read,
  as `nullOnFailure` writes it (detekt's `TooGenericExceptionCaught` and
  `SwallowedException` let `_` through); `FetchAwaitedCovers` keeps

## Test plan
All in `FetchAwaitedCoversTest`, appended after the existing cases; the
component under test is `FetchAwaitedCovers`. One step is one case is one
commit; `./gradlew detekt` before each commit; a step is committed before
its guard's mutation is checked. Both editions await `INVENTAIRE`: the
existing `awaiting(INVENTAIRE)` and `awaiting(INVENTAIRE, second)` with
`second = onePiece(ONE_PIECE_2)`, as *each awaited inventaire io cover is
taken* sets them up. The existing helper `fetchAwaitedCoversOver` may gain
a `covers` parameter defaulting to the field; whether it does is the
refactor's call.

1. **red — the storing of the first of two editions throwing, the second is
   stored.** The store is `CoversFailingFirstWrite` (new, see *Files*):
   its first `write` throws an `IOException`, as `Files.write` does on a
   full disk, and later writes store as `CoversInMemory` does. Then
   `editions.findByIsbn(isbnOf(ONE_PIECE_2))` is
   `second.copy(coverName = cover.name)`. Red: the `IOException` leaves
   `fetchAwaitedCovers()` and fails the case before the second edition is
   taken. Green: one edition's take, after its dating, sits in a
   `try` whose `catch (_: Exception)` ends that edition's take and nothing
   else (see *Risks*: the catch holds the fetch, its normalisation and the
   storing, not the dating).
2. **guard — the edition whose storing threw keeps its wait, dated.** Same
   Given as step 1; then `awaitedCovers.findAll()` is
   `listOf(AwaitedCover(isbnOf(ONE_PIECE), INVENTAIRE, clock.instant()))`:
   the first still awaited, dated, the second's wait ended. Mutation: the
   dating moved below the take of the cover (after the store), so a throw
   skips it; the case reds with ONE_PIECE's attempt `null`.
3. **guard — the fetch of the first of two editions throwing, the second is
   stored.** The fetch is `CoverFetchFailingFirst(INVENTAIRE, cover)` (new,
   see *Files*): its first `coverFor` throws an `IllegalStateException`,
   later calls answer `cover`; the store is the plain `covers`. Then
   `editions.findByIsbn(isbnOf(ONE_PIECE_2))` is
   `second.copy(coverName = cover.name)`. Mutation: the `try` holds the
   storing alone, the cascade's call outside it; the case reds with the
   `IllegalStateException` leaving the run.
4. **Tidy on green**, the gate run plainly, then the documents: the task
   line ticked, a `PROGRESS.md` entry, the PR, its body naming the guards'
   mutations (checked and reverted), the first-of-its-kind line, and the
   choices of *Risks* (`Exception` not `Throwable`, no log).

**gotchas/backend.md:** in the item on the cover worker, one sentence: a

## Out of scope
- A log of the swallowed exception: a logger in `application` is outside
  what `ArchitectureTest` lets it see, and no document sets how a use case
  logs. Note it in `agent/PROPOSED.md` if the implementer finds it
  wanting.
- The cascade going on to the next *source* when one source's fetch throws:
  the spec has the run go on to the next *edition*; the adapters already
  answer `null` on a failure through `nullOnFailure`, and `CoverFetches` is
  unchanged.
- A failure of the dating itself, of `findAll`, or of the executor's
  thread: these are the database's or the JVM's, and end the run as today.
- Any scenario test: the property has none (the line, and S8's proof).

## Risks and decisions
**The catch is the use case's, around one edition.** The loop over the
awaited covers is `FetchAwaitedCovers.invoke`; only there does "go on to
the next" mean anything. *Rejected:* a catch in `ExecutorCoverWorker`, which
runs the use case once, so the first throw would still leave every later
edition to the next waking; a catch in each port's adapter, three places
that cannot cover a throw of the normalisation or of the transaction.

**The catch holds the fetch, its normalisation and the storing, not the
dating.** The spec names those three and says the attempt *stays* dated,
so the dating comes before and is outside: a failed dating is the database
failing, which `findAll` would meet too. Inside, a throw of the
transaction that names the cover and ends the wait leaves the attempt
dated, since the dating is written before and outside that transaction.
*Rejected:* a catch around the store alone, which leaves the fetch's throw
uncaught (step 3's mutation); a catch around the dating too, which would
take the next edition against a database that just failed.

**`Exception`, not `Throwable`.** The tree's catch-all, `nullOnFailure`,
catches `Exception`; an `Error` (`OutOfMemoryError`, `StackOverflowError`)
leaves the JVM in a state no edition should be fetched in, and the one
`Error` met so far, the huge header's, T070 stopped before any decoding.
*Rejected:* `Throwable` or `runCatching`, which would also swallow an
`Error` and a thread's interruption.

**No log.** The run already logs *Fetching the awaited covers* from the
worker; the failed edition stays visible as an awaited cover dated each
day. *Rejected:* `System.getLogger` in the use case (`java..` passes
`ArchitectureTest`), a logging convention for `application` that no
document states; the use case answering its failures for the worker to
log, a new return type for one log line.

**The two fakes stay in the test file.** One class uses them, as
`ReadersLosingTheRace` serves `WelcomeReaderTest` alone; `fixture` holds
what several classes share (D07). Their names follow the tree's
`<What><Behaviour>` (`CoverFetchAnswering`, `ReadersLosingTheRace`).
